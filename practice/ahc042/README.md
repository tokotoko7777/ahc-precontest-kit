# AHC042 - 安全な往復をまとめ、完全シミュレーションで削る

[公式問題文](https://atcoder.jp/contests/ahc042/tasks/ahc042_a) / [公式ローカルツール](https://img.atcoder.jp/ahc042/cnhLtdRT.zip)

## 問題の要点

`N=20` の盤面に鬼 `x` と福 `o` が40個ずつあります。1回の操作で行か列を1マスずらし、端から駒を1個押し出します。

- 鬼をすべて押し出す。
- 福は1個も押し出さない。
- 操作数は `4N^2=1600` 以下。

両方を達成したときのスコアは `8N^2-T=3200-T` なので、あとは操作数 `T` を短くすればよいです。

## baseline: 公式ヒントの安全往復

ある鬼の左側に福が1個もないなら、その行を `左へ j+1 回` 動かすと鬼を外へ出せます。その後、同じ回数だけ右へ戻すと、残った駒は元の場所へ戻ります。

```text
L row を j+1 回
R row を j+1 回
```

上・下・右も同様です。各鬼について、使える方向のうち端まで最短のものを個別に実行すれば必ず完成します。これを `AHC042_HINT_BASELINE` として残しています。

## 同じ安全方向の鬼をまとめる

同じ行を左へ出せる鬼が複数いるとします。最も遠い鬼まで左へ動かせば、途中にいる鬼もまとめて外へ出ます。戻す操作も1回で済むので、個別に往復するより短くなります。

安全方向を次の80グループとして扱います。

- 各行を左へ: 20グループ
- 各行を右へ: 20グループ
- 各列を上へ: 20グループ
- 各列を下へ: 20グループ

各鬼を、利用可能なグループのどれか1つへ割り当てます。1グループの費用は、担当した鬼の端までの距離の最大値を `d` として `2d` です。

初期割当は、追加費用が小さいグループを順に選ぶ貪欲法を、鬼の順序を変えて200回試します。その後、次の近傍を固定回数の焼きなましで改善します。

- 鬼1個の担当変更
- 2個の担当交換
- 同じグループへ複数の鬼を寄せる

割当から往復集合を作った後は、他の往復でも既に除去できる鬼を調べ、不要なグループの削除と押し出し距離の短縮も行います。`AHC042_GROUP_ONLY` でここまでの解を出力できます。

## 操作列を直接短くする

完全な往復は安全ですが、戻し操作を全部残す必要がない場合もあります。そこで、合法なグループ解から次の編集をランダムに試します。

- 操作を1個削除
- 連続する1～8操作を削除
- 離れた2操作を同時に削除
- 2操作を交換
- 1操作を別の位置へ挿入

候補を作るたび、初期盤面から全操作をそのまま再現します。

- 福を1個も落としていない
- 鬼が0個

の両方を満たす候補だけを採用します。削除は必ず短くなり、交換・挿入は同じ長さの別の合法列へ移るために使います。別の並びで削除を続けると、さらに操作を消せることがあります。

グループの順番を変えた13個の開始列を用意し、それぞれ30,000回編集します。現在解は常に完成した合法解なので、探索途中で止まっても不正解を出しません。

## 合法性が保たれる理由

最初の各往復は、押し出す範囲に福が存在しないことを入力盤面で確認しています。往復後は、押し出された鬼以外の駒が元の位置へ戻るため、安全な往復をどの順に実行しても福は残ります。

往復集合は全鬼を少なくとも1回覆います。操作列編集後は推測や部分判定を使わず、毎回20×20盤面を完全シミュレーションします。最終出力直前にも同じ検査を `assert` で行います。

初期baselineが1600手以下であり、その後はまとめるか削除するだけなので、操作数上限も必ず守ります。

## 計算量

鬼数を `K=40`、操作列長を `T<=1600` とします。

- 1回の割当評価: `O(K)`
- 1回の操作列検査: `O(TN)`
- メモリ: `O(N^2 + K^2)`

盤面が20×20と小さいため、差分シミュレーションよりも毎回の完全再現を選びました。実装が単純になり、福落下やundo漏れを避けられます。

## コンパイルと使い方

提出時は `main.cpp` だけで動き、外部ヘッダには依存しません。

```bash
g++ -std=c++20 -O2 -Wall -Wextra -Wshadow -Wconversion -pedantic -Werror main.cpp -o main
./main < in.txt > out.txt
```

公式ツールでは次のように採点できます。

```bash
cargo build --release --bin vis
./main < in/0000.txt > out.txt
./target/release/vis in/0000.txt out.txt
```

比較用ビルドです。

```bash
g++ -std=c++20 -O2 -DAHC042_HINT_BASELINE main.cpp -o hint
g++ -std=c++20 -O2 -DAHC042_GROUP_ONLY main.cpp -o grouped
```

追加の検証結果です。

## 知識コーパスについて

Knowledge map、AHC042レビュー、差分評価、焼きなましの4か所だけを参照しました。AHC042レビューでは、盤面シミュレーションで可変長操作列を評価し、追加・削除・方向や位置の変更を探索する構造が確認されています。

ただし、レビュー対象提出のスコア対応は未確認です。本実装は第三者の操作列探索を再現せず、公式ヒントの安全往復を出発点に、常に完成解だけを保持する独自の割当・削除探索にしています。第三者コードは使用していません。
