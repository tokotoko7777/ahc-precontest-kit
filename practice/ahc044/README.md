# AHC044 練習用ソルバー

[AHC044 A - Cleaning Plan](https://atcoder.jp/contests/ahc044/tasks/ahc044_a) の、
提出可能な単一 `main.cpp` です。ローカルheaderには依存しません。

## 問題の見方

社員 `i` を訪れるたび、次の社員は `a_i, b_i, a_i, b_i, ...` と交互に選ばれます。これは
各頂点が2本の出辺を交互に使う **rotor-router** と見ることができます。

社員 `i` を約 `T_i` 回訪れるなら、2本の辺はそれぞれ約 `T_i/2` 回使われます。したがって、
遷移先 `j` へ流れ込む回数を `T_j` へ近づければ、長期訪問回数も目標へ近づきます。

## 解法

### 1. 目標回数が近い社員を安全なcycleにする

目標が正の社員を `T_i` 順に並べ、昇順側と降順側を交互につないだpendulum順を4通り作ります。
各社員の奇数回目の辺 `a_i` を、この順序の次の社員へ向けます。

全員を単純な番号順cycleにすると訪問頻度がほぼ一様になります。一方、pendulum順では隣同士の
目標値が近く、cycle辺が運ぶ `T_i/2` と次頂点の需要が大きく食い違いにくくなります。
また、この1本を残している間は正の社員全体へ到達できる安全網になります。

### 2. 残りの辺を需要へ割り当てる

頂点 `j` にはcycleの直前頂点から約 `T_prev/2` が既に入ります。残り需要

```text
T_j - T_prev / 2
```

を容量と考え、各社員の偶数回目の辺が運ぶ `T_i/2` をgreedyに割り当てます。大きい順と
小さい順を試し、500,000週を実際に再生した誤差が小さい規則を残します。

### 3. 必ず全期間を再生して辺を直す

現在多すぎる社員へ向く `b_i` を、少なすぎる社員へ付け替えます。候補は近似流量で絞りますが、
採否は毎回500,000週を最初から再生して決めます。

- 700回の決定的な乱択付け替え
- 推定改善量上位だけを見る偶数辺の座標降下
- 最後にcycleを壊す可能性がある奇数辺も少数だけ試す

奇数辺変更で閉じたcycleへ落ちる候補も、全期間の誤差が悪化すれば即座に戻ります。短い代理
simulationだけで採用しないため、長周期の影響も最終評価へ含まれます。

## まず使う

```bash
g++ -std=c++20 -O2 -pipe main.cpp -o solver
./solver < in.txt > out.txt
```

`-DAHC044_BASELINE` を付けると、`a_i=b_i=(i+1)%N` の単純cycleになります。全社員を同じ
回数だけ訪れる比較用解です。

```bash
g++ -std=c++20 -O2 -DAHC044_BASELINE main.cpp -o baseline
```

## 計算量と高速化

1規則の評価は `O(L)`、追加メモリは `O(N)` です。探索回数はソース中の小さな固定値で、
最大でも約1,250回です。内側ではvectorを作らず、固定長arrayの訪問回数を増やすだけにして
います。`N=100`, `L=500000` でも代表caseは約1秒です。
