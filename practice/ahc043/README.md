# AHC043 練習用ソルバー

[AHC043 A - Railway Company](https://atcoder.jp/contests/ahc043/tasks/ahc043_a) の、提出可能な単一 `main.cpp` です。ローカルの `.hpp` には依存しません。

50×50の盤面へ駅と線路を800ターンかけて建設します。駅はマンハッタン距離2以内の家・職場をカバーし、同じ鉄道網の駅で家側と職場側を両方カバーすると、毎ターン運賃が入ります。

## まず使う

```bash
g++ -std=c++17 -O2 main.cpp -o main
./main < in.txt > out.txt
```

提出時は `main.cpp` をそのままAtCoderへ貼り付けます。出力は必ず800行です。

[公式ツール](https://img.atcoder.jp/ahc043/de43f43a9c.zip)では、資金不足・不正な線路・行数不足も検査できます。

```bash
# 公式toolsディレクトリで一度だけ
cargo build --release --bin vis

./target/release/vis in/0000.txt out.txt
```

## 最初に覚える3つ

- 線路は100、駅は5000かかる
- 建設の直後に、そのターンの収入が入る
- 早く開通した路線ほど、残りターンで何度も収入を得られる

駅や線路をたくさん置けるかだけでなく、**いつ完成して、投資を何ターンで回収できるか**が大切です。

## このsolverの流れ

### 1. 最初の2駅を探す

各家・職場について、距離2以内にある最大13セルを駅候補にします。ある2セルを駅にしたときの収入は、各通勤者が寄与する駅ペアへ運賃を足して前計算します。

2駅をL字の最短線路で結ぶとき、駅間距離を `d`、開通後の毎ターン収入を `income` とすると、延伸しない場合の最終資金は次の式で正確に求められます。

```text
初期資金 - (10000 + 100 × (d - 1)) + income × (800 - d)
```

この値が高い上位96ペアを残し、縦→横と横→縦の両方のL字経路を試します。

### 2. 新しい駅を1つずつ延伸する

最初の路線が開通した後は、全駅と線路が1つの鉄道網につながっている状態を保ちます。

各延伸では次を行います。

1. 現在の全駅を始点にBFSし、空きセルだけを通る最短距離を一度に求める
2. 各候補セルへ駅を追加した場合、新たに利用可能になる通勤者の運賃を求める
3. 線路建設中の既存収入と、資金不足時に必要な待機ターンも含めて800ターン目の資金を再現する
4. 今すぐ何もせず待つ場合より最終資金が増える駅だけを建てる

既存の線路を駅に置き換える場合は線路を追加せず、駅代5000だけで評価します。

### 3. 合法な順に出力する

延伸では、既存駅から新駅の手前まで線路を先に置き、最後に新駅を建てます。各支線の途中は空きセルだけを使うため、既存線路へ線路を上書きしません。

資金が足りないときは、現在の収入で建設費が貯まるまで `-1` を出力します。したがって資金が負になる操作はありません。最後は `-1` で800行まで埋めます。

## コードを読む順番

1. `main`：複数の初期路線を試して最良を出力
2. `best_initial_pairs`：最初の2駅候補を選ぶ
3. `Plan::build_best_extension`：次の新駅を選ぶ
4. `Plan::projected_final_money`：待機を含む資金シミュレーション
5. `make_l_path` と `rail_type`：L字経路と6種類の線路

`INITIAL_CANDIDATES` が主な速度調整値です。

```bash
# より軽い版
g++ -std=c++17 -O2 -DINITIAL_CANDIDATES=24 main.cpp -o main
```

初期値96は、公式最大人数ケースで約1.55秒でした。192では一部ケースが約2.9秒となったため、3秒制限の余裕を優先して採用していません。

## 比較用の2つのモード

全ターン待機するだけの最小baselineです。

```bash
g++ -std=c++17 -O2 -DWAIT_BASELINE main.cpp -o wait
```

最初の2駅と路線だけを作り、その後は待機する版です。

```bash
g++ -std=c++17 -O2 -DSINGLE_LINE_ONLY main.cpp -o single
```

## 検証

- `g++ -std=c++17 -O2 -Wall -Wextra -Wshadow -pedantic`：3モードとも警告なし
- 公式visualizer：seed 0〜99の3モードすべてが800行で合法、スコア0なし
- AddressSanitizer + UndefinedBehaviorSanitizer：seed 0, 44, 99で異常なし
- sanitizer版の公式再採点：`393669`、`15838483`、`194718`

知識コーパスからは、AHC043の「駅候補・接続木・建設順を資金推移と一緒に評価する」という確認済みレビューを構造上の参考にしました。また、AHC020の被覆と接続の分離、AHC029の候補制限、AHC058の早期投資の複利評価も参照しています。一方、AHC043の最終順位代表・タスク勝者代表はどちらもスコア未照合です。この実装と計測値は、第三者コードを使わず独自に作成し、公式ローカルツールで確認したものです。
