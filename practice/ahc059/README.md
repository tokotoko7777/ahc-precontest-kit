# AHC059 `Stack to Match Pairs` 練習解

公式問題: [AHC059 A - Stack to Match Pairs](https://atcoder.jp/contests/ahc059/tasks/ahc059_a)

`main.cpp` は、外部ファイルを必要とせずそのまま提出できるC++17単一ファイルです。
山札のLIFO条件を「探索後に修理」するのではなく、出力の形だけで常に守ります。

## 問題を短く言うと

- 20×20マスに、同じ番号のカードが2枚ずつ置かれている。
- カードを取ると山札の一番上へ積まれる。
- 山札の上2枚が同じ番号なら、その2枚は消える。
- 16,000操作以内に全400枚を消し、移動回数 `K` を小さくする。
- 全消去時の得点は `16400-K`。`Z` と `X` は移動回数には数えない。

## 解法

### 1. 全ペアを1本の入れ子鎖にする

ペアを `p0,p1,...,p199` の順に選び、各ペアの片方を順番に取ります。その後、もう
片方を逆順に取ります。

```text
open(p0), open(p1), ..., open(p199),
close(p199), ..., close(p1), close(p0)
```

`close(p199)` を取る時点では山札の一番上が `p199` なので、その場で2枚が消えます。
以後も同じことが逆順に続き、最後には山札が必ず空になります。

これは、一般的な「ペアの入れ子木」のうち、各頂点が子を高々1個だけ持つ最も簡単な
形です。木構造を直接編集するより理解しやすく、探索中に不正なスタック順を作りません。

### 2. 各ペアの向きは2状態DPで決める

各ペアには「どちらのカードを先に取るか」という2通りの向きがあります。隣り合う
ペア `a,b` の向きを決めると、増える移動距離は次の2本です。

```text
open(a)  -> open(b)
close(b) -> close(a)
```

ペア順を固定すれば、直前の向きだけを覚える2状態DPで全向きの最小値を `O(ペア数)`
で求められます。

### 3. 400通りの最近傍初期解を試す

最初のペアと向きを変えると最近傍法の結果が大きく変わります。ペア200種類×向き2種類の
全400通りを始点として、次の2本の距離和が小さい未使用ペアを順に足します。

```text
現在のopen端 -> 次のopen端
次のclose端  -> 現在のclose端
```

各初期順に上の2状態DPを行い、最短のものから探索を始めます。

### 4. 前半は分かりやすい全DP評価

最初の0.30秒は、ペア順へ次の変更を加えます。

- 2ペアを交換する。
- 区間を反転する。
- 1ペアを別位置へ移す。

候補ごとに2状態DPをやり直します。少し遅い代わりに、向きは常にそのペア順での最適値に
なります。距離を悪化させない変更を中心に受理する、低温の焼きなましです。

### 5. 後半は境界差分で高速に反復する

残り時間は、向きを明示的に持って次を反復します。

- 1ペアの向きを反転する。
- 2ペアを交換する。
- 区間を反転する。

入れ子鎖の隣接コストは対称なので、区間内部を逆順にしても内部の辺の和は変わりません。
交換でも変わるのは両端付近だけです。そのため評価差は、全200ペアではなく最大4個の
境界項から計算できます。定期的に2状態DPも行い、向き全体を整え直します。

最後に最良のペア順へもう一度DPを行い、open列、reverseしたclose列の順で最短マンハッタン
経路と `Z` を出力します。カードを置く `X` は使いません。

## なぜ必ず合法か

- 各番号はopen側とclose側に1回ずつだけ現れる。
- close列はopen列の完全な逆順なので、取るカードは必ず山札の一番上と一致する。
- 各目的マス間は盤面内の縦横移動だけで結ぶ。
- 400個の目的地までの移動区間は400本で、1区間は最大38歩。
- よって操作数は最大 `400*38 + 400 = 15600 < 16000`。

探索結果によらず全カードが消え、操作数上限も超えません。

## 計算量

ペア数を `M=200` とします。

- 全始点の最近傍初期化: `O(M^3)`。固定サイズでは約1,600万候補比較。
- 向きDP: 1回 `O(M)`、メモリ `O(M)`。
- 前半の近傍評価: 1候補 `O(M)`。
- 後半の評価差: `O(1)`。区間を実際に反転する処理だけ `O(M)`。

## この解から再利用できる部分

- LIFOの合法列を、入れ子構造で最初から保証する方法。
- 向きを反転できる区間列に対する2状態DP。
- 最近傍法を全始点から試す、小規模なmulti-start。
- swap・reverseで変わる境界だけを見る差分評価。
- 低速で正確な探索から高速な差分探索へ切り替える時間配分。

さらに詰める場合は、1本の鎖を一般の順序木へ広げ、部分木の削除・挿入や兄弟順交換を
行う方法が候補です。ただし、木を平坦化した列の対応関係と差分評価が複雑になるため、
まずはこのコードの「鎖＝最も単純な入れ子木」でLIFO表現を理解するのがおすすめです。
