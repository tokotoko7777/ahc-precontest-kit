# AHC005 practice

[公式問題](https://atcoder.jp/contests/ahc005/tasks/ahc005_a)の非インタラクティブな過去問です。
`main.cpp`の1ファイルだけで使えます。AtCoderへの提出はしていません。

## 基本フォーマットを使う箇所

[保守用の例](../../examples/search/ahc005_patrol_sa.cpp)の`PatrolProblem`が、
[局所探索の基本形](../../template/search/local-search/basic.cpp)に対応しています。

| 編集箇所 | 書くもの・返すもの |
|---|---|
| `State` | 各直線道路の代表点を並べた訪問列と移動時間 |
| `Move` | 反転区間、変更する代表点、再挿入位置 |
| `propose_move` | 試したい変更1個。作れないなら`nullopt` |
| `evaluate_move` | 新score−旧score。今回は旧移動時間−新移動時間 |
| `apply_move` | 採用された変更と差分cacheだけ反映 |

時計、冷却、採否、最良解保存は`TimeBasedAnnealingRunner`へ任せます。
評価中はStateを書き換えません。閾値引数は受け取りますが、
境界辺だけで計算できる評価なので、途中打ち切りは行っていません。
どこを編集するかは日本語のTODOコメントを参照してください。

## 問題の要点

移動先セルの数字5〜9が移動時間です。開始点から出て必ず戻り、
壁で遮られない同じ行・列の全道路が一度は視界に入る閉路を作ります。
全道路を見た場合、公式scoreは`round(10000 + 10000000 * N / travel)`。
制限時間は3秒です。

## 解法

最大の水平・垂直道路区間へ分解し、長さ2以上の各区間を「group」とします。
各group上の交点（または開始点など）から代表点を1つ選び、
その代表点全てを訪れる巡回路を焼きなまします。
各groupの候補内で代表点を変える限り、訪問順を変えても全道路が見えます。
同じ交点が2つのgroupを同時に担当しても構いません。

この被覆条件は**十分条件であって必要条件ではありません**。
通過途中にも視界が増えるため、最後に実際の最短路を再検査して
不要な代表点を期限内だけ取り除きます。

候補点間のDijkstra最短距離・親は探索前に計算します。
到着料金は非対称ですが、
`dist(a,b)-cost(b) = dist(b,a)-cost(a)`を使えば、
2-optの区間内部を走査せずに境界4辺だけで差分を計算できます。
代表点変更とrelocateも削除・挿入位置の辺だけで評価します。

最終設定は開始温度30→終了温度1、探索終了の目安は入力開始から2600msです。
代表点を変更しながら全ての挿入位置を比較する近傍を含めます。
最後の不要点削除は2820msで打ち切り、入出力と検証の余裕を残します。
16bit距離表による高速化案も比較しましたが、スコアが下がったため採用していません。

旧practiceの集合被覆＋2-opt解も先に保存します。
最後は経路の移動・帰還・可視性を独立に検査し、
旧解より移動時間が短い候補だけを出力します。
旧解自身にも全道路DFS往復への安全なフォールバックがあります。

## 再利用できる考え方と限界

「各groupから代表を1つ選ぶ」と「訪問順を選ぶ」を同時に探索する形は、
施設選択やgeneralized TSPにも使えます。
フォーマットは共通の局所探索1種類のままで、専用テンプレートは増やしていません。

一方、group被覆は制約を強めたモデルです。最適性・上位相当の成績は主張しません。
入力が異なる公式順位表との直接比較もできません。
