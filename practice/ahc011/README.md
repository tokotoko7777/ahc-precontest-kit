# AHC011 practice

公式問題: [A - Sliding Tree Puzzle](https://atcoder.jp/contests/ahc011/tasks/ahc011_a)

`main.cpp` だけで提出できる、スライドパズルのビーム探索例です。完成図を別に用意せず、
現在の盤面にできた木を直接評価するため、初心者でも処理を追いやすくしています。

## 問題の要点

`N×N` の盤面には、4方向の線をビットで表したタイルと空きマスが1個あります。
`U`, `D`, `L`, `R` は、それぞれ空きマスをその方向へ動かす操作です。

- `6 <= N <= 10`
- 操作回数は `T = 2*N^3` 以下
- 線が互いに向き合う隣接タイル間だけに辺ができる
- 閉路を含まない連結成分のうち、最大の頂点数 `S` を大きくする
- `S < N^2-1` なら得点は `round(500000*S/(N^2-1))`
- 完全木なら、さらに操作が短いほど高得点になる

## 解法

### 1. 盤面を公式ルールどおり評価する

`evaluate` は Union-Find で全ての一致辺をつなぎます。同じ成分内へ辺を追加した場合は
閉路フラグを立て、閉路のない成分だけを木として数えます。

探索用の優先度には次の値を混ぜています。

- 最大の木: 公式得点へ直接つながる
- 一致している辺の総数: 完成形へ近づく局所的な目印
- 木成分サイズの二乗和: 小さな木同士をつなぐ手を優先する
- 閉路成分サイズの二乗和: 閉路を大きく育てないための罰則

公式得点だけでは、多くの手が同点になって先へ進みにくいため、この補助評価を使います。

### 2. 1手ずつビーム探索する

各状態から合法な最大3方向へ空きマスを動かし、優先度上位だけを残します。直前の手を
すぐ元へ戻す操作は省きます。

`Zobrist hash` を使って、以前に見た同一盤面も省きます。同じ盤面へ遠回りで戻っても、
完全木を作った時の手数が増えるだけだからです。盤面そのものは状態に保持しているので、
評価時にhashから盤面を復元する必要はありません。

履歴は全候補へ文字列をコピーせず、採用状態に対して「親番号と最後の1文字」だけを保存
します。最後に親を逆向きにたどって出力列を復元します。

### 3. 短い合法手列で谷を越える

大きな木の完成直前では、一度その木を崩さないと残りのタイルを運べないことがあります。
ビーム探索後の短い時間で2〜20手の合法列を提案し、焼きなまし型の確率で一時的な悪化も
受け入れます。公式得点用の最良盤面と出力列は別に保存するため、探索途中で失いません。

## 読む時の目印

- `evaluate`: 公式の木判定と探索用優先度
- `State::board`: 最大100マスを持つビーム状態
- `zobrist`: 盤面hashの表
- `visited`: 既出盤面の除去
- `HistoryNode`: 文字列コピーを避ける親ポインタ
- `BEAM_END_MS` / `SEARCH_END_MS`: ビームと後処理の締切

## 使い方

```bash
g++ -std=c++17 -O2 main.cpp -o solver
./solver < input.txt > output.txt
```

出力は1行の `UDLR` 文字列です。空文字が最良なら空行を出力します。

1盤面評価は `O(N^2 alpha(N^2))` です。ビーム幅を `W` とすると、1層でおよそ `3W` 状態を
評価します。`N` が大きいほど幅を狭め、2.2秒でビームを止め、2.5秒で全探索を止めます。

[公式ローカルツール](https://img.atcoder.jp/ahc011/df8bb452a2.zip)のseed 0〜9を、同じ環境で
比較しました。

時間打ち切りなので、CPU負荷によって探索層数と得点は少し変動します。

## 公式ツールでの最終確認

付属seed 0〜99を全て実行しました。

- 不正文字・盤外移動・手数超過: 0ケース
- 平均得点: 409,296.3
- 最小得点: 297,980
- 最大得点: 784,722
- 完全木: 1ケース
- 平均出力長: 232.20手
- seed 0の実行時間: 約2.70秒、最大常駐メモリ約138 MiB

`-Wall -Wextra -pedantic` で警告なしです。ASanとUBSanを同時に有効にしたseed 0も、
公式ビジュアライザで合法に完走しました。

## 注意と発展

- 上位解のように、理想の木を先に設計して割当問題とスライド列生成へ分離する方式では
  ありません。直接ビームなので、長く木を崩す必要がある盤面は苦手です。
- Zobrist hashの64 bit衝突確率は非常に小さいものの、数学的に0ではありません。
- 同じ考え方の汎用部品は `library/shared-history.hpp` と
  `library/zobrist-hash.hpp` にあります。提出用 `main.cpp` には必要部分を直接置いています。
- 研究資料の構造上の着想を参考にした独自実装で、第三者提出コードの転載ではありません。
