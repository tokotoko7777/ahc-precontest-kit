# AHC049 練習用ソルバー

箱を壊さない範囲で何個かまとめて持ち帰る、提出可能な単一 `main.cpp` です。
外部ライブラリや、このリポジトリ内のヘッダには依存しません。

## 問題を簡単にいうと

- `(0, 0)` が搬出口です。
- 箱を拾うと、今持っている箱の一番上に積まれます。
- 1 マス動くたび、下の箱ほど「上にある箱の重さ」のぶん耐久値が減ります。
- 耐久値が 0 以下になると失格です。
- 全 399 個を搬出したうえで、移動回数が少ないほど高得点です。

## まず考える baseline

最も簡単で確実なのは、箱を 1 個ずつ取りに行って帰る方法です。
1 個しか持たないため耐久値は減りません。

この baseline は `-DBASELINE` を付けると動かせます。

```bash
g++ -std=c++17 -O2 -DBASELINE main.cpp -o baseline
./baseline < in.txt > out.txt
```

ただし、各箱を毎回往復するので移動回数は常に 15,200 回です。

## 完成版の方針

完成版は、搬出口から出発して複数の箱を拾い、搬出口へ戻る一連の動きを「1 回の旅」として作ります。

### 1. 次の箱で何歩得するか

現在の箱を `a`、次の候補を `b`、搬出口を `O` とします。
別々に帰る代わりに `a -> b` と続けて訪問すると、

```text
distance(a, O) + distance(O, b) - distance(a, b)
```

歩だけ節約できます。この値が正の候補だけを調べ、節約量・重さ・耐久値の優先度を少しずつ変えた 48 通りの貪欲構築を試します。

### 2. 「今すぐ帰っても安全」を常に守る

候補 `b` を拾う前に、

1. 現在地から `b` まで移動する
2. `b` を一番上に積む
3. `b` から搬出口まで最短で帰る

という場合の耐久値をすべて計算します。どれか 1 個でも耐久値が 0 以下になる候補は使いません。

この判定を毎回行うので、候補がなくなった時点で必ず安全に帰れます。箱の並び順は下から上まで `vector<int>` 1 本で表しています。

### 3. 小さな局所改善

良かった構築案 2 個に対して、次を試します。

- 同じ旅の中の 2 箱交換、区間反転
- 別の旅への 1 箱移動
- 2 つの旅の箱交換
- 安全なら 2 つの旅を連結

移動回数が実際に減り、全耐久値を最初から再計算して安全だった変更だけを採用します。箱は 399 個なので、差分計算を複雑にしなくても時間内に収まります。

### 4. 搬出口を途中で踏まない

箱を持ったまま `(0, 0)` を踏むと、その場で全箱が搬出されます。
箱から箱へ移動するときは L 字経路の縦横の順番を選び、予定した帰還以外では `(0, 0)` を通らないようにしています。

## コンパイルと実行

```bash
g++ -std=c++17 -O2 -Wall -Wextra -Wshadow -Wconversion -pedantic \
  main.cpp -o main
./main < in.txt > out.txt
```

公式ツールでの確認例です。

```bash
cargo run --release --bin vis in.txt out.txt
```

乱数や時刻は使っていないため、同じ入力には毎回同じ答えを出します。

## 検証結果

公式配布の seed 0〜99 を、baseline と完成版の両方で採点しました。

| 版 | 合法 | 平均スコア | 最小 | 最大 | 平均移動回数 | 平均出力命令数 |
|---|---:|---:|---:|---:|---:|---:|
| 1 箱ずつの baseline | 100 / 100 | 1,200.00 | 1,200 | 1,200 | 15,200.00 | 15,599.00 |
| 完成版 | 100 / 100 | 11,959.82 | 11,702 | 12,212 | 4,440.18 | 4,839.18 |

- 同一 seed の勝 / 分 / 敗: `100 / 0 / 0`
- 完成版 100 ケースの合計スコア: `1,195,982`
- ローカル実行時間: 平均 `0.867` 秒、最大 `1.473` 秒（seed 93）
- strict compile: 警告なし
- ASan + UBSan: seed 0, 42, 99 で異常なし
- sanitizer 時の公式スコア: `11,878`, `12,038`, `12,016`

## 合法性について

- 各箱は未回収リストから 1 回だけ選ぶため、重複して拾いません。
- 各旅は、移動ごとの上載せ重量を 64 bit 整数で再現します。
- 局所改善後も同じ完全シミュレーションを通します。
- 完成版は正の節約だけから作り、局所改善も短くなる変更だけを採用するため、命令数は baseline の 15,599 以下です。これは上限 16,000 以下です。

耐久値の判定は `remaining > 0` としています。ちょうど 0 も破損なので、`>= 0` にしない点が重要です。
