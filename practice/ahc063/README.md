# AHC063 練習解答: 色付き蛇の層別ビームサーチ

提出するのは [`main.cpp`](./main.cpp) だけです。ローカルのヘッダやライブラリには依存しません。

## 問題を短く整理

盤面上の蛇を `U/D/L/R` で動かし、すべての餌を食べながら、頭から尻尾までの色を目標列へ合わせます。

- 餌を食べると、蛇の末尾にその色が追加される
- 頭が胴体へ重なると、そこより尻尾側を噛みちぎって餌へ戻す
- 盤面外への移動と、首へ戻るUターンは禁止
- 最大100,000手
- 最終色の不一致と長さ不足には、1個あたり10,000点以上の大きな罰が付く
- 色と長さを完全一致できた後は、手数がそのまま絶対Scoreになる

絶対Scoreは小さい方が良い問題です。

公式問題文: <https://atcoder.jp/contests/ahc063/tasks/ahc063_a>

## 最も簡単なbaseline

何も出力せず、初期状態の長さ5で終了しても合法です。制約により先頭5色は最初から一致していますが、残りの長さ不足へ大きな罰が付きます。

```bash
g++ -std=c++17 -O2 -DSIMPLE_BASELINE main.cpp -o baseline
./baseline < in.txt > out.txt
```

## この解法

### 1. 1手を正確に再現する

`State` は次を持ちます。

- 頭から尻尾までの座標
- 蛇の色列
- 色ごとの餌の位置
- 噛める胴体位置
- 目標と一致している先頭の長さ `matched`

蛇の座標は長さ256のリングバッファです。通常移動では先頭番号を1減らすだけなので、座標列全体をずらしません。

盤面上の餌と噛める位置は64 bit整数4個のbitsetにします。餌を食べる、尻尾を餌へ戻す、噛める位置をずらす処理を小さなbit演算で更新します。

中心となる `apply_move` は、公式ルールの順に次を処理します。

1. 盤外とUターンを拒否
2. 餌を食べて伸びる
3. 胴体へ重なった場合は尻尾側を切る
4. 切った各色を盤面の餌へ戻す
5. 先頭一致長と噛める位置を更新

### 2. 深さごとのビームサーチ

各状態から、Uターンを除いた高々3方向を試します。同じ手数の候補だけを一つの層へ集め、良いものを `beam_width` 個残します。

候補の優先順位は単純です。

1. 目標と一致する先頭部分 `matched` が長い
2. 一致部分より後ろの余計な色がない
3. 次に必要な色の餌まで近い
4. 手数が短い

完全一致解が見つかった後は、それ以上の深さを探索しないため、短い答えを残せます。

### 3. 必要な一時悪化を残す

次に欲しい色まで行く途中で、別の色をどうしても食べる必要がある場合があります。常に「余計な色を食べない」を優先すると、この局面で停止します。

そこで次の条件が揃った時だけ、0-1 BFSを使います。

- 現在の色列に余計な末尾がない
- 欲しい色が遠い
- その色の餌が残り少ない
- 別色の餌を避ける経路がない

空きマスと欲しい色の餌をコスト0、別色の餌をコスト1として、必要な別色餌の最小個数を求めます。この値が最小になる移動だけを残し、あとで自己切断して余計な末尾を捨てられる経路を探索します。

### 4. 似た状態をまとめる

各層で、蛇の頭・中央・尻尾の3座標から短いhashを作ります。同じhashの候補は評価が良い1個だけ残します。

これは完全な状態一致判定ではなく、探索量を減らすための意図的な近似です。餌配置まで異なる候補をまとめる場合もありますが、幅を大きくしやすくなる利点を優先しています。

操作履歴は候補ごとに文字列をコピーせず、`親番号 + 1手` だけを共有します。最後に最良ノードから親をたどって答えを復元します。

### 5. 時間に合わせて幅を広げる

幅1000から始め、2000、4000、……、最大32000まで、初期状態から探索し直します。各回で得た最良解は別に保存します。

1900 msで探索を止めるため、次の幅を最後まで回せない入力でも、それ以前の完成解を必ず出力できます。

## コードを読む順番

1. `main`: 入力、幅を倍増する反復、出力
2. `apply_move`: 蛇の1手を再現
3. `choose_path_by_beam`: 層別ビーム本体
4. `better_node`: 候補の順位
5. `has_zero_junk_path_to_target` と `min_junk_to_target`: 一時的に別色を食べる判断
6. `reconstruct_path`: 共有履歴から操作列を復元

## コンパイルと実行

```bash

```


## 公式seed 0〜99での検証

完成版と空出力baselineを、同じ公式100入力で比較しました。

| 版 | 合法 | 完全一致 | 平均絶対Score | 中央値 | 最小 | 最大 | 合計 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 空出力baseline | 100 / 100 | 0 / 100 | 1,315,800.00 | - | 220,000 | 3,660,000 | 131,580,000 |
| 層別ビーム | 100 / 100 | 100 / 100 | 337.39 | 252.0 | 43 | 1,940 | 33,739 |

- 完成版の勝 / 分 / 敗: `100 / 0 / 0`
- 完成版では全ケースで不一致0・長さ不足0なので、Scoreは操作数と同じです。
- 実行時間: 平均 `1,893.66 ms`、最大 `1,909 ms`
- 1ケースあたりの幅違い探索回数: 平均4.18回、2〜6回
- strict compile: 通常版・baselineとも警告なし
- AddressSanitizer + UndefinedBehaviorSanitizer: seed 0、37、99で異常なし
- sanitizer時も3ケースすべて完全一致し、Scoreは `60`、`322`、`303`

乱数は使いません。ただし時間内に完了できた最大幅が実行環境で変わるため、操作列とScoreはわずかに変わる場合があります。
