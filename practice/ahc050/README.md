# AHC050 - 滑るロボットから逃げる岩の順番

外部ヘッダーを使わない、提出可能な単一 `main.cpp` です。初心者でも追いやすいように、解法を「確率を動かす」「一番安全なマスを選ぶ」「同点の選び方だけ複数試す」の3段階に絞っています。

## 問題を短く言うと

`40 x 40` の盤面に、最初から `M` 個の岩があります。

1. ロボットは空きマスのどこかに一様ランダムで置かれる
2. 上下左右を各25%で選び、岩の直前まで滑る
3. あらかじめ決めた順番の次のマスへ岩を置く
4. そこにロボットがいた確率だけゲームが終了する

初期状態で空いていた全 `N*N-M` マスを、重複なく1回ずつ出力します。長く生き残るほど高得点で、1ケースの最大得点は `1,000,000` です。

## まず使える単純baseline

空きマスを上から下、左から右へそのまま出しても合法です。

```cpp
for (int cell : empty_cells) {
    cout << cell / N << ' ' << cell % N << '\n';
}
```

`main.cpp` では、次のようにコンパイルするとこのbaselineだけを出力できます。

```bash
g++ -std=c++17 -O2 -DSIMPLE_BASELINE main.cpp -o baseline
./baseline < input.txt > baseline.txt
```

## 解法

### 1. ロボットの位置を確率で持つ

実際のロボット位置は分かりませんが、各マスにいる確率は正確に計算できます。

```text
probability[cell] = ロボットがそのマスにいて、まだ生存している確率
```

最初は全空きマスへ `1 / (N*N-M)` ずつ置きます。岩を置くマスの確率が `q` なら、生存確率から `q` を引き、そのマスの確率を0にします。

この確率は「生存しているという条件付き確率」ではありません。死亡した分を戻さず、そのまま減っていく確率質量です。この形なら公式の期待賞金を足し算だけで再現できます。

### 2. 滑走を空区間ごとにまとめる

横一列の岩と岩の間を考えます。同じ空区間にいるロボットは、左を選べば全て区間左端へ、右を選べば全て右端へ止まります。

```text
空区間の確率合計 = sum
左端へ 0.25 * sum
右端へ 0.25 * sum
```

縦方向も同じです。1マスずつ岩まで歩かせる必要がなく、盤面を横1回・縦1回走査するだけなので、1ターン `O(N^2)` です。コードでは `move_robot` がこの処理です。

### 3. 今もっとも安全なマスを選ぶ

各ターンでロボットを動かしたあと、まだ岩でないマスのうち確率が最小の場所へ岩を置きます。

```text
次に置く場所 = argmin probability[cell]
```

多くのターンでは確率0のマスがたくさんあります。そのどこを選んでも「今ターン」は安全ですが、追加した岩は次ターン以降の止まり方を変えます。固定の行優先で同点を解くと、未来の盤面が偏りやすくなります。

### 4. 同率候補だけランダムにして32本作る

最小確率という条件は絶対に崩さず、同率のマスだけ乱数で選びます。乱数seedを変えて32本の完成順序を作り、それぞれを `evaluate_order` で最後まで正確に再シミュレーションします。

```text
32本のgreedy列を構築
    ↓
各列の公式期待賞金を厳密計算
    ↓
一番良い完成列を出力
```

探索途中の近似値ではなく、完成列の正確な期待値で選びます。行優先baselineも候補に残すため、内部評価ではbaselineより悪い列を出しません。

## コードを読む順番

1. `main` - 入力と候補比較
2. `move_robot` - 確率を1ターン動かす
3. `build_greedy_order` - 最小リスクgreedyを1本作る
4. `evaluate_order` - 完成順序の正確な期待賞金
5. `print_order` - 1次元番号を座標へ戻す

`cell = row * N + column` として盤面を1次元配列にしているだけなので、複雑なクラスやnamespaceは使っていません。

## コンパイルと実行

```bash
g++ -std=c++17 -O2 -pipe main.cpp -o main
./main < input.txt > output.txt
```

公式ローカルvisualizerでは次のように確認できます。

```bash
cargo run -r --bin vis input.txt output.txt
```

`Score = ...` と表示され、重複・範囲外・初期岩への出力・出力不足も検出されます。

## 計算量

空きマス数を `K=N*N-M` とします。

- 1本の構築: `O(K*N^2)`
- 32本の構築: `O(32*K*N^2)`
- メモリ: `O(N^2)`

`N=40` なので十分軽く、公式seedの代表5件では0.23〜0.27秒でした。

## 知識集をどう使ったか

参照した範囲はKnowledge map、AHC050全文、構造的に近いAHC008・AHC009・AHC046のレビューだけです。

- 公式に確認した事実: 入出力、滑走規則、期待値の採点式、公式scorerの確率伝播
- AHC050レビューの確認済み構造: 位置確率分布を進め、岩候補を比較する。ただし代表提出と順位表スコアの対応は未照合
- AHC008/AHC009からの移植観点: ランダムな移動を1軌跡に決めず、盤面全体の確率として評価する
- AHC046からの移植観点: 追加した岩が将来の停止位置を変える「環境編集」として扱う
- この実装独自の簡略化: 最小即時リスクを厳守し、同率だけを32回多点化して正確な完成期待値で選ぶ

第三者提出コードはコピーしていません。レビューにある構造的な着眼だけから独立実装しています。

## 公式seed 0〜99での検証

2026-08-31、公式配布入力と公式visualizerで測定しました。

| 指標 | 行優先baseline | 完成版 |
|---|---:|---:|
| 100ケース合計 | 21,912,841 | 95,859,821 |
| 1ケース平均 | 219,128.41 | 958,598.21 |
| 1ケース最小 | - | 932,799 |
| 1ケース最大 | - | 975,596 |
| 勝/同点/負 | - | 100 / 0 / 0 |

- 公式visualizer: seed 0〜99の100件すべて合法
- 出力行数: 全件で正確に `N*N-M` 行
- strict compile: `-Wall -Wextra -Wshadow -Wconversion -Wpedantic` で警告0
- ASan + UBSan: seed 0, 50, 99で異常なし
- LeakSanitizerのみ実行環境のptrace制約により無効化
- Release版: 代表5件で0.23〜0.27秒、最大常駐メモリ約3.9 MB

## 最初に変えるなら

候補数を変えたい場合は、次だけを調整します。

```cpp
for (uint64_t seed = 10; seed < 42; ++seed)
```

上限の `42` を増やすほど多くの同率パターンを試せますが、実行時間もほぼ比例して増えます。まず現在の32本を基準にし、手元の実行時間を確認しながら変更してください。
