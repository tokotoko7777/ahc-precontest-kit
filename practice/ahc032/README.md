# AHC032 — Action先行ビーム

[公式問題 Mod Stamp](https://atcoder.jp/contests/ahc032/tasks/ahc032_a)は4時間の短期コンテストです。
`main.cpp`へ`action-beam-search.hpp`を展開済みなので、1ファイルだけで動きます。
ヘッダ分離版は[`ahc032_action_beam.cpp`](../../examples/search/ahc032_action_beam.cpp)です。

## 何を編集するか

`BEGIN LIBRARY`〜`END LIBRARY`は共通処理です。
`TODO(AHC032)`以降の`ModStampProblem`を問題に合わせて編集します。

| 場所 | 書く内容・返す値 |
|---|---|
| `State` | 盤面、走査位置、使用回数、確定得点、各位置で選んだ組合せ番号 |
| `Action` | 同じ位置で押すスタンプ多重集合の番号。2 byte |
| `generate_actions` | 現在位置・残り予算で使える組合せ番号の一覧 |
| `evaluate_action` | 適用後の順位値そのもの。差分ではない |
| `apply_action` | 採用Actionを子Stateへ反映する |
| `build_placements` | 走査順序、各位置の最大枚数、累積手数予算 |
| `validate / print_answer` | 全再生による整合性確認と公式形式の出力 |

全候補のStateをコピーせず、Actionと評価値で上位N件を選び、
残った候補だけStateを作る処理は`ActionBeamRunner`が担当します。
候補生成と評価・状態更新は1つのProblemへ集めています。

## 解法

未確定領域の上辺と左辺を交互に処理し、49個の配置位置を確定します。
この順なら、今確定したセルは以後のスタンプでは変わりません。
評価は確定済みセルの和と残り手数の価値を合わせ、整数で比較します。

同じ場所へ押す順序は関係ないため、スタンプの多重集合を前計算します。
通常位置は最大2枚、右端・下端は最大3枚、最後の3×3は最大4枚。
0〜4枚の組合せは合計10,626個です。既定のビーム幅は9,000です。

これは旧practiceの「4方向ビーム＋焼きなまし＋座標降下」を移植したものではなく、
既にあったRunner例を実問題得点で比較して置き換えたものです。
旧practiceは比較元commit `f56782586166350002812bf499ec6ac7b9ce96b0` に残っています。

## 実行

```sh
g++ -std=c++17 -O2 -DNDEBUG main.cpp -o main
./main < in.txt > out.txt
# 探索量を変える
g++ -std=c++17 -O2 -DNDEBUG -DAHC032_BEAM_WIDTH=1000 main.cpp -o main-small
```

固定幅・固定世代数なので、同じ入力には同じ出力を返します。
`validate`は81手以内・範囲内・差分得点と全盤面再生の一致を確認します。
ビーム幅を増やすと実行時間が増えます。手元の時間測定はAtCoder上の保証ではありません。

## 公式スコアの比較

### コア高速化と既定幅9,000（2026-09-15）

共通ライブラリの中間sort・候補選抜・Stateコピーを軽くし、問題側の評価は据え置きました。
今回の調整に未使用のseed 10〜39では、同じ幅9,000の新旧で全出力が一致し、
時間中央値は1.513秒→1.352秒（約10.6%短縮）。新幅9,000の最長は1.583秒でした。

旧既定幅6,000からの平均scoreは79,119,334,656.53→79,157,140,410.87（約0.0478%増）。
共通best比の平均は99.938314%→99.986067%、14勝13分3敗です。
旧版も幅9,000なら同じ得点で時間内なので、得点増は幅調整の効果として区別します。
Problemの編集箇所やAPIは増やしていません。

開発10件の幅比較、時間超過で不採用の幅13,000、全120実行の記録と再測定方法は
[コア高速化レポート](../../benchmarks/AHC032_CORE_REPORT.md)です。

### 以前の幅6,000への移行記録

2026-09-15、公式配布seed 0〜9、同一入力・公式visualizerでの比較です。

| 方法 | 平均score | 最大壁時計 |
|---|---:|---:|
| 旧practice（独自実装） | 73,487,381,446.50 | 1.752秒 |
| 従来Runner例・幅1,000 | 78,996,169,390.50 | 0.186秒 |
| 新Runner例・幅6,000 | **79,159,150,255.20** | **1.115秒** |

旧practiceへ10勝、従来Runner例へ9勝1分。旧practiceから平均約7.72%改善しました。

この設定を固定した後、残りの公式seed 10〜99も採点しました。

| 入力 | 旧practice平均 | 旧Runner平均 | 新Runner平均 |
|---|---:|---:|---:|
| seed 10〜99 | 73,495,135,284.09 | 78,970,761,125.01 | 79,129,321,395.62 |
| 全100ケース | 73,494,359,900.33 | 78,973,301,951.56 | **79,132,304,281.58** |

全100ケースで旧practiceに100勝（平均約7.67%増）、旧Runnerに85勝5分10敗
（平均約0.20%増）でした。幅を増やしても全ケースで単調に良くなるわけではありません。
全出力が合法、追加90ケースの新版最大壁時計は1.394秒でした。

## 採用しなかった終盤7枚合成

[公式解説](https://img.atcoder.jp/ahc032/editorial.pdf)の合成・最後の1マスによる絞り込みを参考に、
5〜7枚合成を各4,096個選ぶ案も独自実装しました。

- 候補だけ追加した場合は、残り予算が足りず開発10ケースの得点は変化なし。
- 最後の7手も予約すると、幅1,000の平均が78,722,018,208.20へ低下し10敗。

この条件では強くなっていないため、既定の`AHC032_END_COMBOS=0`で無効にしています。
候補選抜・配分の組合せを研究するためのオプションとしてのみ残します。

```sh
g++ -std=c++17 -O2 -DNDEBUG -DAHC032_BEAM_WIDTH=1000 \
  -DAHC032_END_COMBOS=4096 main.cpp -o main-experimental
```

[手数予約ありの実験CSV](../../benchmarks/results/ahc032-end7-reserved-dev-10.csv)も残しています。
1マスによる上位選抜は近似であり、厳密な枝刈りではありません。
