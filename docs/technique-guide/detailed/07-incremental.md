## D150. 接触要素だけの差分

変更の影響を受ける要素だけ拾えば、全体を再評価する必要がありません。影響は直接動かした要素より広がる場合があります。

境界を押して隣の3区画が縮むなら、自分とその3区画の損益を合計します。自分の改善だけで採用すると、周囲の損失を見落とします。

<a id="example-20926292-03"></a>
### コードでの具体例：境界を押し縮める連鎖の損失を先に合算

境界を仮に1動かし、自身と同じ境界に接する領域の損失差だけを足す。非改善なら書き換え前に終了する。

**適用条件・落とし穴。** 接触関係を列挙できる配置の局所差分に向く。途中打切りは追加損失の符号の前提が必要。

**検算と練習。** 接触数0・複数・点への接触で、全再評価との差分一致を確かめる。

出典: [AHC001 / 提出 20926292](https://atcoder.jp/contests/ahc001/submissions/20926292) · `expandLeft` · L507–L543。 [収録情報](SOURCES.md#submission-20926292)

## D151. 連結列の隣接辺差分

列の費用が隣接要素の費用の和なら、移設で変わるのは切断・接続する部分だけです。

A–X–BからXを抜くと、A–XとX–Bが消え、A–Bが増えます。先頭と末尾には存在しない辺があるため、その境界条件を分けます。

<a id="example-23751222-04"></a>
### コードでの具体例：除去側と挿入側の辺だけで長さ差を出す

中間・先頭・末尾を分け、切れる連結と増える連結の長さだけを足し引きする。採用時に逆位置を直す。

**適用条件・落とし穴。** 列の移設を軽く評価する定石。端点と要素数1の分岐が重要。

**検算と練習。** ランダムな移設後の文字列全構築と長さ・逆位置を照合する。

出典: [AHC004 / 提出 23751222](https://atcoder.jp/contests/ahc004/submissions/23751222) · `delta1 / delta2 / wx / wy` · L365–L408。 [収録情報](SOURCES.md#submission-23751222)

## D152. 隣接辺による経路差分

対称な距離では、経路を逆向きにしても内部の辺費用は同じです。区間反転は両端の接続だけで評価できます。

ただしA→BとB→Aの費用が違う有向問題では使えません。速い差分式が成立する前提を確認してから利用します。

<a id="example-27260278-03"></a>
### コードでの具体例：反転は境界4辺、移設は切断再接続辺だけで評価

内部辺の距離が反転対称なら反転の内部費用は変わらず、境界辺だけを更新できる。

**適用条件・落とし穴。** 対称距離の巡回に適用する。非対称費用へ式をそのまま移さない。

**検算と練習。** 全再計算との差分一致を、隣接位置や端点を含めて確かめる。

出典: [AHC006 / 提出 27260278](https://atcoder.jp/contests/ahc006/submissions/27260278) · `estReverse / estMove` · L351–L387。 [収録情報](SOURCES.md#submission-27260278)

## D153. 確定状態からの分岐コピー

実際に確定した状態と、未来を試す仮の状態を分けます。仮想シナリオの変更が現実側へ混ざるのを防ぎます。

採用済みの辺だけ入ったDSUをコピーし、未来の辺を足して試します。本体を更新するのは、本当にその辺を採用したときだけです。

<a id="example-27880973-04"></a>
### コードでの具体例：採用済みDSUを各シナリオの出発点にする

採用辺だけを持つDSUをコピーして仮想未来を評価し、実採用時だけ元DSUを更新する。

**適用条件・落とし穴。** 小さな確定状態から多数の仮想評価へ枝分かれさせる。

**検算と練習。** シナリオの更新で元DSUが変わらず、採用後だけ接続が増えるか確認する。

出典: [AHC007 / 提出 27880973](https://atcoder.jp/contests/ahc007/submissions/27880973) · `uf_ / uf` · L64–L75, L91–L96。 [収録情報](SOURCES.md#submission-27880973)

## D154. 修復候補の遅延反映

候補の得点を軽い表現で計算できるなら、重い状態変更を受理後まで遅らせます。

修復した経路の方向列から長さを求め、採用された場合だけ盤面を書き換えます。棄却時に大きな状態を戻す手間を減らせます。

<a id="example-31233938-05"></a>
### コードでの具体例：得点受理後に盤面の回転と経路列を確定する

DFSの方向列で新しい長さを計算し、受理時だけ旧区間を削除して盤面と経路列を作り直す。

**適用条件・落とし穴。** 評価用の候補表現と確定状態を分ける。

**検算と練習。** 確定後の経路追跡が方向列と一致し、拒否後の使用数が一致するか確認する。

出典: [AHC010 / 提出 31233938](https://atcoder.jp/contests/ahc010/submissions/31233938) · `next_path_info` · L523–L547, L584–L589。 [収録情報](SOURCES.md#submission-31233938)

## D155. 局所次数分布の差分

グラフの辺を入れ替えると、次数や局所形が変わるのはその辺の端点だけです。

追加辺A–Bと削除辺B–Cなら、A,B,Cの3点を更新します。Bを2回独立に処理して、個数表を二重に直さないよう重複を除きます。

<a id="example-32267675-02"></a>
### コードでの具体例：辺交換の端点だけでタイル形の不足を評価する

追加・除去する2辺の重複を除いた端点だけを更新し、16種類の形の個数差を計算する。

**適用条件・落とし穴。** 局所変更で型ヒストグラムが変わる構成問題に使う。

**検算と練習。** 重複端点を持つ交換で全盤面の型個数と一致するか確認する。

出典: [AHC011 / 提出 32267675](https://atcoder.jp/contests/ahc011/submissions/32267675) · `af / delta_fsum` · L709–L728。 [収録情報](SOURCES.md#submission-32267675)

## D156. 隣接帯だけの再評価

区切り線を動かしたとき、遠く離れた領域の内容は変わりません。線の両側だけを再評価します。

縦線を1本動かすと左右2帯の点数が変わりますが、他の帯はそのままです。別の線を越える大移動では、影響範囲が増える点に注意します。

<a id="example-32961594-02"></a>
### コードでの具体例：一本の線を動かした前後の帯だけ更新する

移動線に隣接する二つの帯について、もう一方の軸の各区間の点数を問い合わせる。

**適用条件・落とし穴。** 二次元累積和などの矩形カウントを局所更新へ組み込む。

**検算と練習。** 線の移動後の全領域数え直しと一致するか確認する。

出典: [AHC012 / 提出 32961594](https://atcoder.jp/contests/ahc012/submissions/32961594) · `Helper::move` · L533–L572。 [収録情報](SOURCES.md#submission-32961594)

## D157. 差分ログによるundo

変更した添字と加算量を記録すれば、その逆を適用して戻せます。

表の位置3へ+2、位置7へ−1を行ったなら、取消しではそれぞれ−2、+1です。値の差分だけでなく、座標列など他の構造も同じ取引として復元します。

<a id="example-32961594-05"></a>
### コードでの具体例：ヒストグラムの加減算を記録して逆適用する

変更した添字と加算量を記録し、拒否時はすべて減算し直す。座標の並びも元の位置へ戻す。

**適用条件・落とし穴。** コピーするより小さい差分が残る状態に向く。

**検算と練習。** apply→undo後に座標・ヒストグラム・スコアが完全一致するか確認する。

出典: [AHC012 / 提出 32961594](https://atcoder.jp/contests/ahc012/submissions/32961594) · `delta_ / undo` · L488–L490, L545–L552, L617–L668。 [収録情報](SOURCES.md#submission-32961594)

## D158. 変更周辺の更新

移動可能性が周囲の空きだけで決まるなら、1要素の移動後に全候補を調べ直す必要はありません。

移動元と移動先の隣だけを再判定します。ただし履歴や遠方の制約にも依存する候補なら、その依存先も更新集合へ含めます。

<a id="example-34085279-02"></a>
### コードでの具体例：移動可能集合と巻き戻し可能集合を周辺だけ更新する

移動元と移動先の隣接セルだけについて空き隣接・履歴条件を再判定し、候補集合を更新する。

**適用条件・落とし穴。** 全PC走査を避けたいとき。集合からの削除だけでなく再追加の条件も対称に保つ。

**検算と練習。** 全盤面再走査で得た候補集合と比較する。

## D159. 候補キャッシュ

候補一覧を毎回作り直す代わりに、変更で無効になった候補を消し、新しく可能になった候補を追加します。

点を1つ描いた場合、その点を使う図形だけ新しく生まれるかもしれません。追加時だけでなく削除時に何が復活するかも設計します。

<a id="example-35264600-01"></a>
### コードでの具体例：描画と削除のたびに合法矩形候補を更新する

描画の影響から候補を更新し、新規部分のみCutValidRectsで検査する。削除時も消した矩形群から候補を再生成する。

**適用条件・落とし穴。** 幾何配置で全候補列挙が重い場合。古い候補の無効化と新候補の追加を両方扱う。

**検算と練習。** 小盤面で全列挙した合法矩形集合と差分更新結果を比較する。

出典: [AHC014 / 提出 35264600](https://atcoder.jp/contests/ahc014/submissions/35264600) · `DrawRect / RemoveRects` · L3632–L3683。 [収録情報](SOURCES.md#submission-35264600)

## D160. 動的最短路

辺の変更が、すべての始点の最短距離を変えるとは限りません。影響し得る始点だけ更新します。

新しい長さ1の辺の両端が始点から距離2と9なら短縮の可能性があります。一方、選んだ最短路木にない辺の削除は、その木の距離を変えません。

<a id="example-38643777-01"></a>
### コードでの具体例：削除辺が最短路木に含まれる始点だけ更新する

工事で辺を削るときはfromEisで木への所属を確認する。辺を戻すときは両端距離差が辺長以下なら改善なしとして飛ばす。

**適用条件・落とし穴。** 辺追加・削除が少ない非負重みグラフ。木に含まれない削除は現最短路を壊さない。

**検算と練習。** ランダムな工事日変更のたびに全Dijkstraと距離配列を比較する。

出典: [AHC017 / 提出 38643777](https://atcoder.jp/contests/ahc017/submissions/38643777) · `ConstructSimple / CancelConstructDiff` · L1868–L1900, L2094–L2118。 [収録情報](SOURCES.md#submission-38643777)

<a id="example-57377353-04"></a>
### コードでの具体例：追加辺の両端距離差が1以下なら伝播を省く

各始点の距離を見て、新辺で短縮できるときだけキューに入れて距離改善を広げる。

**適用条件・落とし穴。** 単位重みグラフの少数辺変更。削除では別の処理が必要で同じ式は使えない。

**検算と練習。** 各変更後に全始点BFSと距離表を比較する。

出典: [AHC036 / 提出 57377353](https://atcoder.jp/contests/ahc036/submissions/57377353) · `recalcDistAdd` · L1204–L1242。 [収録情報](SOURCES.md#submission-57377353)

## D161. 差分ログによる巻き戻し

元の値をログへ保存しておけば、複数の補助構造を持つ変更も確実に戻しやすくなります。

距離だけでなく親辺、日別の合計、全体合計も更新したなら、全てが取消し対象です。戻した後に全再計算と比較し、復元漏れを検出します。

<a id="example-38643777-04"></a>
### コードでの具体例：工事日と距離木の変更ログから集計値まで戻す

旧工事日、旧距離、旧親辺を記録し、日別・始点別・全体の距離和を差分で戻す。

**適用条件・落とし穴。** 多層キャッシュを持つ探索。主状態だけ戻しても評価が壊れるため集計階層を揃える。

**検算と練習。** 変更・棄却後に全フィールドの再計算値と一致するか確認する。

出典: [AHC017 / 提出 38643777](https://atcoder.jp/contests/ahc017/submissions/38643777) · `Aggregate::Restore` · L2128–L2176, L2957–L2962。 [収録情報](SOURCES.md#submission-38643777)

<a id="example-48359374-05"></a>
### コードでの具体例：棄却時は経路を戻して保存済み費用を代入する

置換前の区間とCostを保存し、棄却時には費用更新なしの操作で列を戻してからCostを復元する。

**適用条件・落とし穴。** 逆操作中の費用計算を省きたい場合。評価以外の間隔キャッシュは正しく復元する必要がある。

**検算と練習。** 棄却後のCostと内部間隔を完全再計算し一致を確認する。

出典: [AHC027 / 提出 48359374](https://atcoder.jp/contests/ahc027/submissions/48359374) · `replace_path / replace_path_undo` · L2021–L2031, L2274–L2287。 [収録情報](SOURCES.md#submission-48359374)

## D162. 被覆回数とビット集合

被覆の有無を表すビットと、何個から覆われているかの回数を分けます。ビットが変わるのは回数0と1の境界だけです。

回数2から1へ減っても被覆は残ります。1から0になったときだけ未被覆へ戻すことで、重複被覆の削除を正しく扱えます。

<a id="example-40290839-03"></a>
### コードでの具体例：投影の被覆回数が0と1を跨ぐときだけマスクを反転する

各セルが覆う2投影点を持ち、参照数の初回追加・最後の削除だけで被覆マスクと未被覆数を変える。

**適用条件・落とし穴。** 重複被覆を許す集合選択。単純なON/OFFでは重複した要素の削除で壊れる。

**検算と練習。** 複数セルが同じ投影点を覆うケースで全再計算と比較する。

出典: [AHC019 / 提出 40290839](https://atcoder.jp/contests/ahc019/submissions/40290839) · `Fill0 / UnFill0 / Fill` · L308–L340。 [収録情報](SOURCES.md#submission-40290839)

Aの子Bの下にC,Dがあるなら、Bを外しAの子としてC,Dを同じ順で置きます。変わるのは境界の接続ですが、子の順序が費用へ影響する点に注意します。

<a id="example-72330966-03"></a>
### コードでの具体例：中間ノードを抜くとき子を親へ繰り上げる

葉と非葉を分け、変わる境界辺だけで除去費用を計算。非葉削除では子列を同じ順序で親へ移す。

**適用条件・落とし穴。** 内部構造を維持したペア再配置向け。親ポインタと順序の両方を更新する。

**検算と練習。** 全DFS距離と除去差分をランダム木で比較する。

## D180. 意思決定境界まで巻き戻す

<a id="example-72942421-03"></a>
### コードでの具体例：変更の最初の影響点を含む経路の先頭から再探索する

**適用条件・落とし穴。** まとめて計画した行動列に局所変更を加える場合向け。既存接頭辞の再生は依然O(接頭辞長)。

**検算と練習。** 最初からsimulateする版と再生版の出力を照合する。

**適用条件・落とし穴。** 壁衝突で前進が非可逆に見える移動系向け。単に命令回数だけ後退すると元に戻らない。

**検算と練習。** 壁際を含むマクロをapply/revertして状態一致を検査する。

## D185. XORによる可逆差分

XORは同じマスクを2回適用すると元に戻ります。ビット反転の変更と取消しを同じ演算で書けます。

0101 xor 0011は0110で、もう一度0011を適用すると0101です。上書きや加算はこの性質を持たないため、操作を混同しません。

<a id="example-79251146-04"></a>
### コードでの具体例：変更ビットを保存し適用と復元を同じ演算にする

消した行内ビットと次行の反転をXORで表し、同じマスクをもう一度適用して戻す。

**適用条件・落とし穴。** 各差分が反転操作で表せる状態向け。最終状態からマスクを再推定せず変更前に保存する。

**検算と練習。** 任意のノード列を往復し初期盤面へ戻るか検査する。

出典: [AHC071 / 提出 79251146](https://atcoder.jp/contests/ahc071/submissions/79251146) · `Node.xor / State.apply / State.revert` · L268–L287。 [収録情報](SOURCES.md#submission-79251146)

## D186. 修復接頭辞の共有

複数の修復候補が同じ順序の前半を共有するなら、その途中状態を再利用できます。

A→B→CとA→B→Dの挿入順なら、A→Bまでを共通の枝として持ちます。まだ使わない枝の具体状態を作らないことで、無駄な構築も減らせます。

<a id="example-79793411-06"></a>
### コードでの具体例：同じ挿入順の接頭辞を枝として再利用する

挿入順の親子関係と部分世界を保存し、既知の子があれば再使用する。部分世界の具体構築は必要になるまで遅延する。

**適用条件・落とし穴。** 順序違いの修復を何度も試すLNS向け。変更による部分世界の無効化管理が要る。

**検算と練習。** 共有なしと結果一致、部分構築回数を比較する。
