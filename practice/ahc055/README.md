# AHC055 `Weakpoint` 練習解

公式問題: [AHC055 A - Weakpoint](https://atcoder.jp/contests/ahc055/tasks/ahc055_a)

`main.cpp` は、そのまま AtCoder へ提出できる C++17 の単一ファイルです。kit 内の
別ファイルを `#include` する必要はありません。

## 問題を短く言うと

- 宝箱 `i` を開けると武器 `i` が使える。
- 素手は1回につき1ダメージで、何度でも使える。
- 武器 `w` は最大 `C[w]` 回使え、箱 `b` へ `A[w][b]` ダメージを与える。
- 全200箱を開けるまでの攻撃回数 `T` を小さくする。
- 1ケースの得点は `sum(H) - T + 1`。したがって、攻撃回数を直接最小化すればよい。

## 解法

### 1. 解を「開封順」と「武器の攻撃先」で持つ

箱を開ける順番を `order` とします。武器 `w` の各使用枠には、攻撃先の箱、または
未使用を記録します。

武器 `w` が攻撃する箱 `b` を必ず `w` より後ろに置けば、実際の出力時にも武器を
入手してから使えます。この `w -> b` を依存辺と考えます。

ある箱 `b` が武器から受ける合計ダメージを `damage[b]` とすると、現在の攻撃回数は
次の簡単な式です。

```text
使用する武器攻撃の数 + sum(max(0, H[b] - damage[b]))
```

後半は、足りないダメージを素手で補う回数です。

### 2. 2種類の貪欲解を作る

最初は、使用可能な武器と未開封箱の組から、現在の残り硬さを最も多く減らす攻撃を
繰り返します。使う価値のある武器がなくなった場合は、次のどちらかで箱を素手開封
します。

- 残り硬さが最小の箱を選ぶ。
- 新しく得る武器が将来どれだけ素手攻撃を減らせそうかも1手先読みする。

両方を作り、攻撃回数が少ない方から探索を始めます。

### 3. 時間制限まで焼きなます

次の2操作を反復します。

- 武器の使用枠1個について、攻撃先を変更する。
- 依存辺が逆向きにならない場合だけ、開封順の2箱を交換する。

攻撃先1個の変更で影響する箱は、古い攻撃先と新しい攻撃先だけです。そのため、
攻撃回数の差は全箱を計算し直さず `O(1)` で求められます。候補は「その武器で大きな
ダメージを出せる箱」とランダムな箱に絞り、高速に反復します。

### 4. 必ず合法な操作列へ戻す

探索終了後、素手と同等以下の不要な武器攻撃を削ります。その後、箱を `order` 順に
処理し、先に武器攻撃、足りない分を素手で攻撃します。

- 各武器は箱を開けた後だけ使う。
- 使用回数は配列 `C[w]` の枠数を超えない。
- 箱が途中で開かないよう、小さいダメージの攻撃から並べる。
- それでも余る攻撃は出力しない。

以上により、開封済みの箱を再び攻撃する出力にはなりません。

## コンパイルと実行

```bash
g++ -std=c++17 -O2 -DNDEBUG main.cpp -o main
./main < in.txt > out.txt
```

探索時間の既定値は1.80秒です。短い動作確認では、コンパイル時に変更できます。

```bash
g++ -std=c++17 -O2 -DNDEBUG \
  -DAHC055_TIME_LIMIT=0.05 main.cpp -o main
```

公式ローカルツールでは次の形で合法性と得点を確認できます。

```bash
cargo run --release --bin vis in/0000.txt out.txt
```

## 手元測定

公式seed 0〜4、`g++ -O2 -DNDEBUG`、探索1.80秒の1回の測定です。時間打ち切りの
探索なので、マシン負荷によって値は少し変動します。

| seed | 良い方の貪欲解の攻撃回数 | 1.80秒探索後の攻撃回数 | 公式得点 |
|---:|---:|---:|---:|
| 0 | 5752 | 1401 | 55881 |
| 1 | 4873 | 895 | 59755 |
| 2 | 4029 | 916 | 57422 |
| 3 | 5871 | 1231 | 60513 |
| 4 | 8754 | 3032 | 57850 |

平均攻撃回数は約5856回から1495回へ減りました。また、探索時間を0.01秒に縮めた
スモークテストでも、公式配布seed 0〜99の100ケースすべてを公式judgeへ通しています。

## この解から再利用できる部分

- `Timer`: 単調時計と、4096反復ごとの時刻確認。
- `Random`: 小さく高速な乱数生成器。
- 差分焼きなまし: 変更箇所だけで新しい評価値を計算する形。
- 依存順序: 「資源を得てから使う」という条件を有向辺で守る形。
- best-so-far: 探索途中の状態が悪化しても、最良解を別に保存する形。

kit の `timer.hpp`、`random.hpp`、`time-based-simulated-annealing.hpp` と同じ考え方を
使っていますが、提出しやすいよう必要部分を `main.cpp` 内へ直接置いています。

## 改良するなら

現在のコードは、初心者が追える範囲に収めた実用的なベースラインです。さらに詰める
場合は、複数の攻撃先を同時に入れ替える近傍、箱の区間移動、探索を複数初期解へ時間
配分する方法が候補です。変更後は単純な得点だけでなく、必ず公式judgeで合法性も確認
してください。
