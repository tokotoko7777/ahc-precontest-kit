# AHC066 練習解答: マクロと運搬順序の交互探索

提出するのは [`main.cpp`](./main.cpp) だけです。ローカルのヘッダやライブラリ、事前生成ファイルには依存しません。

## 問題を短く整理

ロボットを `F`（前進）、`R`（右折）、`L`（左折）、`S`（手元と床のボールを交換）で動かし、各ボールを同じ番号のかごへ運びます。

- `M ... M` で、その間に実行した基本操作を最新のマクロとして登録する
- `P` は最新マクロを1ボタンで再生する
- マクロを記録している最中も、中の基本操作はその場で実行される
- 記録中の `P` は、古いマクロを展開して実行・記録する
- 出力ボタン数は `T` 以下、展開後の基本操作も先頭 `T` 回までしか実行されない

全 `M` 個を収納できた場合の絶対Scoreは出力ボタン数です。未収納がある場合は `T × (M - V)` なので、まず全収納し、その上でマクロによりボタン数を減らします。絶対Scoreは小さいほど良い問題です。

公式問題文: <https://atcoder.jp/contests/ahc066/tasks/ahc066_a>

## 最も簡単なbaseline

`SIMPLE_BASELINE` 版は、入力順に次を繰り返します。

1. 現在地から次のボールへ、向き込みのBFSで移動する
2. `S` で拾う
3. 対応するかごへBFSで移動する
4. `S` で置く

マクロも順序探索も使いません。次の1個を運ぶと `T` を越える場合だけ、そこで安全に終了します。

```bash
g++ -std=c++17 -O2 -DSIMPLE_BASELINE main.cpp -o baseline
./baseline < in.txt > out.txt
```

`-DBASELINE` も同じ動作です。

## 完成版の考え方

### 1. 位置と向きを一つの状態にする

状態番号は次の形です。

```text
state = (row * N + column) * 4 + direction
direction = 0:右, 1:下, 2:左, 3:上
```

各状態から `F/R/L` を行った次状態を最初に表へ保存します。あるマクロを1回実行した結果も、全状態について `macro_effect[state]` にします。

するとマクロ登録後の移動は、各状態から次の4辺が出る普通のグラフとしてBFSできます。

```text
F, R, L: 1ボタンでそれぞれの次状態へ
P:       1ボタンで macro_effect[state] へ
```

### 2. ボールを運ぶ順序を、到着方向まで含めて評価する

1個の仕事を「ボールを拾う → 対応かごへ置く」というペアにします。順序を固定しても、各地点へどの向きで着くかにより次の移動距離が変わります。

そこで各ボール・かごの到着方向4通りを前計算し、4要素のDPで順序全体の最短ボタン数を求めます。初期順序は複数のgreedyから作り、区間を別位置へ移す近傍の焼きなましで改善します。

候補評価では `T` ぎりぎりの展開長へ大きな罰を付けます。短く見えても、`P` を展開すると途中で切れる経路を避けるためです。

### 3. マクロを扱いやすい形に絞る

マクロは次のブロック列として持ちます。

```text
F を何回か + L/R/LL のいずれか
```

初期形はおおよそ `FFFFFFRFFFFFLFFR` です。焼きなましでは次をランダムに行います。

- `F` の回数を増減
- 曲がる向きを変更
- ブロックを追加・削除
- 隣接ブロック間で長さを移動・結合

完全な文字列空間より狭い代わりに、「移動として意味を持つマクロ」を短時間で多数試せます。同じ文字列hashは再評価しません。

### 4. 順序とマクロを交互に合わせる

完成版の中心は次の反復です。

```text
現在の運搬順序
  ↓
その順序に合うマクロを約30 ms探索
  ↓
そのマクロに合う順序を約5 ms修復
  ↓
良かった順序を次の反復へ渡す
```

「最短の通常経路」と「同じ部分を `P` で何度も使える経路」は一致しません。順序だけ、またはマクロだけを最後まで固定せず、少しずつ互いへ合わせます。

### 5. マクロ登録そのものも圧縮する

本命マクロを `M + 本文 + M` で直接登録する案に加え、本文中の短い反復を補助マクロにする案も試します。

例えば補助マクロが `FF` なら、先に `MFFM` と登録し、本命の記録中に一致部分を `P` で書けます。記録中の `P` も展開されて本命へ入るという問題固有の規則を利用しています。

さらに、本命マクロを登録する前に最大5手だけ動く候補も比較します。登録中に本文が実行されるため、「どこで登録を始めるか」も運搬開始位置と向きを変えます。

### 6. 最後の候補だけ経路を復元する

探索中は距離と展開後手数だけで候補を比較し、操作文字列は毎回作りません。最良候補が決まった後だけBFSの親をたどって `F/R/L/P/S/M` 列を復元します。

主な高速化は次です。

- BFS配列をepoch番号で再利用し、毎回の全初期化を避ける
- 連続する `F` の効果を表引きする
- 運搬順序の区間移動をprefix/suffix DPと4×4行列で評価する
- マクロhashで重複候補を除く
- 探索を複数フェーズに分け、最後の経路復元時間を先に確保する

## コードを読む順番

ファイルは高速な提出版を保ったため長めです。最初から全行を追わず、次の順が分かりやすいです。

1. `main` と `Solver::solve`: 全体の流れ
2. `build_simple_baseline`: マクロなしの最小例
3. `build_motion_transitions` と `build_macro_effect`: 状態遷移
4. `shortest_motion_with_macro`: `P` 辺を含むBFS
5. `annealed_macro_pair_order`: 運搬順序の方向DPと焼きなまし
6. `mutate_internal_macro_blocks_inplace`: マクロ近傍
7. `search_internal_macro_candidate_for_order`: 固定順序でのマクロ探索
8. `registration_plan_candidates`: 直接登録と補助マクロ登録
9. `build_best_registered_macro_candidate`: 順序とマクロの交互探索
10. `materialize_registered_macro_candidate`: 最終文字列の復元

独自namespaceは使っていません。座標・状態・候補は小さな`struct`に分け、主要パラメータはファイル先頭へまとめています。

### 速度とコンパイラ検査

- 通常の94ケースは `1.92〜1.93秒`、中央値 `1.92秒`
- バッチ中、ホストの周期的な負荷に重なった6ケースだけ `4.85〜4.88秒` の外れ値になった
- 外れ値だったseed 7を単独で3回再実行すると、すべて `1.92秒`
- 最大常駐メモリは `8,632 KB`
- 通常版、`SIMPLE_BASELINE`、`BASELINE` の3ビルドをC++17 strict警告0件でコンパイル
- AddressSanitizer + UndefinedBehaviorSanitizer版をseed 0、37、99で実行し、検出0件
- sanitizer時も3ケースすべて全収納し、Scoreは `282`、`55`、`157`

時間制限2秒に対して内部締切は1,950 msです。入力・前計算も締切内に含め、最後の経路復元用に30 msを先取りしています。ローカルの4.8秒値はプロセスが長時間スケジュールされなかった外れ値で、同じケースの単独再測定とは再現しませんでした。

## 既存資産と知識コーパスの扱い

手元に保存していた `main.cpp`、`main2.cpp`、`main3.cpp`、`main_copy.cpp`、マクロ探索ログを監査しました。

- 短い練習用として、通常経路の順序SA＋反復部分の後処理DP圧縮も独立実装し、公式100seedで全件合法・平均絶対Score `215.85` を確認した
- しかし、既存 `main3.cpp` の「マクロと運搬順序の交互探索」は同条件で平均 `186.98` と明確に強かった
- そのため弱い短縮版を正本にせず、強い交互探索を単一ファイルへ整理し、匿名namespaceを除去して合法baselineを追加した

知識コーパスはKnowledge mapと、構造的に近いAHC066・AHC006・AHC044・AHC052レビューだけを参照しました。

- AHC066の確認済み構造: pickup-and-delivery列を作り、反復部分をマクロへ変え、必要なら順序を再探索する
- AHC006からの一般的観点: 集荷・配達の先行関係を壊さない順序近傍
- AHC044/AHC052からの一般的観点: 小さな制御規則と実行列を交互に評価する

AHC066レビューの代表提出Scoreは未照合です。第三者提出コードは参照・転記せず、性能表にはこのローカルファイルを公式ツールで実行した値だけを使います。
