# 5. 乱数と再現性

[目次へ](README.md) · [前：候補の管理](04-candidates.md) · [次：時間予算](06-time.md)

乱数は候補の選択や悪化の受理に使います。乱数の範囲と、同じ実験を再現する条件を理解すると、探索の偏りやバグを調べやすくなります。

<a id="b20"></a>
## B20. seedを固定する意味

疑似乱数生成器は、内部状態から次の値を計算します。seedはその初期状態を決める値です。同じ生成器に同じseedを与え、同じ順序・同じ回数で呼び出せば、同じ列が得られます。

これは不具合の再現に役立ちます。「入力17、seed42、反復518で壊れた」と記録できれば、その時点を追いやすくなります。現在時刻だけでseedを決め、記録しない実装では再現が難しくなります。

**注意。** seedだけで実行全体が完全に同じになるわけではありません。時間制限で終了する探索は、実行速度によって反復回数が変わります。近傍を1つ追加して乱数を消費する順番が変わっても、その後の候補列は変わります。

乱数の再現性を調べるときは反復回数を固定し、最終性能を比べるときは実時間も揃える、と目的を分けると扱いやすくなります。

**練習。** 同じseedで2つの `Random` を作り、最初の10個の整数を比べてください。片方だけ途中で1回余分に乱数を引き、その後がどうずれるか確認します。

**キットとの対応。** [Random(seed)](../../library/random.hpp)。整数分布やシャッフルまで同じ列に揃えるには、使用する標準ライブラリの実装・版も揃えて記録します。

<a id="b21"></a>
## B21. 剰余を取るだけでは偏ることがある

0から9までが同じ確率で出る乱数を、3で割った余りに変えるとします。0になる元の値は `0, 3, 6, 9` の4個、1と2はそれぞれ3個です。結果は一様ではありません。

一様にしたければ、例えば0から8までだけを使い、9が出たときは引き直します。使う値の総数を3の倍数にすれば、各余りに同じ数の元の値が対応します。このように一部を捨てて引き直す方法を棄却法と呼びます。

64ビット乱数でも原理は同じです。範囲の大きさが抽選したい個数で割り切れない場合、単なる剰余にはわずかな偏りが残ります。キットの `Random::next_int` は、一様整数分布を提供する `std::uniform_int_distribution` を利用します。

**注意。** 上限0の抽選は定義できません。また、候補が空なのに乱数だけ引こうとしていないか確認します。小さな偏りより、候補がほとんど無効で引き直しを繰り返す費用の方が大きい場合もあります。

**練習。** 0から15を5で割った余りの個数を数え、どの値を捨てれば均等にできるか示してください。

**キットとの対応。** `Random::next_int(left, right)` は `[left, right)` です。右端は含まず、`left < right` が必要です。

<a id="b22"></a>
## B22. シャッフルは残っている範囲から選ぶ

配列の末尾に入れる要素を全体から1つ選び、次は残りの末尾に入れる要素を未確定部分から1つ選びます。これを繰り返すのがFisher–Yates型のシャッフルです。

3要素A、B、Cなら、最後の位置を選ぶ方法が3通り、その前が2通り、最後の1つは1通りです。合計 `3 × 2 × 1 = 6` 通りの選択列があり、各選択が一様なら6種類の順列が同じ確率になります。

「各位置について配列全体から相手を選んで交換する」方法は、見た目は似ていても同じ性質を持つとは限りません。要素がどの順列へ到達する経路を何個持つかが異なるためです。

**注意。** シャッフルが一様でも、その後に無効候補を拒否する処理があれば、採用された候補の分布は変わります。乱数生成と候補選別を分けて考えます。

**練習。** 3要素で、各位置が全体から交換相手を選ぶ方法には27通りの選択列があります。27を6で均等に割れないことから、全順列を同確率にできない理由を説明してください。

**キットとの対応。** `Random::shuffle(values)` はvectorを受け取り、`std::shuffle` を呼びます。

<a id="b23"></a>
## B23. 実数乱数の端点と丸めを確認する

`[0, 1)` は0を含み1を含まない範囲、`(0, 1)` は両端を含まない範囲です。区間の違いは、対数、配列添字、確率判定で重要です。例えば `floor(u × N)` で添字を作るなら、`u = 1` が出るとNになって範囲外です。

数学上は端点を避けた式でも、浮動小数点の丸めで端点へ到達することがあります。例えば、53ビット整数に0.5を足して `2^53` で割る自作の式を考えます。通常のIEEE 754 binary64・最近接丸めでは、最大の整数に0.5を足した値が `2^53` へ丸められ、結果が1.0になる境界があります。

したがって、関数名やコメントだけで厳密な開区間を仮定せず、実際の式と丸めを検査します。現行キットの `SimulatedAnnealing::random_01()` は上位53ビットをそのまま `2^53` で割る形で、0を含む `[0, 1)` を作ります。上の0.5を足す式とは異なります。

**注意。** 1.0が出ても対数は計算できますが、厳密な開区間の契約を必要とする別の用途では問題になります。一般の添字抽選には `Random::next_int(0, size)` を使う方が、意図を明確にできます。空の配列は抽選する前に処理を分けます。

**練習。** `((double)((1ULL << 53) - 1) + 0.5) / (double)(1ULL << 53)` を表示し、1.0と等しいか確認してください。続いて、0が出た場合に `log(u)` がどうなるかも調べます。

**キットとの対応。** [Random::next_real / next_int](../../library/random.hpp) と [SimulatedAnnealing::random_01](../../library/simulated-annealing.hpp)。実数乱数は0を含む仕様なので、対数への入力は別に確認します。境界値は最大値を直接作る検算も使います。
