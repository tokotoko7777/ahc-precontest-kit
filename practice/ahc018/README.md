# AHC018 練習解答

公式問題: [A - Excavation](https://atcoder.jp/contests/ahc018/tasks/ahc018_a)

`main.cpp` だけを提出できる、対話型問題用の自己完結した C++17 解答です。
外部ヘッダーや独自 namespace は使っていません。

## 何をしているか

1. 水源と家のマスを先に掘り、硬さの観測値を得ます。
2. 壊したマスのうち、水源からつながったマスを「水路」として持ちます。
3. 全ての水路を始点、まだ水が来ていない家を終点として、推定掘削費で Dijkstra 法を実行します。
4. 選んだ道を8マス掘るたびに硬さの推定を更新し、経路を引き直します。
5. 全ての家へ水が届くまで繰り返します。

地盤は空間的に滑らかなので、あるマスを壊したときの硬さを近傍の予測へ使えます。ただし、家と水源は生成上やわらかい場所に偏るため、遠方までその値を信じず、距離とともに硬さ1000へ戻しています。

1回の掘削強度は、おおよそ

```text
sqrt(2 * C * 予測硬さ)
```

です。`C=128` で、直前に隣のマスを観測できた場合だけ、予測硬さを初回の掘削にも利用します。それ以外では、小刻みに掘って過剰なパワーを避けます。

## 提出

```bash
g++ -std=c++17 -O2 -pipe main.cpp -o main
```

提出するのは `main.cpp` だけです。対話型なので、各出力の後に必ず flush が必要です。この実装では `endl` が改行と flush の両方を行います。

## 公式ローカルテスターでの実行例

公式ツールのディレクトリで、次のように実行します。

```bash
cargo run --release --bin tester /path/to/main < in/0000.txt > out.txt
```

比較用に `-DSIMPLE_POLICY` を付けてコンパイルすると、「最初の水源から各家まで直角に掘る」単純解になります。

```bash
g++ -std=c++17 -O2 -pipe -DSIMPLE_POLICY main.cpp -o simple
```

公式配布ツールの seed 0〜9 で、同じコンパイラ設定の通常版と単純版を比較しました。値は公式テスターが表示する `Total Cost` で、小さいほど良い値です。

この10ケースでは全ケースで通常版が改善し、合計コストは約55.1%減りました。さらに公式 seed 0〜99 は全て正常終了し、通常版の平均コストは244,138.21、最小30,430、最大648,452でした。最適化ビルドの観測最大 wall time は0.56秒です。

次の設定でも確認しています。

- `-Wall -Wextra -Wpedantic -Wconversion -Wshadow`: 警告なし
- AddressSanitizer + UndefinedBehaviorSanitizer: seed 0, 5, 61, 89 で異常なし

LeakSanitizer は公式テスターが子プロセスを監視する実行形態と衝突するため、sanitizer確認時だけ `ASAN_OPTIONS=detect_leaks=0` としました。

## 計算量

- 硬さ観測の反映: 掘った1マスにつき `O(N^2)`
- 経路の再計算: 8マスにつき1回、`O(N^2 log N)`
- メモリ: `O(N^2)`

`N=200` 固定なので、複雑な空間データ構造を使わず初心者向けの実装を優先しています。

## 失敗しやすい場合

- 隣接マスでも硬さが急変すると、初回掘削の予測が外れます。
- 最近傍の観測値を1個だけ使うため、複数の硬さ領域の境界を精密には表せません。
- 経路を8マス単位で作るので、再計画で途中の枝を捨てることがあります。その枝も水路として残るため、完全な無駄とは限りません。
