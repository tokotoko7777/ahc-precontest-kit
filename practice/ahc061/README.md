# AHC061 練習用ソルバー

AHC061「[Multi-Player Territory Game](https://atcoder.jp/contests/ahc061/tasks/ahc061_a)」の、提出可能な単一 `main.cpp` です。外部ヘッダや同梱ライブラリには依存しません。

公式スコアは次の値で、**大きいほど良い**です。

```text
round(100000 * log2(1 + S0 / max(S1, ..., S(M-1))))
```

## まず動かす

通常版をコンパイルします。

```bash
g++ -std=c++17 -O2 -pipe main.cpp -o solver
```

公式ローカルテスタのディレクトリで、たとえば seed 0 を実行します。

```bash
target/release/tester /path/to/solver < in/0000.txt > out.txt
```

対話問題なので、`main.cpp` を入力ファイルへ直接リダイレクトして実行するのではなく、必ず `tester` から起動します。AtCoder へは `main.cpp` だけを提出できます。

## 何をしているか

このゲームでは相手の `wa, wb, wc, wd, epsilon` が隠されています。ただし、相手が実際に選んだマスは毎ターン分かります。そこで次の順に手を決めます。

1. 自分の連結領土を BFS し、合法手を全て作る。
2. 相手ごとに512個の「隠しパラメータ候補」を持つ。
3. 観測した相手の手が出やすかった候補の確率を上げる。
4. 推定分布から40通りの相手行動を作る。
5. 軽い評価で自分の候補を上位18手へ絞る。
6. 全候補を同じ40シナリオで3手先まで進める。
7. 衝突、占領、強化、攻撃、駒の復帰を再現し、公式スコア式が最も良い手を選ぶ。

候補間で同じ相手パラメータと乱数を使うため、「候補Aだけ運の悪いシナリオを引いた」という比較ノイズを減らしています。

ニューラルネットワークや学習済みデータは使っていません。コードだけ読めば処理を追えるよう、以下の小さな関数に分けています。

- `legal_moves`: BFS で合法手を列挙
- `predict_moves`: 相手の各マスへの移動確率を計算
- `observe_move`: 観測した手で相手モデルを更新
- `simulate_turn`: 公式ルールどおりに1ターン進める
- `choose_move`: 候補制限と3手ロールアウト

## 合法 baseline

比較用に、相手予測をせず「直ちに自分の得点が増える最大価値マス」を選ぶ合法貪欲も同じファイルに入っています。

```bash
g++ -std=c++17 -O2 -pipe -DSIMPLE_BASELINE main.cpp -o baseline
```

通常提出では `-DSIMPLE_BASELINE` を付けません。

## 実装上の注意

- 座標は公式どおり `(row, column)` の順です。
- 毎ターン、改行後に `flush` しています。
- 相手の駒が現在いるマスを候補から除外しています。
- シミュレーションでは、同じマスの所有者だけが衝突に勝つ規則も再現しています。
- レベル2以上への攻撃が失敗したときは、レベルだけを1下げ、駒を元の位置へ戻します。
- 固定乱数を使うため、同じ入力なら同じ行動になります。

計算量の中心は、おおよそ `候補18 × シナリオ40 × 先読み3 × プレイヤー数 × 100マス` です。盤面が常に10×10なので、動的確保や巨大な状態を必要としません。

### 合法性と速度

- 公式testerで seed 0〜99 の全100ケースが正常終了
- 不正手、途中終了、スコア0: 0件
- 全ケースで出力はちょうど100行、合計10,000行
- バッチ計測の実行時間中央値338ms、95パーセンタイル562ms、99パーセンタイル651ms
- バッチ中にホスト負荷由来と見られる4.055秒の外れ値が1回ありました。同じケースを単独で3回再実行すると0.48〜0.49秒でした。
- 人数8の重めの代表ケースも単独再実行で0.58〜0.67秒でした。

提出環境の速度差に対しても、2秒制限から十分な余裕を取った固定量探索です。

### コンパイラ検査

次の警告を全て有効にし、通常版とbaselineの両方を警告0件でコンパイルしました。

```bash
g++ -std=c++17 -O2 -pipe \
  -Wall -Wextra -Wshadow -Wconversion -Wpedantic \
  main.cpp -o solver
```

AddressSanitizer + UndefinedBehaviorSanitizer 版でも seed `0, 19, 47, 70, 99` を公式testerで完走し、検出0件でした。実行環境ではLeakSanitizerが `ptrace` と共存できないため、リーク検査だけ `detect_leaks=0` とし、ASan/UBSan本体は有効にしています。

## 参考にした知識と範囲

公式問題文・公式generator/tester/visualizerの仕様を先に確認しました。その後、ローカル知識集から Knowledge map と AHC061、構造的に近い AHC003・AHC029・AHC054 のレビューだけを参照しました。

- AHC061レビューで確認できた知見: オンライン相手推定を盤面方策へ入れる考え方
- AHC003レビューから移した考え方: 複数仮説を尤度で重み付けするオンライン推定
- AHC029レビューから移した考え方: 候補を絞って短い確率ロールアウトを行う構成
- AHC054レビューから移した考え方: 相手方策を内蔵したシミュレーションのモデルずれに注意すること

AHC061の代表レビューには「代表提出のスコア未照合」「学習データと学習手順は未確認」というギャップがあります。そのため、レビューにあるCNNや第三者提出コードは使わず、公式ルールから独立に粒子推定と短期シミュレーションを実装しました。
