# AHC065 練習用ソルバー

[AHC065 A - Conveyor Design](https://atcoder.jp/contests/ahc065/tasks/ahc065_a) の、提出可能な単一 `main.cpp` です。
リポジトリ内のライブラリや AtCoder Library には依存しません。

## 問題を短く整理

- 盤面は常に `20 x 20` で、箱 `0..399` が1個ずつあります。
- 搬出口は `(0, 10)` です。
- 最初に、上下左右に隣接するマスからなる環状ベルトを最大400本作ります。
- 1マスが属せるベルトは高々2本です。
- 1操作で、選んだベルトを右回りまたは左回りへ1マス動かします。
- 搬出口に「今残っている最小番号」の箱が来ると、その箱が取り除かれます。
- 最大100,000操作です。全400箱を出した場合は、操作数が少ないほど高得点になります。

## まず理解しやすいbaseline

`-DBASELINE` を付けると、400マスすべてを通る蛇行ベルトを1本だけ作ります。
次の箱まで近い方向へ回すことを400回繰り返すだけです。

```bash
g++ -std=c++17 -O2 -DBASELINE main.cpp -o baseline
./baseline < in.txt > out.txt
```

各箱まで高々200回転なので、合計は必ず80,000操作以下です。単純ですが、合法な解を作る最初の例として使えます。

## 完成版の考え方

### 1. 200マスの主ベルトと200個のポケット

盤面を100個の `2 x 2` ブロックに分けます。

各ブロックでは、隣接する2マスを主ベルトに使い、残り2マスをそれぞれの「ポケット」にします。主ベルトの各マスと対応ポケットを、長さ2の小さなベルトで接続します。

```text
主ベルト: 1本、長さ200
swap用ベルト: 200本、各長さ2
合計: 201本
```

主ベルト上のマスは「主ベルト + swap用ベルト」の2本に属し、ポケット側はswap用ベルト1本だけに属します。したがって「各マスは高々2本」という制約を構築時点で満たします。

### 2. 必ず閉路になる候補だけ作る

まず `5 x 5` の粗い盤面でランダムな全域木を作ります。各粗マスを小さな4頂点閉路にし、全域木の辺に沿って閉路を順に結合すると、`10 x 10` の全ブロックを1回ずつ通るHamilton閉路になります。

そのブロック閉路を `2 x 2` の実マスへ展開すると、長さ200の主ベルトが得られます。この作り方では、探索中に壊れたベルトを生成してから修理する必要がありません。

- 蛇行型の固定候補16個
- 固定seedで作る全域木候補1000個と、その逆向き

を試します。通常環境では計2016レイアウトを評価します。1.50秒で探索を止める保険も入れており、途中で止まっても最初の固定候補から必ず合法解を出します。

### 3. 箱を200個ずつ処理する

箱を `0..199` と `200..399` の2組として扱います。

1. 今の組の箱を、主ベルトからポケットへ一度退避する。
2. 主ベルトを1周させながら、番号順になる位置へ箱を戻す。
3. もう1周させ、並んだ箱を搬出口から順番に出す。

退避時は、主ベルト上の対象箱と空いているポケットを円環順序を保って対応させます。対応の開始位置を全通り試し、「最後の箱を退避するまでの回転数」が最小になる組合せを選びます。

### 4. 出力と同じ操作をシミュレーションする

候補評価では近似式を使わず、次をそのまま配列上で再生します。

- 主ベルトの回転
- ポケットとのswap
- 搬出口での箱の除去
- 実際に出力する操作列

全箱を搬出できた候補のうち、操作数が最小のものだけを出力します。

## コードを読む順番

1. `make_snake_cycle`: baselineと固定候補の蛇行閉路
2. `make_tree_cycle`: 全域木から保証付き閉路を作る
3. `make_layout`: ブロック閉路を主ベルトとポケットへ展開する
4. `simulate`: 退避・整列・搬出を正確に再生する
5. `main`: 候補生成、比較、出力

## 既存資産の監査

手元に保存していた旧版を、公式入力・公式testerで確認しました。

### `main.cpp`

- 400マスを通る全域ベルトを2本作る
- 幅700、先読み3箱のbeam search
- 代表ケースで約1.8〜2.0秒
- strict compileでは `int` から `int16_t` への変換警告が6件

公式100 seedはすべて合法でしたが、2秒制限に対する余裕が小さめです。

### `main2.cpp`

200マスの主ベルトと200個のswapベルトを使う高速な決定的構築で、既存ソースの中では最も良好でした。ただし、実際には使っていない `atcoder/all` へ依存しており、そのままでは単一ファイルになりません。

完成版はこの「主搬送路 + 局所交換器」という分解を採用し直し、全域木から作る多数の保証付きレイアウトと、円環の切れ目に依存しない退避割当を追加しています。

### `main3.cpp` と `a.out`

- `main3.cpp` は0 byteで、実装はありません。
- `a.out` はログを標準エラーへ出す2本全域ベルト系の中間バイナリでした。seed 0, 1, 2はすべて合法で、得点は6,106,809・6,124,314・6,094,926、操作数は2,902・2,867・2,926でした。

## 速度と安全性

- 完成版100ケースのwall time中央値: `0.530秒`
- 95 percentile: `0.570秒`
- 外れ値2件を除く最大: `0.590秒`
- 共有計測環境の同時負荷で2ケースだけ4.11〜4.14秒になりましたが、同じ2ケースを各3回再測定すると `0.52〜0.59秒` でした。
- ソースには1.50秒の探索停止判定があります。
- C++17 strict compile: 警告なし
- ASan + UBSan: seed 0, 42, 99で異常なし
- sanitizer版も3ケースすべて公式testerで合法

sanitizer版は計装が重いため1.50秒の探索停止まで到達し、3ケースとも約1.51秒でした。候補数が通常版より減るため、性能比較には使っていません。
