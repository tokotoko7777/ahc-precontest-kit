# AHC060 練習用ソルバー

グラフを歩いて Vanilla (`W`) と Strawberry (`R`) の列を作り、10 個の店へ異なる文字列をできるだけ多く届ける問題の提出用 `main.cpp` です。
外部ライブラリやリポジトリ内のヘッダには依存しません。

## 問題の要点

- 頂点 `0..9` は店、`10..99` はアイスの木です。
- 木へ移動すると、その時点の `W/R` がコーンの末尾へ追加されます。
- 店へ移動すると、コーンの文字列がその店の集合へ入り、コーンは空になります。
- `-1` を出すと、現在いる未反転の木を `W` から `R` へ永久に変えます。
- 直前の移動元へすぐ戻ることは禁止されています。
- 最大10,000操作で、各店へ届けた異なる文字列数の合計が得点です。

## このソルバーの方針

### 1. 木を二色の固定ラベルにする

`R` にする木を最初に決め、現在位置と直前位置を状態にしたBFSで近い対象木を順に訪れます。対象木に着いたらすぐ `-1` を出します。

移動途中で別の対象木を通った場合も、その場で反転します。準備後は各木の色が固定されるため、経路を二進文字列として扱えます。

`R` の本数は25・35・45・55・65本を試し、それぞれ4通りの決定的な並べ替えを使います。

### 2. 未登録文字列を届ける最短経路を探す

1回店へ入るたびに、次の配送経路をBFSします。探索状態は次の3つだけです。

```text
(直前の頂点, 現在の頂点, 現在の W/R 文字列)
```

直前の頂点を持つことで、禁止されている即時逆走を候補生成の時点で除外できます。

店へ到着したとき、その文字列がまだ店の集合にない経路を見つけたら得点になります。最短手数を優先し、同じ長さなら次を優先します。

- 登録数が少ない店
- 同じ辺からの入店回数が少ない店
- 頂点・文字列の辞書順

短い文字列を使い切って新規配送が見つからない場合は、入店辺の使用回数が少ない経路を使って別の状態へ移り、次の配送を探します。

### 3. 全候補を正確にシミュレーションする

各店は実際の `unordered_set<string>` を持ちます。rolling hashだけで同一性を近似せず、出力と同じ移動・収穫・納品・反転をそのまま再生して得点を比較します。

各色分け案には75msの時間枠を設けています。20案すべてが難しい探索へ入っても約1.5秒で止まり、2秒制限へ余裕を残します。

## コンパイルと実行

```bash
g++ -std=c++17 -O2 -Wall -Wextra -Wshadow -Wconversion -pedantic \
  main.cpp -o main
./main < in.txt > out.txt
```

全木を `W` のままにする簡単な比較版は `-DBASELINE` で動かせます。

```bash
g++ -std=c++17 -O2 -DBASELINE main.cpp -o baseline
```

公式testerでの確認例です。

```bash
cargo run --release --bin vis in.txt out.txt
```

## 合法性について

- 移動候補は入力された隣接リストからだけ選びます。
- BFS状態に直前頂点を含め、そこへ戻る辺を生成しません。
- `-1` は対象の未反転木へ到着した直後だけ出します。
- 操作追加前に10,000手上限を確認します。
- 最後に公式testerでseed 0〜99を全件検証しています。

なお、knowledge corpusのAHC060 Reviewは公式問題文と異なる問題要約を含んでいました。そこからは「重要イベントへ圧縮する」「変更後を正確に再生する」という一般的な観点だけを使い、仕様・合法性・得点は公式問題文と公式testerを正としています。
