# AHC037 練習用ソルバー

[AHC037 A - Soda](https://atcoder.jp/contests/ahc037/tasks/ahc037_a) の、提出可能な単一 `main.cpp` です。ローカルの `.hpp` には依存しません。

最初に持っている `(0, 0)` から、両方の座標を増やす操作だけで1,000個の目標点を作ります。1操作のコストは増やした `x+y` で、操作回数は最大 `5N=5000` です。スコアは大きいほど良く、総コストが小さいほど高くなります。

## まず使う

```bash
g++ -std=c++17 -O2 main.cpp -o main
./main < in.txt > out.txt
```

提出時は `main.cpp` をそのままAtCoderへ貼り付けます。

[公式ツール](https://img.atcoder.jp/ahc037/WneGTzJP.zip)で合法性・コスト・スコアを確認できます。

```bash
# 公式toolsディレクトリで一度だけ
cargo build --release --bin vis

./target/release/vis in/0000.txt out.txt
```

## 一番簡単な解

全目標を原点から直接作れば必ず合法です。

```text
(0, 0) -> (A_i, B_i)
```

ただし、似た方向にある目標にも毎回同じ区間のコストを払います。このコードは `-DDIRECT_BASELINE` を付けると、その単純解になります。

```bash
g++ -std=c++17 -O2 -DDIRECT_BASELINE main.cpp -o baseline
```

## このsolverの考え方

2つの点 `P=(px, py)` と `Q=(qx, qy)` を考えます。両方へ向かう共通の中継点として

```text
S = (min(px, qx), min(py, qy))
```

を使えます。`S` までは1回だけ作り、そこから2方向へ分岐できます。原点から別々に作る場合と比べて、`S.x + S.y` だけコストを節約できます。

この性質を使い、次の順で木を作ります。

1. 1,000個の目標を、それぞれ1個の小さな木とみなす
2. 全ペアの「共有できる長さ」を優先度付きキューへ入れる
3. 共有部分が長い2本をまとめ、中継点を親にした新しい木を作る
4. 木が1本になるまで繰り返す
5. `((A,B),C)` を `((A,C),B)` に変えるような小さな組み替えで、共有部分が伸びる場合だけ更新する
6. 同じ座標の中継点をまとめ、子が0個または1個しかない不要な中継点を消す

単純に毎回1位のペアを選ぶ案に加え、上位2〜3ペアについて次の1回まで軽く先読みする案も作ります。合計4案の総コストを整数で正確に計算し、最小の1案だけを出力します。時間や乱数には依存しないため、同じ入力なら常に同じ結果です。

最後は親を先、子を後に出力します。そのため、各操作の始点は必ずその前に作られています。

## コードを読む順番

最初から全部を追う必要はありません。

1. `main`：入力、候補比較、出力
2. `make_agglomerative_operations`：2本ずつ木をまとめる中心部分
3. `operation_cost`：候補を正確に比較する関数
4. `choose_nearest_parents` と `remove_useless_steiner_points`：中継点の整理

主要な調整値はファイル冒頭にあります。

| 定数 | 初期値 | 意味 |
|---|---:|---|
| `MAX_POINT_COUNT` | 5001 | 原点込みの最大点数。操作上限5000を守る |
| `REFINE_ROUNDS` | 5 | 中継点整理の反復上限 |
| `MERGE_LOOKAHEAD` | 3 | 単独構築時に比較する上位ペア数 |
| `TREE_LOCAL_PASSES` | 30 | 木の小さな組み替え回数 |
| `LOOKAHEAD_FUTURE_PERCENT` | 50 | 次の併合を現在の何%で見るか |

探索の中心は約 `O(N^2 log N)`、メモリは約 `O(N^2)` です。`N=1000` 固定なので、全ペアを持っても十分小さく収まります。

## 検証

- `g++ -std=c++17 -O2 -Wall -Wextra -Wshadow -pedantic`：警告なし
- 公式visualizer：seed 0〜99の全ケースで合法、スコア0なし
- AddressSanitizer + UndefinedBehaviorSanitizer：seed 0, 37, 99で異常なし
- sanitizer版の公式再採点：それぞれ `35,939,493`、`35,950,845`、`35,806,083`

知識コーパスからは、AHC037の「座標優越を親子関係にして共有経路を増やす」という確認済みレビューを構造上の参考にしました。一方、記録された代表提出の最終スコアは未照合です。この実装は、成分ごとの最小値を分岐点にする階層併合と軽い2手先比較として独自に組み立て、上記の数値もこのコードを公式ツールで測った結果だけを記載しています。
