# AHC067 練習解答: 扉で作る10ビットカウンタ

提出するのは [`main.cpp`](./main.cpp) だけです。ローカルのヘッダやライブラリには依存せず、独自 `namespace` も使っていません。

- 公式問題: <https://atcoder.jp/contests/ahc067/tasks/ahc067_a>
- 制限時間: 2秒

## 問題を短く整理

20×20の城へ、最大50枚の扉と10種類のスイッチを置きます。勇者は入口から玉座までの最短手順を選ぶので、その最短手数 `T` を大きくする問題です。

- スイッチ `k` を押すと、扉 `2k` と `2k+1` の開閉が入れ替わる
- 偶数型の扉は最初に開き、奇数型は最初に閉じている
- 移動もスイッチ操作も1手
- 勇者の状態は `(現在位置, 10個のスイッチの偶奇)`
- 到達時の得点は `round(1,000,000 × log2(T / 20))`
- 到達不能にすると1点なので、完全に封鎖してはいけない

## 最も簡単なbaseline

扉もスイッチも置かなければ、元の迷路の最短経路をそのまま通れます。これは常に合法な比較対象です。

```bash
g++ -std=c++17 -O2 -DSIMPLE_BASELINE main.cpp -o baseline
./baseline < in.txt > out.txt
```

出力は次の2行だけです。

```text
0
0
```

## この解法

### 1. 空きマスをグラフにする

空きマスを頂点、上下左右の移動を辺として扱います。扉は辺に置くため、以降は盤面座標よりも辺番号を中心に考えます。

次数2の頂点では、両側の辺へ互いに逆状態の扉を置くと、その通路を実質的な壁として使えます。候補ごとにこの2辺組を5個、合計10辺選びます。

### 2. 壁を除いたグラフを橋の木へ縮約する

選んだ10辺を一時的に除き、Tarjan法で橋を求めます。橋でない辺だけをたどって連結成分へ縮約すると、成分と橋からなる木ができます。

木の枝は「この扉を通らないと先へ行けない」を作りやすい場所です。入口から玉座へ続く幹と、スイッチを置くための脇枝を選びます。

### 3. 10個のスイッチを二進カウンタのようにつなぐ

単にスイッチを10個並べても、勇者は各スイッチを1回ずつ押すだけです。そこで、上位スイッチへ行く前に下位スイッチの状態を揃え、帰りにまた戻す扉構造を作ります。

概念的には次の再帰です。

```text
bit 0 を切り替える
bit 1 の場所へ行くために bit 0 を使う
bit 2 の場所へ行くために bit 0, 1 を使う
...
bit 9 を切り替えて、最後に玉座へ進む
```

これにより、スイッチ操作だけでも約 `2^10 - 1` 回が必要になります。実際には各スイッチ間の往復移動も加わるため、最短手数はさらに長くなります。

50枚の上限へ収めるため、最初の2段を複数の枝で共有します。残りの枝と玉座への末尾にだけ個別の扉を置き、10枚の壁用扉と合わせてちょうど50枚を使います。

### 4. 安い概算で候補を大量に比べる

すべての候補へ状態付きBFSを行うと重すぎます。構築したカウンタを予定どおりたどると仮定し、各スイッチ間の通常BFS距離へ訪問回数の重みを掛けた値を `estimate` とします。

```text
概算 = スイッチ操作回数
     + bit 0 から各上位bitへの往復距離 × その訪問回数
     + 最後の玉座までの距離
```

この概算なら、各BFSの状態数は空きマス数だけです。

### 5. 焼きなましで配置を変える

候補の変更は2種類です。

- 同じ安全な領域内でスイッチ位置を移す
- 壁として使う次数2の2辺組を入れ替え、橋の木から作り直す

良化は必ず採用し、悪化も温度に応じて採用します。盤面文字列から乱数seedを作るため、入力ごとに探索系列が変わります。

時間配分は次の通りです。

- 0〜750 ms: 初期候補を多数生成
- 750〜1450 ms: 焼きなまし
- 最後: 上位16候補を正確に比較

有効候補がまだない場合だけ、初期生成を最大1725 msまで延長します。通常は750 msで終わるため、難しい入力専用の保険です。

### 6. 最後は `(位置, bitmask)` BFSで保証する

概算が大きくても、勇者が予定外の近道を見つけることがあります。そこで上位候補だけは、最大約40万状態の正確なBFSで最短手数を計算します。

- 移動先の扉が現在のbitmaskで開いていれば移動
- 現在地にスイッチがあれば、その1bitを反転
- 初めて玉座へ着いた距離が本当の `T`

最終出力は、この正確な `T` が最大の候補です。構築に失敗した場合も、扉0・スイッチ0の合法出力へ戻ります。

## コードを読む順番

1. `main` と `Solver::solve`: 全体の流れ
2. `build_graph`: 盤面を辺付きグラフへ変換
3. `random_static_edges`: 壁候補を5組選択
4. `build_from_static_edges`: 橋の木と10ビット構造を構築
5. `estimate`: 軽い代理評価
6. `anneal`: スイッチ位置と壁候補を変更
7. `exact_score`: 状態付きBFS
8. `print_answer`: 辺番号を公式の座標形式へ戻す

最初に調整するなら、`SEARCH_TIME_LIMIT_MS` だけを変えてください。各探索期限はこの値に合わせて同じ割合で伸縮します。

## 公式seed 0〜99での検証

公式配布入力と公式visualizerを使い、同じ100ケースで比較しました。

| 版 | 合法 | 合計Score | 平均 | 中央値 | 最小 | 最大 |

| 10ビットカウンタ | 100 / 100 | 1,084,469,134 | 10,844,691.34 | 10,903,806.0 | 9,169,800 | 11,498,924 |

- 完成版 vs baseline: `100勝 / 0分 / 0敗`
- 100ケースすべてで10ビット構築に成功し、100万点付近へのフォールバックは0件
- 実行時間: 平均 `1.463秒`、中央値 `1.460秒`、95 percentile `1.470秒`、最大 `1.650秒`、最大RSS `7.1 MB`
- 共有CPUで停止時間を含むwall timeが4.39秒になった4ケースは、通常負荷で再測定して上の集計へ置き換えました

時間で探索回数を決めるため、CPU負荷によって配置とScoreは少し変わります。乱数そのものは入力から決まる固定seedです。

## 既存資産と知識コーパスの扱い

手元に保存していた複数候補を、公式visualizerで同じ代表seedへ通して監査しました。安定版は7代表seedで平均約1082万点、他の初期候補は約970万〜1031万点でした。より複雑な実験版には複数seedで100万点付近へ落ちる失敗があったため採用していません。

採用した安定版から、実行されない9ビット旧構築、未使用補助関数、使えない追加壁処理を削除しました。実際に使う10ビット構築・焼きなまし・正確BFSだけを残しています。

知識コーパスはKnowledge mapと、AHC067・AHC065・AHC054・AHC044のレビューだけを参照しました。

- 確認済みレビュー: スイッチ依存を入れ子にし、状態付き最短路で近道を検査する
- 静的解析からの判断: 概算を全候補、正確BFSを少数eliteだけに使う
- この実装での新しい整理: 最初の2段を共有して50枚へ収める構築を、未使用経路なしの単一ファイルにする

第三者提出コードは参照・転記していません。コーパス中の代表提出Scoreは未照合なので性能根拠にせず、上表はこの `main.cpp` を公式ツールで測った値だけを使います。
