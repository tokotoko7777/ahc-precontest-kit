# AHC054: Treant's Forest

`main.cpp` だけで提出できる、C++17 のインタラクティブソルバーです。ローカルのヘッダやライブラリには依存しません。

- 公式問題: <https://atcoder.jp/contests/ahc054/tasks/ahc054_a>
- 公式Webビジュアライザ: <https://img.atcoder.jp/ahc054/YDAxDRZr_v2.html?lang=ja>

## 問題の要点

- 盤面サイズは `20 <= N <= 40`、入口は `(0, N/2)` です。
- 本物の木と花の位置は最初からソルバーに渡されます。
- 毎ターン、冒険者の現在位置と、新しく見えたマスが渡されます。
- 木を追加できるのは「まだ見えていない・空いている・花ではない」マスだけです。
- 木を置いたあとも、入口から花まで実際の空きマスだけで到達できなければなりません。
- 冒険者が花へ着くまでの移動回数がスコアです。大きいほど良いです。

冒険者は未確認マスを空きだと思って移動先を決めます。したがって、単に花までの最短路を長くするだけでなく、「一度に見える未知マスを少なくする」ことも重要です。

## 方針

### 1. 花の周囲に小さな要塞を作る

初手に、花 `F` の周囲へ次の形を置きます。`X` は木、`o` は花へ入る最後の一マス、`O` は外側の通路の始点です。

```text
    X
O   o X
X   F X
    X
```

この形を回転・反転した8通り試し、入口から花へ到達できるものだけを残します。花へは `O -> o -> F` の曲がった入口からしか入れないため、偶然の到達が起きにくくなります。

### 2. 要塞の外側に細い通路を付ける

`O` から要塞の木3個のそばへ順にBFSで道を伸ばし、その道の両側へ木を置きます。通路の終端だけは次の区間へつなぐため開けます。

候補の優先順は次の通りです。

1. 完成した通路区間が多い
2. 入口から到達できる空きマスが多い
3. 花までの距離、または開口部と盤端の距離が良い
4. 同点なら置く木が少ない

中央のガード木の四方が天然木で埋まる場合だけ、一つ外側の天然木を目標にする代替経路を使います。seed番号に依存する特別処理ではなく、盤面の形だけで決まります。

### 3. 毎ターン、視線の手前を少しだけ塞ぐ

現在位置から上下左右へ6マスまでを候補にし、各方向から高々1個を選びます。

- 初手: 下・右・左の最大3方向
- 2手目以降: 最大2方向

全候補を小さく全探索し、「このターン新しく見えるマス」が最少の案を選びます。同点なら入口から花までの距離が長い案を選びます。

ただし、木を置く前にBFSを行い、以前入口から行けたマスを不用意に切り離さない案だけを採用します。最後にも入口から花へ届くことを再確認します。

### 4. 時間切れを避ける

開始から1650 msを超えたら `-1` を出して終了します。公式testerは、その後を「追加の木なし」で最後までシミュレーションします。

## コンパイルと実行

提出用のコンパイル例です。

```bash
g++ -std=c++17 -O2 main.cpp -o main
```

この環境にある公式testerで seed 0 を試す例です。

```bash
/home/utility/AHC054/target/release/tester ./main \
  < /home/utility/AHC054/in/0000.txt \
  > out.txt
```

スコアは標準エラーに表示されます。`out.txt` は公式Webビジュアライザへ貼り付けられます。

何もしない比較用ソルバーも、同じファイルから作れます。

```bash
g++ -std=c++17 -O2 -DSIMPLE_BASELINE main.cpp -o baseline
```

この版は最初のターンに `-1` を出すだけです。

## ローカル検証結果

公式配布の seed 0〜99、公式 v2 tester、同一マシンで比較しました。すべて素のローカルスコアであり、順位表の正規化点ではありません。

| 版 | 合計 | 平均 | 最小 | 最大 | 100ケースwall time |
|---|---:|---:|---:|---:|---:|
| この `main.cpp` | 401785 | 4017.85 | 14 (seed 23) | 15317 (seed 70) | 35.56 s |
| 既存 `/home/utility/AHC054/main.cpp` | 398293 | 3982.93 | 14 (seed 23) | 15317 (seed 70) | 42.03 s |
| `SIMPLE_BASELINE` | 7097 | 70.97 | 5 (seed 39) | 873 (seed 40) | 1.94 s |

- 完成版 vs baseline: 100勝0分0敗、合計差 `+394688`
- 完成版 vs 既存候補: 11勝82分7敗、合計差 `+3492`
- 完成版・既存候補・baselineとも100ケースでtesterエラー、スコア0、欠測はありませんでした。
- strict compile: `-Wall -Wextra -Wshadow -Wconversion -Wpedantic -Werror` を通過しました。
- ASan + UBSan: seed 0, 16, 23, 70 で異常なしでした。sanitizer版は遅いためスコア自体は通常版と一致しない場合があります。

既存候補は合法で強い一方、1713行あり、strict compileでは3件の `-Wmisleading-indentation` が出ました。この版は考え方を小さな関数へ分け、同じコードからbaselineも作れるようにしています。

## 読み始める場所

初心者は、次の順に関数を読むと追いやすいです。

1. `main`: 入出力とターン処理
2. `choose_flower_fort`: 初手の要塞選び
3. `make_corridor_segment`: BFS通路と側壁
4. `choose_first_ray_blocks`: 初手の視線封鎖
5. `choose_ray_blocks`: 2手目以降の視線封鎖
6. `run_bfs`: 全ての安全判定の土台

調整しやすい値は、視線候補の距離 `6`、通常ターンの最大方向数 `2`、終了時刻 `1650.0` ms、初期要塞で許す切り離し量 `N*N/4` です。一度に複数を変えず、同じseed集合で比較するのがおすすめです。

## 参照した知見と残る不確実性

ローカル知識集は Knowledge map、AHC054 review全文、構造が近い AHC008・AHC046・AHC050 reviewだけを参照しました。そこから「通路・部屋・枝」「障害物による誘導」「BFSでの安全確認」という構造だけを取り出し、実装は独自に組み直しています。

知識集にある未確認事項もそのまま残しています。AHC054の代表スコア、AHC046/AHC050の記載スコアは未検証で、AHC008は候補ソースに曖昧さがあります。そのため、これらを性能の根拠にはせず、上表の公式tester実測だけを比較値にしています。
