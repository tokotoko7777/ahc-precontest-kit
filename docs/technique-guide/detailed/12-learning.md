## D235. モデルの格納と推論

学習済みの重みを小さい型で保存し、計算時に扱いやすい型へ戻すと、埋込みデータの容量を減らせます。

半精度で保存した配列を単精度へ変換して行列演算に使う例です。層の形と読取り位置を合わせ、重みを違う層へ割り当てないよう検査します。

<a id="example-36660262-05"></a>
### コードでの具体例：半精度で格納した重みを単精度へ戻してNumPyで推論する

base64のfloat16データをfloat32へ変換し、位置を順に進めて各層の重みへreshapeする。最後に長さ一致をassertする。

**適用条件・落とし穴。** 提出サイズや依存ライブラリを抑えた推論。学習方法の解説や重みの再利用権まで示すものではない。

**検算と練習。** 元モデルとの出力誤差、量子化前後の精度、起動時間を測る。

## D236. 量子化モデルの展開

小さい整数と尺度で重みを近似するのが量子化です。推論前に実数へ戻す方式もあります。

整数値−12、尺度0.01なら復元値は−0.12です。チャネルごとに尺度が違う場合、符号の扱いと対応する尺度の位置を正しく読む必要があります。

<a id="example-73562256-01"></a>
### コードでの具体例：int8重みと半精度のスケールをfloatへ復元する

圧縮バイト列を読み、出力チャネルごとのスケールを半精度から復元し、符号付き8bit値に掛けて推論用配列へ格納する。

**適用条件・落とし穴。** 提出サイズと実行時推論を両立する設計。学習方法や量子化後の精度は提出コードだけでは確認できない。

**検算と練習。** 既知の小重みで復号と推論の数値一致を確認する。

## D237. 相手ごとの特徴抽出

全体の状況と、対象ごとの特徴を別の枝で処理してから合わせます。可変の相手を共通処理へ通す設計です。

盤面の混雑度は全体枝、各相手の位置や得点は相手枝へ入れます。入力順を変えたときの挙動は、並べ方と集約方法に依存します。

<a id="example-73562256-03"></a>
### コードでの具体例：全体盤面の枝と相手別の枝を合わせて方策を出す

全体特徴の残差ネットと、各相手の特徴を共通処理する枝を合わせる。相手特徴のスロットはスコア順へ整える。

**適用条件・落とし穴。** 相手人数が変わる盤面推論向け。不在相手はゼロにするが、その学習上の意味は未確認。

**検算と練習。** 人数や相手番号の入替えに対する出力変化を調べる。

## D238. 合法手マスク

モデルが高い値を返した手でも、規則上できないなら選べません。選択対象を先に合法手へ限定します。

予測値が10,8,3で最初が違法なら、残る8を選びます。合法手が1つもない場合の動作も、モデルとは別に定義します。

<a id="example-73562256-04"></a>
### コードでの具体例：モデルの最大値選択を合法位置だけに制限する

合法位置を先にリスト化し、モデルが返す全盤面logitのうち合法位置だけargmaxする。

**適用条件・落とし穴。** 学習器にルール遵守を完全に任せない設計。合法候補ゼロの既定座標の扱いも確認する。

**検算と練習。** ランダムなlogitでも不合法手を返さないか検査する。

## D239. 解析評価への補正モデル

解析的な評価を全部置き換えず、そこで表せない誤差だけを学習器で補正する構成です。

基本の受付費用100に、混雑状態から予測した補正+15を足します。標準化の尺度や学習時の入力範囲が変わると、補正の意味も変わります。

<a id="example-78259988-04"></a>
### コードでの具体例：機会費用モデルに小ネットの補正額を足す

空き成分数・最大成分・稼働率・期間・料金比などを標準化して推論し、理想料金でスケールした補正を受付判断に加える。

**適用条件・落とし穴。** 手作りの評価を残したハイブリッド設計。埋め込み重みの学習データや汎化性能は不明。

**検算と練習。** 補正なしとの比較に加え、標準化範囲外の入力を試す。
