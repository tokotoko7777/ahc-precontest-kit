# 3. 差分更新と巻き戻し

[目次へ](README.md) · [前：焼きなましと温度](02-annealing.md) · [次：候補の管理](04-candidates.md)

同じ時間で多くの候補を試すには、1候補あたりの仕事を減らします。その中心になるのが、変わった部分だけ計算する差分更新と、試した変更を元に戻す巻き戻しです。

<a id="b11"></a>
## B11. 変わった項だけを計算する

評価値が多くの項の和になっていて、1回の変更が少数の項にしか影響しないなら、その項だけ再計算できます。

例えば各変数 `x[i]` が目標 `a[i]` からどれだけ離れているかを、`cost = Σ(x[i] - a[i])²` で測るとします。`x[j]` だけを `old` から `next` へ変えるなら、差分は `(next - a[j])² - (old - a[j])²` です。他の項は相殺されます。全評価が `O(N)` でも、この差分は `O(1)` です。

`a[j] = 5`、`old = 2`、`next = 4` なら、その項は9から1へ変わります。差分−8を元のコストに足せば、新しいコストになります。

**注意。** 他の変数との相互作用がある場合は、変更した変数の項だけでは足りません。`(x[i] - x[i+1])²` の和なら、`x[j]` の変更は左右の項に影響します。変更対象ではなく、影響を受ける評価項を列挙することが大切です。

**練習。** `cost = (x0 - x1)² + (x1 - x2)²` で、`x1` だけ変える差分式を書いてください。

**キットとの対応。** 差分式は問題固有です。キットは変更の記録と巻き戻しを提供します。

<a id="b12"></a>
## B12. 試行を1つの取引として扱う

候補を試す処理を「開始位置を記録する → 状態を変更する → 評価する → 採用か取消しを決める」というひとまとまりにします。これを取引、またはトランザクションと考えると、処理の境界が明確になります。

```cpp
RollbackArray<int> values({3, 4});
const int mark = values.snapshot();
values.set(0, 7);

if (accept_candidate) {
    // この例では外側に未確定の取引がない。
    values.clear_history();
} else {
    values.rollback(mark);
}
```

`snapshot()` は現在のログの長さを記録します。`set(index, value)` は添字と変更前の値を保存してから書き換えます。採用しないなら `rollback(mark)` で開始時点まで戻します。

**注意。** 状態本体だけ戻し、得点・個数・位置の逆引きなど補助データを戻し忘れると、次の評価から壊れます。何を変更する取引なのか、一覧を先に作ります。

**練習。** 2つの箱の荷物数を変更する操作について、箱の中身・各箱の重量・全体得点のどれを記録すべきか整理してください。

**キットとの対応。** [RollbackArray<T>](../../library/rollback-array.hpp) の `snapshot`、`set`、`rollback`、`clear_history`。

<a id="b13"></a>
## B13. 取り消しは変更の逆順に行う

同じ変数を1回の試行で何度も変更することがあります。例えば `x = 3` から7へ変え、さらに9へ変えたとします。ログには変更前の3と7が、この順番で入ります。

戻すときは後ろから使います。まず9を7へ戻し、次に7を3へ戻せば、試行前の状態になります。前から戻すと3に戻した後で7に書き換えてしまい、正しい状態になりません。

この性質により、入れ子の試行も扱えます。外側の試行を始めた後、内側の試行の開始位置を覚えておけば、内側だけ取り消して外側の変更を残せます。

**注意。** 内側の変更を採用しただけでログ全体を `clear_history()` すると、外側を取り消すための記録まで消えます。キットでは「これ以前に戻す必要がない」と確定した段階でログを捨てます。内側の採用時には記録を残す設計が必要です。

**練習。** `x = 3` から、外側で7へ、内側で9へ変えます。内側を採用した後に外側を取り消す場合、ログに何を残しておく必要があるか追ってください。

**キットとの対応。** `RollbackArray<T>` はログ末尾から復元します。

<a id="b14"></a>
## B14. ログに保存した対象の寿命を守る

巻き戻しログが「どの変数を戻すか」をアドレスで記録している場合、その変数の置き場所が変わると記録が無効になります。値が正しくても、書き戻す場所が間違えば壊れます。

例えば `vector` の要素をログに登録した後で `push_back` し、領域が再確保されたとします。古い要素のアドレスは使えません。ログがそこへ書き戻す動作は未定義になります。

対策には、取引中は容器の大きさを変えない、必要な容量を確保し再確保を起こさない、アドレスではなく添字を記録する専用ログを設計する、などがあります。ただし `reserve` しても、要素の削除・並べ替えや容器自体の破棄まで安全になるわけではありません。

**注意。** スコープを抜けたローカル変数、移動されたオブジェクト、別の型の補助データにも気を配ります。キットの `RollbackArray<T>` は同じ型の配列を扱います。複数の配列に状態を分けた場合は、各配列の開始位置を記録して取り消します。

**練習。** 固定長配列・要素追加するvector・関数内の一時変数の3つについて、どの条件ならログに登録したアドレスが使い続けられるか説明してください。

**キットとの対応。** [RollbackArray<T>](../../library/rollback-array.hpp) は配列を所有し、添字と古い値を保存します。上のアドレス型ログの注意は、自分でその方式を実装する場合に当てはまります。添字型でも、履歴がある間に要素を消したり並べ替えたりして添字の意味を変えてはいけません。

<a id="b15"></a>
## B15. 全再計算を正解判定器として残す

差分計算は速くても、1箇所の更新漏れで評価が少しずつずれます。そのずれを探索の途中で見つけるには、遅くても分かりやすい全再計算と比較します。

小さなランダム状態を作り、変更を試し、差分で得た評価と全再計算の評価を比べます。さらに変更を取り消し、状態と評価が試行前に戻ったことも検査します。「新しい評価が合う」と「戻せる」は別々の条件です。

整数評価なら完全一致で調べます。浮動小数点なら、値の大きさに応じた許容誤差を決めます。単に大きな誤差を許してテストを通すと、本当の更新漏れを隠します。

**注意。** 差分計算と全再計算が同じ間違ったヘルパーを共有していると、両方が同じ誤答を返すことがあります。検算側は速度を気にせず、できるだけ直接的に書きます。

**練習。** [B11](#b11)の二乗誤差について、10要素の配列を100回変更する検算を作ってください。採用する変更と取り消す変更を混ぜ、最初にずれた操作番号を記録します。

**キットとの対応。** 全評価と状態の一致判定は利用者が作ります。ログの動作例は [部品のテスト](../../tests/parts_test.cpp) にあります。
