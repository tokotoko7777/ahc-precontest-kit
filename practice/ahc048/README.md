# AHC048 練習用ソルバー

[AHC048 A - Mixing Colors](https://atcoder.jp/contests/ahc048/tasks/ahc048_a)
の、提出可能な単一 `main.cpp` です。kit内のheaderには依存しないため、そのままAtCoderへ
貼り付けられます。

## 問題を簡単に見る

1gの絵の具を入れると費用 `D` がかかり、要求色との差も失点になります。大切なのは次の2点です。

- 複数のtubeを混ぜれば色は正確になるが、余りを捨てると絵の具代が増える
- wellに前の絵の具を残せば、次の要求色へ再利用できる

このsolverは性格の異なる3案を入力上で計算し、公式絶対スコアの予測値が最小のものを出力します。
予測には実際に作る色を使うので、単純な基準解より悪い候補を無理に採用しません。

## 3つの作り方

### 1. 1色ずつ作り直す

ある要求色に対し、tubeを `q` 回注いで混ぜ、1gを渡して残り `q-1` gを捨てます。

`q=1,2,3` は小さな組合せを全列挙します。`q>=4` は1本追加した後、「選んだtube 1本を
別のtubeへ交換する」局所改善を行います。各要求について、色誤差の改善量と追加費用 `D` の
釣り合いがよい `q` を優先queueで選び、turn上限を守ります。

これは絵の具代が安い入力で強い方法です。

### 2. 連続する要求を1つのbatchにする

連続する `q` 個の要求へ同じ色を渡すなら、tubeを合計 `q` g注いで `q` 回取り出せます。
余りは0gなので追加費用がありません。

最大24個までの区間について、要求色の幾何medianに近い離散recipeを作ります。その後、
`dp[i] = i個目までの最小色誤差` という普通の区間DPで分け方を決めます。高い `D` でも
安全に使える候補です。

### 3. 複数の小さな絵の具溜めを再利用する

要求色をk-meansでいくつかの色群に分け、各中心に近い絵の具を小さなwellへ最初に用意します。
要求が来るたび、次の操作を全well・全tubeから選びます。

```text
wellに1g追加 -> 混ぜた色を1g渡す -> 残った色を次回へ引き継ぐ
```

wellの大きさは `2, 4, 5, 10, 20`、個数も複数試します。小さいwellは色を速く変えられ、
大きいwellは色を安定して保持できます。

さらに、現在の色が要求へ十分近いときはtubeを追加せず、wellから直接1g渡します。これは
最後に残る絵の具を1g減らし、公式スコアを `D` 改善します。早く減らしすぎると便利な色を
失うため、減らし方の慎重さを4通り比較します。

公式seed 0〜99では、この方法が97ケース、1色ずつ作る方法が3ケースで選ばれました。

## まず使う

```bash
g++ -std=c++17 -O2 -pipe main.cpp -o solver
./solver < in.txt > out.txt
```

比較用の最小版は、各要求へ最も近いtubeを1gだけ使います。

```bash
g++ -std=c++17 -O2 -DAHC048_BASELINE main.cpp -o baseline
```

公式toolsでは次のように合法性とscoreを確認できます。

```bash
cargo build --release --bin vis
./target/release/vis in/0000.txt out.txt
```

AHC048は絶対スコアが**小さいほど良い**問題です。

## 計算量と高速化

- 小さなrecipeは `unsigned short[20]` で保持
- 2g・3gだけ厳密列挙し、それより大きいrecipeは差し替え局所探索
- 色の比較では平方根が不要な箇所を二乗距離にする
- k-means中心はwell個数ごとに一度だけ作って再利用
- paletteは横長wellだけで表し、contest中にdividerを動かさない

最大recipe長は48、batch長は24という小さな定数です。読みやすさを保ちつつ、候補を全要求へ
十分試せる範囲にしています。
