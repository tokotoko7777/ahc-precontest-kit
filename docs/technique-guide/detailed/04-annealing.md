# 04. 焼きなまし・受理制御

[詳細編の目次](README.md) · [用語](GLOSSARY.md) · [出典一覧](SOURCES.md)

受理判定には温度の式だけでなく、乱数をいつ引くか、重い評価をどこまで実行するか、途中で目的を変えるかという設計があります。元の受理規則と同じ変形なのか、意図的な近似なのかを分けて考えます。

説明用の小例と、提出コードで確認した具体例を分けて記載しています。適用効果は未測定で、検算と練習はこれから確かめるための課題です。

## D095. 対数受理判定

悪化量dの受理条件は、乱数Uに対しd < −T log(U)とも書けます。右辺を「今回許す悪化量」として先に作れます。

対数値を表にすれば反復中の計算を減らせます。ただし表の離散化や対数の底に合わせ、温度の尺度も揃えます。

<a id="example-22075413-01"></a>
### コードでの具体例：log乱数を65536個だけ先に作る

区間中央の一様値のlogを表にして、得点差をT×log(U)と比較する。ループ中のexpとlogを避ける。

**適用条件・落とし穴。** 大量のMetropolis判定向け。離散化した乱数分布の精度に注意する。

**検算と練習。** 符号・最小乱数・温度0付近で通常のexp判定と採用率を比較する。

出典: [AHC002 / 提出 22075413](https://atcoder.jp/contests/ahc002/submissions/22075413) · `XorShift::nextLog / Solver::SA` · L33–L63, L369–L373。 [収録情報](SOURCES.md#submission-22075413)

<a id="example-51936966-06"></a>
### コードでの具体例：対数乱数の表から許容悪化量を渡す

4096個の-log2(U)を保存し、温度を掛けた許容差を近傍へ渡す。各近傍は新旧費用差が許容内かで判定する。

**適用条件・落とし穴。** 複数近傍で受理判定を共通化したい場合。自然対数との差は温度スケールに吸収される。

**検算と練習。** 表の再利用周期と受理率、直接乱数方式の比較を行う。

出典: [AHC031 / 提出 51936966](https://atcoder.jp/contests/ahc031/submissions/51936966) · `tolsBase / tolerance` · L4182–L4185, L4197–L4220, L3190–L3208。 [収録情報](SOURCES.md#submission-51936966)

## D096. 小確率受理の打切り

悪化が温度よりはるかに大きい場合、受理確率は非常に小さくなります。その領域を計算せず棄却する近似です。

d/T=8の受理確率は約0.000335です。0ではないため、打切りは元の焼きなましと完全に同じ挙動にはなりません。

<a id="example-27260278-06"></a>
### コードでの具体例：8温度を超える悪化ではexpを呼ばない

非改善のうちdeltaが8×温度以下の候補だけexpを評価する。

**適用条件・落とし穴。** ごく低確率の受理を近似的に切り捨てて計算を節約する。厳密なMetropolisとは異なる。

**検算と練習。** 打切り有無で速度と最終品質を比較する。

出典: [AHC006 / 提出 27260278](https://atcoder.jp/contests/ahc006/submissions/27260278) · `accepts` · L567–L568。 [収録情報](SOURCES.md#submission-27260278)

## D097. 安い受理判定の先行

安い情報だけで不採用と決まるなら、重い検査へ進む必要はありません。

受理乱数を先に引き、得点差だけで棄却されたら連結性のBFSを省きます。この順序変更が正しいのは、後の計算で受理判定に必要な得点差が変わらない場合です。

<a id="example-45917587-05"></a>
### コードでの具体例：空白数の差で棄却できる変更を連結性検査前に落とす

空白の増減から受理確率を計算し、棄却なら接触数更新やBFSを実行しない。

**適用条件・落とし穴。** 目的差分が安く制約検査が重い探索。合法候補であることが必要な最終採用判定は省略しない。

**検算と練習。** 先行判定の棄却率とBFS回数を測る。

出典: [AHC024 / 提出 45917587](https://atcoder.jp/contests/ahc024/submissions/45917587) · `move / move2` · L76–L82, L169–L173。 [収録情報](SOURCES.md#submission-45917587)

## D098. 受理確率の整数比較

確率を毎回実数で計算せず、乱数整数の範囲に対応する閾値へ変換します。

受理確率0.25なら、32ビット乱数の下位約4分の1を受理する閾値を用意します。確率1を2^32として格納する場合など、型の上限に注意します。

<a id="example-49255792-05"></a>
### コードでの具体例：整数の悪化量ごとに32bit乱数用の閾値を作る

温度更新時にexp(-delta/T)×2^32を前計算し、近傍ループでは乱数との比較だけにする。

**適用条件・落とし穴。** 悪化量の取り得る範囲が小さい整数目的。表の300要素を超える差が来ない根拠を別途確認する。

**検算と練習。** 最大悪化量の上界と表の添字、直接exp版との受理率を比較する。

出典: [AHC028 / 提出 49255792](https://atcoder.jp/contests/ahc028/submissions/49255792) · `probs / eval` · L933–L958。 [収録情報](SOURCES.md#submission-49255792)

## D099. 近傍比率の時間変化

序盤と終盤で試したい近傍の種類が違うなら、選択確率そのものを時間で変えます。

大きい変更を序盤70%、終盤10%へ減らす設計です。温度も同時に変えると効果が混ざるため、近傍比率だけを変えた比較も行います。

<a id="example-63121685-06"></a>
### コードでの具体例：温度だけでなく7種類の近傍選択重みも補間する

256反復ごとに時間進捗を読み、温度を指数補間、近傍重みを線形補間で更新する。

**適用条件・落とし穴。** 序盤と終盤で有効な変更規模が違う問題向け。重み値の効果はコードだけでは断定できない。

**検算と練習。** 近傍別の試行数・受理率・改善幅を時間帯別に測る。

出典: [AHC043 / 提出 63121685](https://atcoder.jp/contests/ahc043/submissions/63121685) · `Selector / params.trans0..6` · L7350–L7369。 [収録情報](SOURCES.md#submission-63121685)

## D100. 代理目的から本来目的へ

探索しやすい補助目的で形を作り、途中から本来の目的で仕上げる設計です。

序盤は偏りを減らす評価、後半は公式費用を使う場合、切替時に現在解を再評価します。別尺度の値をそのまま比較したり、代理目的の最良を最終解にしたりしません。

<a id="example-65957786-05"></a>
### コードでの具体例：重みを歪めた前半評価から後半評価へ切り替える

各再スタートの初期候補を代理目的で選び、時間の2/3で通常評価に切り替えて現在値を再計算。最良保存も通常評価に限定する。

**適用条件・落とし穴。** 目的関数を変えるときに異なる尺度のスコアを混ぜない設計。通常評価も出現確率近似である。

**検算と練習。** 切替なし・切替ありを同時間で比較する。

出典: [AHC047 / 提出 65957786](https://atcoder.jp/contests/ahc047/submissions/65957786) · `hevy / annealing` · L143–L144, L180–L219。 [収録情報](SOURCES.md#submission-65957786)

## D101. 補助罰則の減衰

序盤だけ構造を単純にする罰則を入れ、終盤にその重みを消して本来の目的へ近づけます。

残時間率rの二乗を重みにすると、r=0.5で罰則は初期の4分の1です。補助罰則を残したままの得点と公式得点は分けて記録します。

<a id="example-70299716-03"></a>
### コードでの具体例：辺数と弾数の罰則を進捗の二乗で消す

本来の攻撃回数差分に、残り時間率二乗を掛けた使用量・辺数の項を足す。

**適用条件・落とし穴。** 序盤に疎な依存関係を好み終盤に本来目的へ寄せる。係数の効果は別途測定する。

**検算と練習。** 補助項なし・固定・減衰の三条件を比較する。

出典: [AHC055 / 提出 70299716](https://atcoder.jp/contests/ahc055/submissions/70299716) · `score_delta / used_delta / edge_delta` · L346–L366。 [収録情報](SOURCES.md#submission-70299716)

## D102. 閾値付き途中評価

今回は費用がいくらまでなら受理できるかを先に決めると、途中計算がその上限を越えた時点でやめられます。

上限100で、今後増えるだけの累積費用が101になれば棄却できます。後で減少する項がある場合、そのまま打ち切ってはいけません。

<a id="example-71292882-02"></a>
### コードでの具体例：受理閾値を先に引き、部分評価に渡す

負の対数乱数で許容悪化量を先に決め、評価中の累積費用が残り余裕を超えたら打ち切る。

**適用条件・落とし穴。** 非負の残り費用に使える。ただしkrem×1000はコード上の追加見積もりで、厳密下界とは未確認。

**検算と練習。** 打切りなしと比較し、本来受理できた候補を落とす頻度を測る。

出典: [AHC057 / 提出 71292882](https://atcoder.jp/contests/ahc057/submissions/71292882) · `scth / EvalTmp` · L271–L275, L362–L389, L415–L427。 [収録情報](SOURCES.md#submission-71292882)

## D103. 温度の自動較正

温度を固定値で決めず、その入力で実際に発生する悪化量を基準にします。

悪化量の中央値が6なら、例えばその2倍の12を初期温度にする規則です。サンプル数が少ない場合や悪化候補がない場合の処理も決めておきます。

<a id="example-71725942-04"></a>
### コードでの具体例：悪化幅の中央値を初期温度の基準にする

初期解から50候補を試し、実行可能な悪化量の中央値を2倍して初期温度を決める。

**適用条件・落とし穴。** 入力ごとに目的値の尺度が変わる場合向け。標本がない場合は既定値を使う。

**検算と練習。** 受理率と得点を固定温度設定と比較する。

出典: [AHC058 / 提出 71725942](https://atcoder.jp/contests/ahc058/submissions/71725942) · `T0 / neg` · L570–L609。 [収録情報](SOURCES.md#submission-71725942)

## D104. 二項評価の計算順

合計費用を2つの副問題へ分けたとき、一方の下限が分かれば、もう一方へ使える上限を狭められます。

合計上限100でBが最低40なら、Aには60までしか使えません。この棄却を安全にするには、Bの値が本当に下限である必要があります。

<a id="example-79793411-04"></a>
### コードでの具体例：相方の下界を引いて先に評価する側の予算を決める

二グループの変更に対し許容増分を先に決め、相手の下界を差し引いたlimitで一方を評価する。キャッシュ再配置後のポインタも引き直す。

**適用条件・落とし穴。** 複数の高価な項を持つSA向け。下界の安全性とキャッシュの参照無効化を両方扱う。

**検算と練習。** 全評価版との受理一致、打切り数を測る。

出典: [AHC072 / 提出 79793411](https://atcoder.jp/contests/ahc072/submissions/79793411) · `moveDelta / rejectFrom / judge` · L1362–L1428。 [収録情報](SOURCES.md#submission-79793411)
