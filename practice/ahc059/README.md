# AHC059 — LNSでカードの回収順を作り直す

[公式問題](https://atcoder.jp/contests/ahc059/tasks/ahc059_a)。
`main.cpp`はライブラリを展開済みで、外部ファイルなしに1本で提出できます。
原本は[ahc059_lns.cpp](../../examples/search/ahc059_lns.cpp)です。
両者の一致をCIで検査します。

## 編集する場所

| 場所 | 書く内容 |
|---|---|
| `CardPairProblem::State` | カードを取る順番 `order` と、その移動距離 `cost` |
| `make_initial_state` | 空の順序にペアを1組ずつ入れて合法な初期解を作る |
| `destroy` | 区間に現れるペアを、相方も含めて取り除く |
| `repair` | 取り除いたペアを順に入れ直す。完成した**絶対距離**を返す |
| `best_insertion` | AHC059固有の高速な修復処理 |
| `main`の`LnsOptions` | 制限時間、最小化、受理方式、温度・許容幅を選ぶ |

`LargeNeighborhoodSearch`の中身は問題に合わせて編集しません。
別問題への穴埋め用は[large-neighborhood-search.cpp](../../template/search/large-neighborhood-search.cpp)です。

## 解法

盤面は20×20、カードは200ペア。すべて消した場合の得点は
`16400 - 移動回数`です。`Z`（取る）も操作数の上限には含まれますが、
得点からは引かれません。この解法では`X`（置く）は使いません。

回収順を括弧列として持ちます。`A B B A C C`のように、
同じペアが入れ子または互いに独立になっていれば、山札の上で必ず消えます。
`A B A B`のような交差は許しません。
旧practiceの「全ペアを1本の入れ子鎖にする」制約を外し、一般の括弧列を探索します。

1. 回収順から長さ15の区間を選ぶ。
2. その区間に現れるペアを2枚とも取り除く。残りは必ず合法。
3. 除いたペアをランダムな順に、距離増分が最小の合法位置へ入れ直す。
4. 山登り / RRT / SA の受理条件で候補を採用する。最後に最良解を出力する。

部分破壊・再構築とRRTの着想は
[hitonanodeさんの本番2位解説](https://atcoder.jp/contests/ahc059/editorial/15052)。
考え方から独自に実装し、第三者の提出コードは使用していません。

### 1ペアの再挿入がO(n)でできる理由

2枚を入れる隙間では、元の山札の中身が同じである必要があります。
有効な括弧列の各隙間を左から走査し、同じ山札状態ごとに
「1枚目をここまでのどこかへ入れる最小増分」を保持します。
2枚目を今の隙間へ入れる増分と足せば、その隙間を終点にした最良候補が分かります。
2枚の向きを両方調べます。同じ隙間にまとめて入れる場合だけ別の増分式を使います。

これは全ての隙間の組を調べるO(n²)の処理ではありません。
小さい盤面で全挿入位置・両方向を全探索し、高速版の最小値と一致することをテストします。

### 受理方式と打ち切り

既定はSA、開始温度8・終了温度0.25です。RRTへ切り替える場合の許容幅は2です。
距離を小さくする問題なので
`options.maximize=false`にし、`repair`は距離を正のまま返します。

- 山登り: 新しい距離 ≤ 現在の距離。
- RRT: 新しい距離 ≤ **過去最良の距離** + 許容幅。
- SA: 温度から抽選した悪化幅を現在の距離に足した閾値で採否を決める。

Manhattan距離では、カードを挿入しても経路の長さは減りません。
よって修復途中の距離が閾値を超えれば、それ以上修復せず`nullopt`を返せます。
「閾値と等しい」は採用されるため切りません。
修復順の抽選を打ち切り前に済ませ、ON/OFFで次回の乱数列が変わらないようにしています。

| コンパイル定義 | 既定 | 意味 |
|---|---:|---|
| `AHC059_LNS_MODE` | 2 | 0=山登り、1=RRT、2=SA |
| `AHC059_LNS_MARGIN` | 2 | RRTの悪化許容幅 |
| `AHC059_LNS_CUTOFF` | 1 | 閾値による修復途中打ち切り |
| `AHC059_LNS_PRECOMPUTE` | 1 | 距離表の前計算。打ち切りとは独立 |
| `AHC059_LNS_TIME_MS` | 1850 | 入力・初期解を含めた内部の時間枠 |
| `AHC059_LNS_SPAN` | 15 | 破壊対象を選ぶ区間長 |
| `AHC059_LNS_ITERATIONS` | 未指定 | 固定反復テスト用。実時間の採用判断には使わない |

## 合法性と得点の検証

各カードを1回ずつ回収し、移動は盤面内の縦横移動だけを出力します。
400枚への移動は最大400×38歩、回収は400操作なので、
合計は最大15,600操作で制限16,000以内です。

[ベンチマークスクリプト](../../benchmarks/lns_official_benchmark.py)は
公式Rust採点器と独立したPython再生の両方で採点します。
全生得点、実行時間、不正出力・時間超過、入出力・ソースのSHAを保存します。
旧解はcommit `8b79c5c30b5447a511bebeb2d55164bda8362887`から固定して比較します。

測定条件・比較表・採否は[LNS_REPORT.md](../../benchmarks/LNS_REPORT.md)を参照してください。
旧解からの差には**問題側の解の表現・近傍の変更**も含みます。
「共通ライブラリの高速化だけで得点が上がった」という比較ではありません。

## 本番上位者との比較の限界

解説では本番2位解法の再実装が2,300,629点、RRTへ変えた後日提出が
2,301,784点（記事では本番1位相当）と報告されています。
これは本番150ケースの総点です。こちらのローカル入力とは別なので、
平均点の大小から「1位超え」や正確な得点差を主張しません。
同一の本番入力による採点、またはAtCoderへの提出による比較は未実施です。
