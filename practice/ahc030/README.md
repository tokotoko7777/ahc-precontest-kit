# AHC030 - 平行移動候補を正確な掘削で絞る

## 考え方

油田の形と向きは分かっており、分からないのは平行移動量だけです。そこで、各油田について盤面内に収まる全配置を最初に列挙します。

この解法で最も大切な事実は、全セルの油量の合計が入力から分かることです。油田の重なりがあっても

```text
全セルの v(i,j) の合計 = 全油田の面積の合計
```

です。単点掘削にはノイズがありません。したがって、掘ったセルの `v(i,j)` の合計が既知の総面積に達したら、未掘削セルの油量はすべて0だと証明できます。

単純に全セルを掘るより早くこの状態へ到達するため、次の処理を繰り返します。

1. 各油田の残っている配置から、各セルを覆う確率を計算する。
2. 各油田を独立と近似し、そのセルで観測する油量0, 1, 2, ...の確率分布を畳み込みで作る。
3. 「期待油量 + 4 × 観測値のエントロピー」が大きいセルを掘る。
4. 正確な掘削結果と両立しない配置を削除する。

期待油量が大きいセルは、既知の総面積へ早く到達するのに役立ちます。エントロピーが大きいセルは複数の異なる結果が出やすく、配置候補を分けるのに役立ちます。

## 配置候補の安全な削除

セル `c` の掘削結果が `x` だったとします。ある油田の配置が `c` を覆うかどうかは0か1です。他の油田について

- 必ず `c` を覆う油田数
- `c` を覆う可能性がある油田数

を数えると、その配置を選んだ状態で合計を `x` にできるか判定できます。不可能な配置だけを削除し、全観測について変化がなくなるまで繰り返します。

油田が2個のときは、残った配置の全ペアも調べます。過去の全掘削結果を同時に満たすペアだけを残すため、セルごとの判定だけでは見つからない矛盾も除けます。

配置は最大400セルの `bitset` で保持しています。

## ノイズ付き集合占い

油田数が8個以上のケースだけ、最初に盤面を4象限へ分けて集合占いを行います。4回の合計費用はおよそ `8/N` と小さく、結果は次に掘る場所の弱い補助値としてだけ使います。

占い結果はノイズを含むため、配置の削除や最終回答の確定には一切使いません。推定が外れても掘る順番が少し変わるだけです。

## 正しく終了できる理由

最終回答は、次のいずれかを満たしたときだけ出します。

- 残る全配置候補から、全セルの油の有無が同じだと証明できた。
- 掘削済みセルの油量合計が全油田面積の合計に達した。

候補削除は各観測を満たせない配置だけを対象にするため、真の配置は残ります。2油田の全ペア判定も全観測との完全一致だけを使います。

後者では未掘削セルの油量合計が0なので、掘って油が見つかったセルだけを答えれば正解です。最悪でも全 `N^2` セルを単点掘削すれば必ずこの状態になります。集合占い4回と回答を加えても、`N>=10` なので操作上限 `2N^2` には十分収まります。

## 計算量

1油田あたりの配置候補数を `P`、正確な掘削数を `Q` とします。

- 配置列挙: `O(MPN^2 / 64)` 相当のbitset構築
- 1回の掘削候補評価: `O(N^2MP)`
- 制約伝播: おおよそ `O(QMP × 反復回数)`
- 油田2個の全ペア確認: `O(P^2Q)`

制約は `N<=20`、`M<=20` です。検証した最大寄りのケースでも3秒の制限内に収まりました。

## 使い方

```bash
g++ -std=c++20 -O2 -Wall -Wextra -Wshadow main.cpp -o main
```

AHC030は対話形式なので、通常のリダイレクトだけでは動きません。公式ローカルtesterでは次のように実行します。

```bash
cargo run -r --bin tester /absolute/path/to/main < in/0000.txt > out.txt
```

提出時は `main.cpp` だけで動き、外部ヘッダには依存しません。

- seed 0--9: 全ケース成功、全掘削基準に10勝0敗
- seed 0--99: 全100ケース成功、平均48,851,607.90、最小5,000,000、最大231,400,000
- seed 0--99の最大操作数: 236
- `N=20, M=19` のseed 19: 0.91秒
- `-Wall -Wextra -Wshadow -Wconversion -pedantic -Werror`: 警告なし
- ASan + UBSan: seed 0, 5, 19で異常なし

比較用オプションは次の通りです。通常の提出では指定しません。

- `AHC030_FULL_DRILL_BASELINE`: 全セルを行優先で掘る公式例型の基準解
- `AHC030_STATIC_ORDER`: 掘削結果による配置候補更新を止める
- `AHC030_NO_SURVEY`: 4象限の集合占いを使わない

参照した知識コーパスのAHC030レビューでは、配置仮説と情報利得による能動問い合わせが確認されています。この実装はその構造だけを参考にし、最終確定を正確な掘削と証明可能な候補集合へ限定した独自の簡易版です。
