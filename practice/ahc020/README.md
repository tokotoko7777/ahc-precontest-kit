# AHC020 practice

公式問題: [A - Broadcasting](https://atcoder.jp/contests/ahc020/tasks/ahc020_a)

`main.cpp` だけで提出できる、円による被覆とネットワーク接続を分けて考える練習例です。
外部の `.hpp` は参照せず、必要な処理を1ファイルへ直接置いています。

## 問題の要点

100個の放送局ごとに整数半径 `P[i]` を決め、全住民を少なくとも1局の円で覆います。
半径が正の局は、選んだケーブルを通して局0へ接続しなければ放送できません。

費用は次の2種類の和です。

- 放送費: `sum(P[i] * P[i])`
- ケーブル費: 使用する辺の重みの和

半径を小さくするだけでは局数が増えてケーブル費が上がるため、被覆と接続を一緒に比べる
必要があります。公式制限時間は2秒です。

## 解法

### 1. 半径候補を整数で前計算する

局と住民の距離の切り上げが、その局で住民を覆う最小の整数半径です。浮動小数の丸めだけに
頼らず、`ceil_square_root` が最後に整数の二乗で補正します。5000を超える組は候補から
外します。

各局について住民を必要半径順に並べます。半径は連続な0〜5000を全て試さず、この距離の
どれかだけを試せば十分です。

### 2. 重み付きset coverで放送半径を作る

まだ覆われていない住民を `new_count` 人増やせる半径拡大について、次の値が小さいものを
greedyに選びます。

```text
(半径二乗の増分 + 新しい局の接続予想費) / new_count
```

接続予想費には局0からの最短路長を使います。ただし実際のケーブルは複数局で共有できるため、
係数を `0, 0.03, ..., 2.0` と変えた8案を作ります。係数0は放送費重視、係数が大きい案は
少数の局へまとめる傾向になります。

比較用として、各住民を最寄り局へ担当させる単純案も必ず残します。

### 3. 重複している半径を縮める

各住民を何局が覆うか数えます。ある局だけが覆っている住民までの最大距離を残し、それより
外側の余分な半径を削ります。局を調べる順序で結果が変わるため、半径の降順・昇順・添字順・
固定hash順の4通りを比べます。

### 4. 有効局を安い木でつなぐ

Floyd–Warshallで全局間の最短路と復元情報を前計算します。有効局だけの距離完全グラフで
MSTを作り、選ばれた最短路を元の辺へ戻します。その辺集合からもう一度Kruskalで閉路を
除き、最後に放送しない葉を刈ります。

別案として「元グラフ全体のMSTから不要な葉を刈る木」も作り、ケーブル費が安い方を使います。
全候補は最後に本当の `半径二乗和 + 辺費` で比較します。

## 読む時の目印

- `ceil_square_root`: 距離を覆う最小整数半径
- `required_power`: 局×住民の必要半径表
- `clean_redundant_power`: cover countを使った半径縮小
- `make_network`: metric MST、経路復元、Kruskal、葉刈り
- `consider`: 4種類の縮小順と公式費用の比較
- `connection_weight`: 被覆費と接続予想費の配分

## 高速化

- 半径候補を住民距離だけへ離散化する
- 局×住民の必要半径を50万整数の表へ置く
- 全点対最短路は頂点数100なので、一度だけ `O(N^3)` で求める
- set coverでは半径が同じ住民をまとめて評価する
- 各候補のネットワークは最大100端点のKruskalだけで作る
- 時間乱択にせず、約0.1〜0.5秒で終わる決定的な複数案比較にする

## 参照した研究資料と弱点

一次情報として公式問題文、入力生成、公式Rust visualizerの被覆・接続・費用計算を確認しました。
ローカルknowledgeは構造検索後、AHC020 Reviewと、候補制限・Dijkstra・ネットワーク設計の
関連節だけを参照しています。被覆と接続を交互に考える構造だけを着想に使い、第三者コードは
転載していません。

- set coverはgreedyなので、複数局を同時に変えると良くなる組合せを逃します。
- 接続予想費は局0への単独最短路であり、ケーブル共有を正確には表しません。複数係数を
  最終費用で比べることで、このずれを緩和しています。
- metric MSTはSteiner treeの厳密解ではありません。
- さらに詰めるなら、1局を停止して住民を周辺局へ再配分するdestroy/repairと、そのたびの
  接続木再構築が次の候補です。
