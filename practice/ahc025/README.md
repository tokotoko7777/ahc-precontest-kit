# AHC025 practice

公式問題: [A - Balancing by Balance](https://atcoder.jp/contests/ahc025/tasks/ahc025_a)

数値が見えない品物を天秤の比較だけで学習し、合計重量が近い `D` グループへ分ける
対話型問題です。`main.cpp` はローカルヘッダを参照せず、そのまま提出できます。

## 問題の要点

- 品物数は `30 <= N <= 100`
- グループ数は `2 <= D <= N/4`
- 質問回数は `2N <= Q <= 32N`
- 1回の質問では、重ならない空でない2集合の合計重量を比較できる
- 質問はちょうど `Q` 回行う
- 各グループの合計を `t_i`、その分散を `V` とすると絶対得点は
  `1 + round(100 * sqrt(V))`。この値は低いほど良い

## 解法

### 1. 品物の軽い順を質問で推定する

質問に余裕があるケースでは、1要素対1要素の比較を使ったmerge sortで品物の順序を
正確に決めます。merge sortの最悪質問回数が、全質問数の75%以下ならこの方式を選びます。

質問が少ないケースでは、評価値が近く、まだ比べていない2品を優先して比較します。
答えでElo rating風の値を更新し、全品をその値で並べます。これは全順序を保証しませんが、
少ない質問を明らかに大小が離れた組へ何度も使わずに済みます。

### 2. 順位を重さの概算値へ変換する

公式generatorの重量は、上限で打ち切られた指数分布です。順位 `r` をその分布の
`(r+0.5)/N` 分位点へ変換し、各品物の概算重量にします。真の数値を当てるのではなく、
「上位の少数はかなり重い」という分布の形を初期分割へ反映するために使います。

### 3. 大きい品物から軽いグループへ入れる

概算重量の大きい順に、現在の概算合計が最小のグループへ入れます。これはLPTと呼ばれる
単純なgreedyです。同じ処理を `library/greedy-balanced-partition.hpp` に切り出しました。

### 4. 必ず改善する移動だけを天秤で証明する

重いグループの合計を `A`、軽い方を `B`、重い方にある品物を `x` とします。
まずグループ全体を比較して `A > B` を確認し、次に `A` から `x` を除いた集合と `B` を
比較します。

`A-x > B` なら `x < A-B` です。この時、移動前後の二乗和の差は

```text
A^2 + B^2 - ((A-x)^2 + (B+x)^2) = 2x(A-B-x) > 0
```

なので、`x` を重い方から軽い方へ移すと分散が必ず小さくなります。概算値は試す品物の
順番にしか使わず、採用の正しさは実際の天秤回答だけで決めます。

品物の大小順がmerge sortで確定している場合は、重い側の `x` と軽い側の `y` を交換する
候補も試します。`x > y` かつ `A-x > B-y` なら、同じ計算から交換も必ず改善します。

残った質問回数は、答えを無視する1要素同士の比較で埋め、必ずちょうど `Q` 回にします。

## 使い方

公式testerを間に挟んで実行します。

```bash
g++ -std=c++20 -O2 main.cpp -o solver
./tester ./solver < in/0000.txt > output.txt
```

提出環境では対話相手が標準入力を返すため、質問ごとの `endl` によるflushを削除しないで
ください。

## 段階比較

公式ローカルtesterのseed 0〜9を同じ環境で比較しました。

| 段階 | 平均絶対得点（低いほど良い） |
|---|---:|
| 順位推定＋LPTだけ | 5,685,400.5 |
| 保証付き移動・交換まで | **1,026,949.7** |

後処理で平均81.9%低下し、10ケース全てで初期分割を改善しました。

採用版を公式seed 0〜99へ通した結果は次のとおりです。

- 全100ケースでprotocol違反なし、ちょうど `Q` 回質問して完走
- 平均絶対得点: 2,393,906.98
- 最小絶対得点: 1,251
- 最大絶対得点: 12,301,026
- tester込みの最大観測wall time: 約0.05秒

`-Wall -Wextra -Wshadow -Wconversion -Werror` で警告なしです。ASanとUBSanを同時に
有効にしたseed 0と78も完走しました。

## 読む時の目印

- `ask`: 質問出力、flush、回答入力、質問回数の一元管理
- `merge_sort`: 質問に余裕がある時の正確な1要素比較
- `rating`: 質問が少ない時の軽量な順位推定
- `estimated_weight`: 打ち切り指数分布の分位点
- `groups`: LPTで作った現在のグループ
- `failed_move` / `failed_swap`: 同じ失敗候補を質問し直さない記録

## 弱点と発展

- 質問が少ない時のElo風順位は比較の推移律を明示的に使わないため、順序推定に改善余地が
  あります。
- 1回の改善判定にグループ比較と候補比較の2質問を使います。比較結果の半順序を保存して
  再利用すれば、同じ関係を尋ねずに済みます。
- 2品をまとめて移す候補も試しましたが、質問回数を大きい候補へ使い過ぎ、seed 0〜9では
  単品移動より悪化したため採用していません。
- 公式問題文とgeneratorを一次情報として確認し、ローカル研究資料は順位推定・複数仮説・
  集合比較による再分割の構造だけを参考にした独自実装です。第三者提出コードは転載して
  いません。
