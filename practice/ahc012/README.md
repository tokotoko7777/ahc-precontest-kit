# AHC012 practice

公式問題: [A - AtCoder 10th Anniversary](https://atcoder.jp/contests/ahc012/tasks/ahc012_a)

`main.cpp` だけで提出できる、点群を直線で分割する過去AHCの練習例です。

## 問題の要点

円内の苺を100本以下の無限直線で分けます。苺が1〜10個入ったpieceについて、各大きさの
需要個数まで得点になります。余分なpieceや11個以上のpieceがあっても失格ではありません。

自由な斜線を直接探索すると、1本の変更で多くの領域の形が変わります。この実装では直線を
平行な縦線・横線だけに限定し、「整列した境界座標列」の問題へ変えます。

## 解法

### 1. 格子の大きさを複数試す

需要piece数の0.95〜1.45倍を目安に、縦帯数×横帯数の候補を列挙します。各方向の初期境界は
苺座標の分位点に置くため、極端に苺が偏った細長い帯を作りにくくなります。円盤の角には
空cellができるので、需要より多い格子cellを持つ候補も比較します。

### 2. piece数を正確に数える

各苺について、`lower_bound` で縦帯・横帯を決めます。全cellの苺数を数え、1〜10個の
histogramを作れば公式の配布可能piece数が分かります。

探索値は公式の一致個数を最優先し、同点付近では不足・余剰の二乗値と累積histogram差も
使います。例えば4個pieceが余り、5個pieceが不足する状態を、全く離れた分布より直しやすい
候補として残すためです。

### 3. 境界列を焼きなます

次の2近傍を混ぜます。

- 1本の境界を隣の境界との間で少し、または大きく動かす
- 1本を削除し、別の順位へ挿入するrelocate

境界列は常にsort済み・重複なしなので、出力線数と格子の定義が壊れません。候補評価は
毎回全苺を数え直す単純な実装です。最大でも約5500点×100本の二分探索で、2秒内に十分な
反復数を確保できます。

## 半整数の切断線を整数2点で表す

苺座標は整数です。`x=c` を出すと同じx座標の苺を切って失いますが、線上の2点にも整数しか
使えません。そこで縦境界 `x=c+0.5` をほぼ表す次の線を出します。

```text
(c, -1000000000) -- (c+1, 1000000000)
```

cake内でのずれは高々0.000005なので、整数座標の苺を通らず、分類上は厳密に半整数境界と
同じです。横線も同様です。

## 読む時の目印

- `make_quantile_cuts`: 座標分位点による初期境界
- `evaluate_grid`: cell個数とhistogramの全再計算
- `move_one_cut`: 局所移動とrelocate
- `search_score`: 公式一致数を最優先した滑らかな代理値

## 公式ローカルツールでの確認

[公式ローカルツール](https://img.atcoder.jp/ahc012/f756367b32.zip)のseed 0〜9を
採点しました。

- 全10ケース合法、苺を切ったことによるエラー0件
- 平均得点: 939,958.4
- 最小得点: 876,588
- 最大得点: 971,554
- 分位格子だけの平均相当得点: 814,445.9
- 焼きなまし後は初期格子より平均約15.4%改善
- 通常版の実行時間: 1ケース約1.87秒

`-Wall -Wextra -Wshadow -pedantic` で警告なしです。ASan・UBSanを同時に有効化した
seed 0も完走し、遅いsanitizer実行の出力も公式ビジュアライザで合法でした。

## 注意

- 斜線が有効な配置を捨てる代わりに、評価と合法性をかなり単純にした解法です。
- 時間で探索を止めるため、CPU速度によって反復数と答えが変わる可能性があります。
- 研究資料の軸平行格子・histogram差分という知見を基にした独自C++実装で、第三者コードの
  転載ではありません。
