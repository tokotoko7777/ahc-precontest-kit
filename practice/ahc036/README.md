# AHC036 練習用ソルバー

[AHC036 A - Buildings](https://atcoder.jp/contests/ahc036/tasks/ahc036_a) の、
提出可能な単一 `main.cpp` です。ローカルの `.hpp` には依存しないため、ファイル全体を
そのままAtCoderへ貼り付けられます。

## 問題の見方

この問題では `m` の回数ではなく、信号操作 `s` の回数を減らします。そこで600都市を
最大 `L_B` 個ずつの連結なグループへ分け、各グループを `A` の連続区間へ置きます。

一度グループを `B` へコピーすれば、その中の都市はすべて青信号です。グループ内なら
信号を変えず何本でも道路を進めます。そのため各目的地への経路は、次の優先順位で
Dijkstra探索します。

1. またぐグループ境界の数を最小にする
2. 境界数が同じなら移動回数を最小にする

コードでは、グループが変わる辺へ十分大きな費用を足すだけです。

## 解法

### 1. 連結グループを何通りも作る

BFS木の根と子の処理順を変え、最大 `L_B` 都市の連結部分へ下からまとめます。さらに、
Hilbert順などで空間的に近い都市を優先しながら、実際の道路上で領域を成長させる候補も
作ります。Hilbert順だけで分割するのではないので、各グループの連結性は保たれます。

各候補をグループ単位のグラフへ縮約し、入力の目的地列を回る境界数を高速に見積もって、
最良候補だけを残します。

### 2. 経路と `A` を両方比較する

次の2本の経路を作ります。

- 信号回数を先に最小化する経路
- 通常の最短歩数経路

信号優先経路が少し遠回りしすぎるcaseでは、短い経路が勝つ可能性もあるためです。

経路上で頻繁に行き来するグループ対は、`A` 上でも隣り合うよう挿入greedyで並べます。
すると長さ `L_B` の信号区間が2グループの境界をまたぎ、両側の都市を同時に青信号へ
できます。

### 3. 次を最も長く歩けるwindowを選ぶ

次の都市が現在の `B` に無い時、その都市を含む `A` の全windowを調べます。その中から、
今後の経路を信号変更なしで最も長く進めるwindowを選びます。`B` 内の順番には意味がなく、
都市が含まれるかだけを見るのがポイントです。

最後に余った `L_A-N` マスへ、現在複数回の信号を必要とする経路断片を入れます。同じ都市
集合が何度も現れる場合はまとめて数え、再利用回数の多い断片から採用します。

## まず使う

```bash
g++ -std=c++20 -O2 -pipe main.cpp -o solver
./solver < in.txt > out.txt
```

`-DSIMPLE_BASELINE` を付けると比較用の単純解になります。`A[v]=v` として通常の最短路を
進み、1歩ごとに長さ1の信号を送ります。

```bash
g++ -std=c++20 -O2 -pipe -DSIMPLE_BASELINE main.cpp -o baseline
```

## 計算量

出力移動数を `R` とします。経路構築はおおむね `O(T M log N)`、単純に書いたwindow選択は
`O(R L_A L_B)` です。この問題では `N=T=600`, `L_A<=1200`, `L_B<=24` なので十分高速です。

公式seed 0〜99では次の結果でした。

- 全100出力が合法
- 平均: `7,317.11 -> 1,846.32`
- 最終版の範囲: `1,121`〜`3,264`
- baselineとの勝/分/敗: `100/0/0`
- 100ケース合計の信号削減率: `74.77%`
- 最大移動数: `10,732`、最大総操作数: `13,819`
- seed 73の実行時間: `0.09秒`、約 `4.3 MiB`

通常版とbaseline版はどちらも
`-Wall -Wextra -Wshadow -Wconversion -Werror` を通過しました。ASan+UBSanはseed 0, 37,
99で実行し、その出力を改めて公式visualizerへ通しています。
