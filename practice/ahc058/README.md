# AHC058 `Apple Incremental Game` 練習解

公式問題: [AHC058 A - Apple Incremental Game](https://atcoder.jp/contests/ahc058/tasks/ahc058_a)

`main.cpp` は、そのまま AtCoder へ提出できる C++17 の単一ファイルです。kit 内の
別ファイルを `#include` する必要はありません。乱数や時間打ち切りも使わないため、同じ
入力には常に同じ答えを出します。

## フォーマットの編集箇所

`main.cpp`は`DeterministicRolloutRunner`を展開済みです。`BEGIN LIBRARY`から
`END LIBRARY`までは共通処理なので通常は編集せず、`TODO(AHC058)`以降の
`Problem`を編集します。ヘッダ分離版は
[`ahc058_deterministic_rollout.cpp`](../../examples/search/ahc058_deterministic_rollout.cpp)です。

| 編集するもの | 書く内容・返す値 |
|---|---|
| `State / Action / Score` | 機械数・power・りんご・残り時間 / 最初の1手 / `__int128`の将来値 |
| `generate_actions` | 現在資金で可能な強化と待機の一覧 |
| `advance` | 指定した1手を反映し、公式の順番で生産を1ターン進める |
| `second_actions` | 2手目をどの候補に絞るか |
| `evaluate_action` | 指定した最初の1手から先読みした、最終りんご数の見積り |

候補の比較・同点時の選択・評価値bufferの再利用はRunnerが担当します。
状態は固定長配列なので、先読み時の状態コピーで動的メモリ確保を行いません。
これは使い方と実装コストの更新で、探索深さを増やす変更ではありません。

## 問題を短く言うと

- IDが10種類、Levelが4種類ある。
- `P[i][j]` を1上げるには `C[i][j] * (P[i][j]+1)` 個のりんごが必要。
- Level 0 はりんごを作り、Level 1以上は1つ下のLevelの機械数を増やす。
- 500ターンの各ターンで、強化を1回するか何もしない。
- 最後のりんご数 `S` を大きくする。得点は `round(100000*log2(S))`。

強化には「今りんごを減らすが、残り全ターンの生産を増やす」という投資の性質が
あります。安いものだけを見るのでも、最後の1ターンだけを見るのでも不十分です。

## 解法

### 1. 公式ルールどおりの状態を持つ

現在のりんご数、各機械の個数 `B[i][j]`、各機械のパワー `P[i][j]` を持ちます。
候補の強化代が現在のりんご数以下であることを確認してから、公式と同じ順で1ターンを
進めます。

個数や将来価値の掛け算には `__int128` を使います。候補比較用の将来価値だけは
`2^120` で打ち切り、極端な仮候補を計算してもオーバーフローしないようにしています。

### 2. 「今後もう強化しない場合」を式で一度に計算する

残りターン数を `r` とします。あるIDについて、Level 0 の機械数を各ターン分足した値は
次の式になります。

```text
r * B0
+ C(r,2) * P1 * B1
+ C(r,3) * P1 * P2 * B2
+ C(r,4) * P1 * P2 * P3 * B3
```

したがって、このIDが残り `r` ターンで作るりんご数は、上の値に `A[j]*P0` を掛ければ
求まります。500ターンを毎回最後までシミュレーションせず、`O(Level数)` で将来価値を
比較できます。

### 3. 3手だけ先読みし、最初の1手だけ採用する

各ターンで次を行います。

1. 今できる40種類の強化と「何もしない」をすべて試す。
2. 2手目は、将来のりんご増分が大きい上位12候補を残す。
3. Level固有の長期投資を捨てないよう、各Levelで最良の候補も必ず残す。
4. 3手目は、残った各状態から最良の強化を式で選ぶ。
5. 3手後から終了までは「もう強化しない」と仮定して最終りんご数を比較する。
6. 最良だった計画の最初の1手だけを実行し、次ターンにもう一度考え直す。

短い先読みを毎ターンやり直す方法は、ローリングホライズンやreceding horizonと呼ばれ
ます。「何もしない」も候補なので、資金が貯まるまで待つ判断もできます。

2手目を全40種類にすると少し得点が伸びるケースもありますが、手元では2秒を超える
ケースがありました。上位候補と各Level代表へ絞ることで、階層投資を残しながら十分な
速度余裕を確保しています。

## なぜ出力が合法か

- 候補を進める前に、必ず `apples >= cost` を確認する。
- 実際に採用するのは、その合法な候補の1手目だけ。
- LevelとIDは列挙した `0 <= level < L`, `0 <= id < N` だけ。
- 外側のループをちょうど `T` 回回し、毎回1行出力する。

先読み中の高評価だけを信じて、所持りんごを超える強化を出力することはありません。

## 計算量

機械種類数を `M=N*L`、2手目の候補数を `W` とすると、おおよそ
`O(T*M*W*M*L)` です。このコードでは `M=40`, `W<=17`, `L=4` です。メモリ使用量は
各Level・IDの状態と候補状態だけで小さいです。

## 以前のファイルを流用しなかった理由

`/home/utility/AHC058` に置かれていた `main.cpp` とローカルツールは、入力が
`N T M K L` で始まるトーラス上の移動体マージ問題用でした。AHC058公式入力は
`N L T K` と `A,C` であり、別問題です。旧 `main.cpp` は正しい公式seed 0を読ませると
`vector::reserve` の例外で停止したため、この練習解は公式仕様から新規に作りました。

## この解から再利用できる部分

- 長い線形な状態遷移を二項係数でまとめる方法。
- 「候補を仮適用 → 数手読む → 最初の1手だけ採用」というローリングホライズン。
- 上位候補に加え、カテゴリごとの代表も残す候補削減。
- 候補シミュレーションと実際の状態更新に同じ関数を使う設計。
- 大きな将来値を飽和演算で安全に比較する方法。

さらに改良するなら、全500手の行動列を持ち、変更位置より前の状態をprefixとして保存し、
変更位置以降のsuffixだけを再シミュレーションする局所探索が候補です。これは強力ですが、
まずはこの短い先読み版で状態遷移と投資価値の式を理解するのがおすすめです。
