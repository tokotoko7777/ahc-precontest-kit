# AHC024 - 隣接関係を壊さない地図の侵食

## 方針

入力の地図は必ず合法なので、そこから **合法な 1 マス変更だけ**を繰り返します。
変更は次の 2 種類です。

1. 外側の `0` と接しているマスを `0` にして、得点を 1 増やす。
2. マスを隣の色へ塗り替え、同点のまま次の削除をしやすい形へ整える。

各変更前に、次の条件を確認します。

- 元の色が 1 マスもなくならない。
- 元の色から変更マスを除いても連結である。
- 新しい色は変更マスの隣にあり、追加後も連結である。
- 元の地図にない色ペアの接触を作らない。
- 元の地図にある色ペアの最後の接触を消さない。

色ペアごとの「接している辺の本数」を持つと、最後の 2 条件は変更マスの上下左右だけで判定できます。
連結性は、変更マスと同色の隣接マスが、そのマスを避けても互いに到達できるかを小さな DFS で調べます。

## 同点変更の選び方

元の地図で外周と接していない色は、`0` と接してはいけないため直接削除できません。
そこで、次の値が良くなる塗り替えを優先し、少しだけ焼きなましで悪化も許します。

- 外周と接していない色のマス数を減らす。
- 異なる色同士の境界辺を減らし、領域をコンパクトにする。

一定回数の塗り替えごとに、削除可能なマスを全て削ります。180 ms ごとに入力からやり直す多点スタートにし、得点が最大だった盤面を保存します。

## 合法になる理由

- 状態は合法な入力盤面から始まる。
- 色ペアの接触辺数を変更前後で差分計算し、必要な接触の消失と不要な接触の発生を拒否する。
- 元の色については、変更マスが関節点でないことを DFS で確認する。
- 新しい色は必ず隣接色を選ぶため、塗り足しても連結である。
- `0` への変更は外側または既存の `0` に接するマスだけなので、`0` も外側へつながる。

したがって、受理した変更の後も全条件を満たします。探索中は `0` を色付きマスへ戻さないため、各再スタート内の公式得点も単調に増えます。

## 使い方

```bash
g++ -std=c++20 -O2 -pipe -Wall -Wextra -Wshadow main.cpp -o main
./main < input.txt > output.txt
```

提出時は `main.cpp` だけで動き、ローカルヘッダには依存しません。

短い合法性テストでは探索時間を 70 ms にできます。

```bash
g++ -std=c++20 -O2 -DLOCAL_SHORT_TIME main.cpp -o main-short
```

外周から削除するだけの基準解は `-DAHC024_ERASE_ONLY` で作れます。

## 計算量

- 色ペアの接触判定: 1 変更につき `O(1)`
- 連結判定: 変更元の色領域のマス数を `S` として最悪 `O(S)`
- 探索全体: 1.85 秒で打ち切る時間制御
- 使用メモリ: `O(n^2 + m^2)`

## 公式ツールでの検証

公式ローカルツールの seed 0--9 を同じ入力集合で比較しました。

| 方法 | 平均点 | 最小 | 最大 |
|---|---:|---:|---:|
| 入力をそのまま出力 | 1.0 | 1 | 1 |
| 外周侵食だけ | 621.2 | 547 | 695 |
| 塗り替え + 再侵食 + 多点探索 | **1839.5** | 1676 | 1954 |

完成版の seed 0--9 の点数は
`1950, 1829, 1762, 1676, 1814, 1954, 1861, 1881, 1773, 1895`
でした。外周侵食だけに対して全 10 ケースで勝ち、平均は約 2.96 倍です。

- 通常版: seed 0--9 が全て合法、典型 wall time 1.85 秒、最大常駐メモリ約 3.9 MiB
- 70 ms 版: seed 0--99 が全て合法、平均 1848.98 点、範囲 1644--2002
- `-Wall -Wextra -Wshadow -Wconversion -pedantic`: 警告なし
- AddressSanitizer + UndefinedBehaviorSanitizer: seed 0, 73 で指摘なし

70 ms 版の平均は別の 100 ケース集合に対する値なので、通常版の seed 0--9 平均との直接比較には使っていません。
