# AHC057 - Moving Points を固定サイズの分子へまとめる

外部ヘッダーを使わない、提出可能な単一 `main.cpp` です。複雑な逐次合流を直接扱う前に、合法性が分かりやすい「1グループを同じ時刻にまとめて結ぶ」形へ問題を簡略化しています。

## 問題を短く言うと

- 10万×10万のトーラス上に300個の点がある
- 各点は初期位置と速度を持ち、1000ターン動く
- 異なる連結成分の2点を好きな時刻に結合できる
- 結合すると成分速度は運動量保存則による加重平均になる
- 最後に、30点ずつの連結成分をちょうど10個作る
- 結んだ時のトーラス距離合計が小さいほど高得点

必ず `N-M=290` 本の結合を出力します。

## まず使える単純baseline

点番号を30個ずつ区切り、時刻0に各グループの先頭へ残り29点を結びます。

```text
グループ0: 0 と 1,2,...,29 を結ぶ
グループ1: 30 と 31,32,...,59 を結ぶ
...
```

これは常に「30点×10成分」になるため合法です。次のコンパイルでbaselineだけを出力できます。

```bash
g++ -std=c++17 -O2 -DSIMPLE_BASELINE main.cpp -o baseline
./baseline < input.txt > baseline.txt
```

## 解法の中心: 1グループを同時刻に結ぶ

同じグループの30点を時刻 `t` まで結合せず、時刻 `t` に木の29辺を全て結ぶことにします。

時刻 `t` までは各点が単独なので、その位置は正確に次で求まります。

```text
x(t) = (x(0) + vx * t) mod L
y(t) = (y(0) + vy * t) mod L
```

同一時刻内では結合によって位置が変わりません。29辺が木なら処理順が変わっても閉路にならず、最後は必ず1成分です。したがって、結合後の複雑な速度変化を追わずに、合法な解を作れます。

グループごとに別の時刻を選んでも、グループ同士は交わらないため問題ありません。

## 手順1: 全時刻の位置を前計算

`T*N = 1000*300` 個の位置を整数で保存します。結合前の位置なので、入力が整数なら常に整数です。

トーラス距離では、各軸の差を次の短い方へ直します。

```text
dx = min(abs(x1-x2), L-abs(x1-x2))
dy = min(abs(y1-y2), L-abs(y1-y2))
```

## 手順2: 30点ずつの空間クラスタを作る

時刻を50刻みで試し、各時刻で2種類の初期中心から固定サイズクラスタを作ります。

1. 最初の中心を1点選ぶ
2. 既存中心から最も遠い点を次の中心にして、10中心を得る
3. 各中心の容量を30に固定して点を割り当てる
4. 各群の中心をmedoidへ更新する
5. 割当とmedoid更新を3回繰り返す

容量付き割当では、各点について「一番近い空き中心」と「二番目に近い空き中心」を求めます。その距離差が大きい点から割り当てると、代替中心がない点を後回しにしにくくなります。

この時点で全グループは必ず30点です。

## 手順3: 各グループの最良時刻とMST

クラスタ候補の上位6個について、各グループを独立に評価します。

- まず時刻を10刻みで全探索
- 最良だった時刻の前後を1刻みで再探索
- その時刻の30点にPrim法でMSTを作る

MSTは、同じ30点を1成分へする木の中で結合距離合計が最小です。公式と同じ `round(sqrt(dx*dx+dy*dy))` を辺重みにしています。

## 手順4: グループ間swap

2グループから1点ずつ選んで交換すれば、各グループ30点という制約を壊しません。

```text
group A の1点 ↔ group B の1点
```

変更した2群のMSTだけを再計算し、焼きなましで改善します。その後、各群の結合時刻をもう一度探索します。この「swap → 時刻再最適化」を乱数列を変えて2ラウンド行います。

最良解は常に別に保存するため、悪化遷移を一時的に受理しても出力は悪化しません。

## 合法性が保たれる理由

- 最初のクラスタ割当で、300点を重複なく30点×10群へ分割
- swapは異なる2群の点交換なのでサイズ不変
- 各群では30頂点のMST 29辺だけを出力
- グループ同士は頂点を共有しない
- 時刻は必ず0〜999

よって全体は `10*29=290` 結合で、最終的に30点の成分が10個になります。

```bash

./main < input.txt > output.txt
```

公式ローカルvisualizerでは次で確認できます。

```bash
cargo run -r --bin vis input.txt output.txt
```

## 計算量

`N=300, M=10, K=30, T=1000` を使うと、主な部分は次の通りです。

- 位置前計算: `O(TN)`
- 容量付きクラスタ1回: 素朴実装で `O(N^2 M)`
- 1群のMST: `O(K^2)`
- swap 1回: 変更した2群だけなので `O(K^2)`

定数を含めても、代表5ケースで0.89〜0.92秒でした。

## 知識集をどう使ったか

参照範囲はKnowledge map、AHC057全文、構造的に近いAHC045・AHC037・AHC060レビューだけです。

- 公式に確認した事実: トーラス運動、結合時の速度更新、出力条件、距離と得点式、公式scorerの同時刻処理
- AHC057レビューの確認済み構造: 群所属・結合時刻を持ち、群間swapと時刻変更を探索する。ただし代表提出のスコアは未照合
- AHC045からの移植観点: 固定サイズの空間グループと、その内部の低コスト木
- AHC037からの移植観点: 幾何点を木で共有接続し、変更部分だけ再評価する
- AHC060からの移植観点: 細かな状態遷移より重要イベント時刻を探索対象にする
- この実装独自の簡略化: 1群の全MST辺を同時刻に置き、合流後速度の逐次シミュレーションを不要にする

第三者提出コードはコピーしていません。各レビューの構造的な着眼から独立実装しました。

## 最初に調整するなら

- `time_step = 50`: 初期クラスタを作る時刻間隔
- `finalist_count = 6`: 時刻を細かく調べるクラスタ候補数
- `coarse_step = 10`: グループ時刻探索の粗い間隔
- `iterations = 30000`: 1ラウンドのswap回数
- `round < 2`: swapと時刻再最適化のラウンド数

制限時間への影響が分かりやすいのは `iterations` とラウンド数です。まずこの2つから変更してください。
