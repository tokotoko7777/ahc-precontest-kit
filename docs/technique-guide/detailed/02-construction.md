# 02. 初期解・構築

[詳細編の目次](README.md) · [用語](GLOSSARY.md) · [出典一覧](SOURCES.md)

初期解は探索の出発点です。ランダムに作るだけでなく、制約の厳しい要素を先に置き、まとまりや対称性を使い、最後の不整合を小さな修復で直します。構築を何度もやり直せる速さも考えます。

説明用の小例と、提出コードで確認した具体例を分けて記載しています。適用効果は未測定で、検算と練習はこれから確かめるための課題です。

## D036. ランダム化された探索順序

同じ優先度の候補を常に同じ順で選ぶと、初期解が似通います。優先度へ小さな揺らぎを加え、基本方針を保ちながら別の道を試します。

距離の評価差が大きい候補まで逆転させたいのか、同点だけ崩したいのかで、乱数の大きさを変えます。

<a id="example-22075413-06"></a>
### コードでの具体例：中心距離と微小乱数で初期DFSの分岐順を変える

中心距離を優先度に入れ、300回の各DFSで微小な乱数によって同順位の探索順を変える。

**適用条件・落とし穴。** 構築用の方向性を残したまま複数の初期解を作る。

**検算と練習。** 乱数のみ・距離のみ・組合せを同じ展開数で比較する。

## D037. 包含による縮約

大きな要求を満たすと小さな要求も満たされるなら、小さい側を独立に処理する必要がないことがあります。

例えば文字列ABCを置けば、部分文字列BCも現れます。ただし必要な出現回数や重複の数え方が違う場合は、要求を消すだけでは足りません。

<a id="example-23751222-01"></a>
### コードでの具体例：長い文字列に含まれる要求をまとめる

長い順に処理し、既存文字列の部分文字列なら要求数だけ加算する。

**適用条件・落とし穴。** 包含関係のある被覆要求を重み付き代表へ縮約する。

**検算と練習。** 縮約前後の充足要求数が一致するか確認する。

## D039. 乱択最短路

最短路計算の辺費用を少し変えると、毎回同じ経路になることを避けられます。

長さが同じ経路AとBがあるとき、辺へ乱数費用を足すと別の経路が選ばれます。最短なのは揺らした費用に対してであり、元の距離の最短路とは限りません。

<a id="example-30423648-01"></a>
### コードでの具体例：辺費用をランダム化して複数の基礎経路を作る

緩和時に10〜30の乱数を費用へ足し、seedを変えて異なる開始点・目標間の経路を生成する。

**適用条件・落とし穴。** 初期解の多様化のための近道。固定辺重みの最短路保証とは区別する。

**検算と練習。** 得られた経路の隣接・通行可能性と多様性を確認する。

## D040. 失敗率に応じた冗長化

操作が確率的に失敗するなら、同じ操作を余分に実行して成功回数を補う発想があります。

成功率0.8で10回成功させたい場合、期待回数の目安は10/0.8=12.5回です。これは期待値の見積もりで、必ず10回成功する保証でも、余分な成功が無害という保証でもありません。

<a id="example-30423648-02"></a>
### コードでの具体例：経路長を成功確率で割ってコマンドを重複させる

基礎列長/(1-p)から追加回数を決め、選んだ位置の同じ移動を繰り返す。

**適用条件・落とし穴。** 独立な操作失敗がある初期解の作り方。壁での待機などの効果は正確な評価へ渡す。

**検算と練習。** p=0と大きいpで長さ制限と到達率を調べる。

出典: [AHC009 / 提出 30423648](https://atcoder.jp/contests/ahc009/submissions/30423648) · `random_dup` · L219–L243。 [収録情報](SOURCES.md#submission-30423648)

同じ種類の2枚を交換して可解性だけ変えられるなら、追加距離が1の交換を、追加距離8の交換より優先します。

<a id="example-32267675-04"></a>

**適用条件・落とし穴。** スライドの偶奇制約など、同種要素の交換で不変量を直せる場合に使う。

**検算と練習。** 修復後の可解性と、見た目の目標配置が不変なことを確認する。

## D042. 構築順序の変更

構築で同じ処理を使っていても、どの操作を先に許すかで結果が変わります。

まず小さな直接接続を作り、後から中継を含む併合を許すと、初期段階で大きな決定に固定されるのを避けられます。段階を分けた効果は、最終形と作業費用で比較します。

<a id="example-34095240-05"></a>
### コードでの具体例：最初の成分拡張では併合を待つ

isFirstを受け取り、初回にはMergeClusterを呼ばず、後続の探索では呼ぶ。初期の直結成分を優先してから中継併合を行う順序差である。

**適用条件・落とし穴。** 接続資源の早取りを抑えたい場合の仮説。改善効果は提出間の得点だけでは確定しない。

**検算と練習。** 同一seedで初回併合の有無だけを変え、接続先と最終得点を比べる。

出典: [AHC013 / 提出 34095240](https://atcoder.jp/contests/ahc013/submissions/34095240) · `ConnectBFS(isFirst)` · L2460–L2475, L2557–L2566。 [収録情報](SOURCES.md#submission-34095240)

## D046. 限界費用による貪欲

新しい要求を担当させるとき、総費用ではなく、その要求を追加したことで増える費用を比較します。

半径3を4へ広げる二乗費用の増分は16−9=7です。すでに半径5で覆っている施設なら増分0です。現状を再利用できる候補を正しく評価できます。

<a id="example-42196314-02"></a>
### コードでの具体例：未被覆顧客を半径二乗の増分が最小の局へ割り当てる

距離順に局を見てmax(必要半径²−現半径²,0)を比較し、費用0なら打ち切る。顧客順を乱択して複数回試す。

**適用条件・落とし穴。** 凸な施設容量費用を持つ被覆。距離が近い局と追加費用が安い局は一致しない。

**検算と練習。** 各顧客の被覆と最終半径費用を検算し、乱択回数を比較する。

## D048. 固定点つき平滑化

固定した値を境界条件にして、自由な値を周囲の平均へ寄せると、局所的な差を滑らかにできます。

左右が0と10の自由点なら、平均5が両側との二乗差を小さくします。識別に必要な固定点まで動かすと、本来残すべき信号も消えてしまいます。

<a id="example-44783436-01"></a>
### コードでの具体例：識別に使う温度を固定して残りを4近傍平均へ寄せる

固定された識別点を動かさず、周囲の温度を繰り返し平均化して隣接差二乗の設置費用を抑える。

**適用条件・落とし穴。** 境界条件を保った格子上の二乗平滑化。整数丸めと固定回数反復なので連続問題の厳密解とは限らない。

**検算と練習。** 反復ごとの実設置費用と、固定点が変わっていないことを確認する。
