# AHC006 practice

公式問題: [A - Food Delivery](https://atcoder.jp/contests/ahc006/tasks/ahc006_a)

`main.cpp` だけで提出できる、過去AHCを使ったライブラリ実戦例です。

## 使用したパーツ

- `TimeBasedAnnealingRunner`: 時間・温度・採否・最良解の保存
- `route-utils.hpp`: 移動・交換・反転・削除の辺差分
- `ordered-pair-insertion.hpp`: 先行制約付き2点の最良挿入位置をO(n)で探索

パーツはローカルヘッダとして参照せず、`main.cpp` の上部へ直接貼っています。

## 独自解法

単独で往復した時の距離が短い50注文を選び、pickupをdeliveryより前に置く制約を
守りながら、各注文を経路の最良2位置へ挿入して初期解を作ります。

その後、次の4近傍を焼きなまします。

- pickupまたはdeliveryを、先行制約を守れる位置へ移動
- 2イベントのswap
- 区間reverse
- 選択中1注文と未選択1注文の交換＋最良位置への再挿入

イベントは`2*order`がpickup、`2*order+1`がdelivery。
`State.position[event]`で現在位置をO(1)取得し、変わる先行制約だけ検査します。
候補経路をコピー・全再計算せず、`Move`に変更位置と距離差分だけを持ちます。
採用時だけ経路と逆引き位置を更新して`cost += delta`。
最小化なので`evaluate_move`は`-delta`（正なら改善）を返します。
不採用なら状態を変更していないのでundoは不要です。

移動・交換の評価はO(1)、反転は境界2辺の評価と区間内の制約検査。
注文入替では2点を除いた仮想経路を読み、O(n)で最良挿入位置を探します。
交換以外の採用時には、変更区間の並べ替え・位置cache更新のO(k)/O(n)処理が残ります。

距離表は既定ON（約8MB）。`-DAHC006_PRECOMPUTE_DISTANCE=0`でOFFにできます。
入力・距離表・初期解を含めた1850ms枠で探索し、公式2秒制限に余裕を持たせています。
時間内動作を保証するものではないので、提出環境でも確認してください。

## この練習で追加した汎用パーツ

点の型や距離関数を固定しない移動・交換差分と、線形の2点挿入を追加しました。
このソルバ固有の選択注文・先行制約はhppへ混ぜず、`DeliveryProblem`内に置いています。
編集箇所の説明付き原本は[`examples/search/ahc006_sa.cpp`](../../examples/search/ahc006_sa.cpp)。
`main.cpp`と原本＋hppが一致することをCIで検査します。
