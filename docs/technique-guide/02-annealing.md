# 2. 焼きなましと温度

[目次へ](README.md) · [前：探索の組み立て方](01-search.md) · [次：差分更新と巻き戻し](03-incremental.md)

焼きなましは、改善する変更を受け入れながら、悪化する変更も確率的に受け入れる探索です。目的は、今いる場所の近くでは一度悪化しないと先へ進めない状況を抜けることです。

<a id="b06"></a>
## B06. 悪化を確率で受理する

最大化問題で、候補得点から現在得点を引いた値を `Δ` とします。`Δ ≥ 0` なら改善または同点なので受理します。`Δ < 0` のときは、温度 `T > 0` に対して `exp(Δ / T)` の確率で受理します。

例えば現在100点、候補98点なら `Δ = -2` です。温度2では受理確率は `exp(-1) ≈ 0.368`、温度0.5では `exp(-4) ≈ 0.018` になります。高温では悪化を許しやすく、低温では改善を優先する動きになります。

温度は「得点差をどれくらい重く見るか」を決める量です。1点の差が小さい問題と、1点の差が大きい問題で、同じ温度を使っても同じ動きにはなりません。

**注意。** 最小化では差分の向きを間違えやすくなります。コストが `20 → 23` なら悪化量は3です。キットの `SimulatedAnnealing::accept` は改善量を受け取るので、最小化では現在コスト−候補コスト、ここでは−3を渡します。

**練習。** 得点差−5、温度5の場合と温度1の場合の受理確率を求め、高温側で何倍ほど受理されやすいか比べてください。

**キットとの対応。** [SimulatedAnnealing::accept(improvement)](../../library/simulated-annealing.hpp)。最大化では新得点−現在得点、最小化では現在コスト−新コストを渡します。

<a id="b07"></a>
## B07. 温度を得点差から決める

温度を適当な定数にすると、ほぼすべての悪化を受理したり、最初からほぼ受理しなかったりします。まず候補をいくつか生成し、悪化量の大きさを調べると、温度に意味を持たせられます。

代表的な悪化量を正の値 `d`、その変更を受理したい確率を `p` とすると、`p = exp(-d / T)` です。これを解けば `T = -d / log(p)` になります。

悪化量10の変更を半分くらい受理したければ、`T ≈ 14.43` です。これを出発点として、実際の受理率を測りながら調整します。ここで決めているのは、代表的な悪化量に対する受理率であり、すべての候補を合わせた受理率ではありません。

**注意。** 改善候補や同点候補まで平均に混ぜると、悪化量の尺度が分かりにくくなります。また、序盤と終盤で得点差の分布が変わることがあります。最初のサンプルだけで全期間を説明できるとは限りません。

**練習。** `d = 10` で `p = 0.8` と `p = 0.1` の温度を計算してください。受理しやすい側で温度が高くなることも確認してください。

**キットとの対応。** `SimulatedAnnealing` は開始・終了温度を受け取ります。`temperature_for_acceptance(d, p)` で温度を計算できます。代表的な悪化量の採取は探索側で行います。

<a id="b08"></a>
## B08. 線形冷却と指数冷却

探索の進捗を `t`、開始温度を `T0`、終了温度を `T1` とします。`t` は0から1まで動く値です。

線形冷却は `T(t) = T0 + (T1 - T0)t` です。同じ時間が進むごとに、同じ温度差だけ下がります。指数冷却は `T(t) = T0 × (T1 / T0)^t` で、同じ時間が進むごとに、同じ比率で下がります。

開始100、終了1の場合、中間点の温度は線形で50.5、指数で10です。開始と終了が同じでも、途中の探索は大きく変わります。「温度100から1」とだけ記録しても、実験条件としては不十分です。

**使いどころ。** 温度が何桁も変わる場合、指数冷却は割合で変化を追いやすい形です。一方、どちらが良いかは得点差の分布や近傍によります。

**注意。** 指数冷却では開始・終了温度が正である必要があります。時間進捗と反復回数進捗も別のものです。1反復の費用が変わる探索では、同じ温度曲線でも経路が変わります。

**練習。** 開始16、終了1で、進捗0、0.5、1の温度を両方式について計算してください。

**キットとの対応。** `SimulatedAnnealing::use_linear_schedule()` / `use_geometric_schedule()`。温度以外にも [linear_schedule / geometric_schedule](../../library/schedule.hpp) を使えます。

<a id="b09"></a>
## B09. 対数を使った受理判定

悪化候補の受理を直接書くと、0から1の一様乱数 `u` を引き、`u < exp(Δ / T)` を調べます。両辺の対数を取れば、`log(u) < Δ / T` と同じ判定になります。

対数の形では、非常に小さな確率を `exp` で作る必要がありません。ただし、毎回 `log` を計算する費用はあります。対数化だけで必ず高速になるとは言えません。

例えば `u = 0.2`、`Δ / T = -1` なら、`log(0.2) ≈ -1.609 < -1` なので受理します。直接判定でも `0.2 < exp(-1) ≈ 0.368` となり一致します。

**注意。** `u = 0` では通常の実数として対数を計算できません。乱数の端点の仕様を確認します。また、温度0を除算へ渡す前に、改善のみを受け入れる処理へ分けます。浮動小数点の端点は [B23](05-randomness.md#b23) で扱います。

**練習。** `u = 0.8` で同じ得点差を判定してください。直接判定と対数判定が一致することを確かめてください。

**キットとの対応。** `SimulatedAnnealing::accept()` は指数関数による判定です。先に対数で閾値を引く `draw_acceptance_threshold()` と `accept_with_threshold()` もあります。温度は正の有限値が必要です。対数形への変換は、乱数消費順や極小確率での丸めも含めて検算します。

<a id="b10"></a>
## B10. 近傍ごとの動きを観測する

小さな変更と大きな変更では、得点差の分布が違います。全体の受理率だけを見ると、片方の近傍がまったく働いていないことを見落とします。

例えば、小さい交換を900回試して450回受理し、大きい再構築を100回試して1回受理したとします。全体では45.1%の受理率ですが、大きい近傍は1%です。温度が合わないのか、候補の作り方が悪いのか、無効候補が多いのかを分けて調べます。

近傍ごとに「呼んだ回数」「有効な候補になった回数」「受理した回数」「最良解を更新した回数」「使った時間」を記録すると、変更の意味を判断しやすくなります。

**注意。** 受理率が高いだけでは良い近傍とは言えません。同点移動ばかり受理する近傍もあります。また、受理率を揃えるために近傍ごとに温度を変えると、探索全体の確率的な性質も変わるので、別の探索設計として実測します。

**練習。** 受理率80%で改善が1回の近傍と、受理率10%で改善が20回の近傍について、さらに何を測れば採用判断できるか挙げてください。

**キットとの対応。** 近傍ごとに [MoveStatistics](../../library/move-statistics.hpp) を持ち、`add(accepted, improved)` で試行・採用・改善を数えられます。有効率・最良更新・処理時間は必要に応じて別に記録します。
