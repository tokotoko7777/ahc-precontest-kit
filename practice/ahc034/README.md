# AHC034 - 蛇行路の開始位置を選んで、重い移動を減らす

[問題文](https://atcoder.jp/contests/ahc034/tasks/ahc034_a) / [公式ローカルツール](https://img.atcoder.jp/ahc034/vImT4eac.zip)

## まず何を小さくすればよいか

高さが正のマスでは土を積み、高さが負のマスでは土を下ろします。
トラックの現在位置から距離 `d` だけ動く費用は

```text
d * (100 + 現在の積載量)
```

です。

全マスを正しく高さ0にする解では、積む土の総量と下ろす土の総量は最初から決まっています。そのため、`+d` と `-d` にかかる費用の合計もどの正解でも同じです。差が付くのは移動費だけです。

そこで、この実装は次の2点を同時に狙います。

- 訪問順を蛇行状にして、総移動距離を短くする。
- なるべく土を早く下ろし、重い状態で動く距離を短くする。

## 必ず合法になる走査

1つのマス順 `order` を決め、次のように処理します。

1. 1周目では、正のマスの土を全部積む。
2. 負のマスでは、現在積んでいる量と、そのマスが必要とする量の小さい方だけ下ろす。
3. 1周目で土が足りなかった負のマスだけ、2周目で残りを下ろす。

下ろす量を常に `min(積載量, 残り必要量)` にするので、積載量が負になることはありません。入力の高さの総和は0なので、全供給を積み終えた時点の土は、未処理需要の合計と一致します。したがって2周目の終了時には、全マスの高さと積載量がちょうど0になります。

## 蛇行路を途中から始める

行方向・列方向、外側の進行方向、最初の内側方向を切り替え、8種類の蛇行順を作ります。さらに、各蛇行順をすべての非0マスから開始するように巡回シフトします。

道の形がほぼ同じでも、開始位置が違えば「最初に供給へ着くか」「大量の土をどこまで運ぶか」が変わります。全候補を問題と同じ費用式で正確に採点し、最も安いものを残します。

最良の巡回シフトには、短い区間だけを変更する焼きなましも行います。近傍は次の3種類です。

- 2マスの交換
- 区間反転
- 1マスの挿入移動

変更範囲を現在位置の前後12要素に限定し、蛇行路の短さを壊しにくくしています。試行回数は300,000回で、乱数seedと回数は固定です。

## 補助候補

局所的な土の偏りにも対応できるよう、次の独立した候補も作ります。

- 現在地に近い供給マスから積み、近い需要マスへ順に下ろす。
- 供給・需要のペアを作り、1往復ずつ運ぶ。
- 短い供給需要ペアを優先し、空荷区間の順番を局所探索する。

最後は内部の厳密な費用計算で全候補を比較します。内部計算では、積載量が負にならないこと、全マスが0になること、最後の積載量が0であることも確認します。常に合法な二段階蛇行路を初期解に持つため、補助候補が不正なら採用されません。

## 出力の作り方

探索中は「どのマスで何個積む・下ろすか」だけを `Event` として持ちます。最終候補が決まったら、イベント間を縦、横の順にマンハッタン最短路で結び、`U`, `D`, `L`, `R`, `+d`, `-d` を出力します。

走査候補のイベント数は高々800程度です。各イベント間の距離は最大38なので、操作数上限100,000にも十分余裕があります。公式seed 0--99での実測最大は2,385行でした。

## 計算量

非0マス数を `K (<=400)`、焼きなまし反復を `I=300000` とします。

- 蛇行路の全巡回シフト: `O(8K^2)`
- 焼きなまし: `O(IK)`
- 供給需要ペア候補: 最悪 `O(K^3)`
- メモリ: `O(K)`

`N=20` 固定なので、実装を単純にするため焼きなましの評価も毎回先頭から正確に計算しています。

## コンパイルと実行

`main.cpp` だけで動き、ローカルヘッダには依存しません。

```bash
g++ -std=c++20 -O2 -Wall -Wextra -Wshadow -Wconversion -pedantic -Werror main.cpp -o main
./main < in.txt > out.txt
```

公式ツールのディレクトリでは、たとえば次のように採点できます。

```bash
cargo build --release --bin vis
./main < in/0000.txt > out.txt
./target/release/vis in/0000.txt out.txt
```

比較用マクロもあります。通常提出では指定しません。

- `AHC034_SNAKE_BASELINE`: 正のマスをすべて回ってから負のマスを回る単純基準。
- `AHC034_SIMPLE_GREEDY`: 最寄りの供給から積み、最寄りの需要へ下ろす候補まで。
- `AHC034_ORDER_SEARCH_ITERATIONS`: 焼きなまし回数。通常値は300,000。

スコアは大きい方が良いです。同じ公式seed 0--99を3段階で比較しました。

追加の検証結果です。

- 公式seed 0--99: 全100ケース合法、最終版スコア最小25,123,197、最大62,204,352。
- 通常の単独実行: 約0.45--0.66秒。実行環境の一時的なCPU待ちを除く。
- 最大出力行数: 2,385。
- strict warnings: 通常版と比較用2マクロのすべてで警告なし。
- ASan + UBSan: seed 0, 5, 58, 99で異常なし。
- 全高さ0、および供給1マス・需要1マスだけの人工ケースでも異常なし。
