# AHC003 practice

公式問題: [A - Shortest Path Queries](https://atcoder.jp/contests/ahc003/tasks/ahc003_a)

`main.cpp` だけで提出できる、オンライン推定を使った過去AHCの実戦例です。

## 問題の要点

30×30のグリッドに未知の正の辺長があります。1000回、始点と終点を受け取って経路を
出力すると、その経路の真の長さへ0.9〜1.1倍のノイズを掛けた整数だけが返ります。
過去の返却値から辺長を学び、後半ほど真の最短路に近い経路を出す問題です。

出力後は必ずflushが必要です。不正な経路とは、盤面外へ出る、頂点を再訪する、終点へ
着かない経路です。

## 解法

各辺の推定値を、次の3段階の足し算で表します。

1. 横辺なら行、縦辺なら列ごとの基本値
2. その行・列の前半または後半の補正値
3. その辺だけの補正値

真の入力も、横辺は行ごと、縦辺は列ごとに似た値を持ち、高々1箇所で傾向が変わります。
最初から1740辺を完全に別々に学ぶより、少ない観測を共有できます。

経路を出力した後は、以下を行います。

- 現在の推定値から経路長を予測する
- 返却された長さとの差を求める
- 経路が各行・各半区間・各辺を何回使ったか数える
- 長い区間だけ更新量が大きくならないよう正規化して、誤差を各推定値へ分配する

返却値には乗算ノイズがあるので、一度の極端な誤差は上限を付けてから使います。

## 探索と活用

未観測の辺を少しだけ安く見積もる「探索ボーナス」を使います。序盤は未知の辺も試し、
1000ターン目へ近づくほどボーナスを0へ減らします。各ターンでは、この計画用辺長に
対してDijkstra法を実行します。

全ての計画用辺長を1000以上に保つため、Dijkstraが返す経路に頂点の再訪はありません。
30×30専用の固定長配列で実装し、毎ターンの処理はおよそ
`O(30^2 log(30^2))` です。

## 読む時の目印

- `OnlineEdgeEstimator::estimated_cost`: 3段階の推定値を足す
- `OnlineEdgeEstimator::planning_costs`: 不確実性に応じた探索ボーナスを引く
- `OnlineEdgeEstimator::update`: 観測された経路総和でオンライン更新する
- `shortest_path`: 固定30×30グリッド用のDijkstra法
- `endl`: 経路を出力した直後にflushする

## 注意

- 1位解の複数KalmanモデルやMCMCを移植したものではありません。初心者が追いやすい
  正規化勾配更新へ簡略化した独自実装です。
- 観測は経路全体の和だけなので、個々の辺を完全には特定できません。行・列の共通値を
  併用することが重要です。
- 汎用化するなら、疎な特徴量と観測値を渡す `OnlineLinearEstimator` が候補になります。
  今回は問題固有の3階層モデルが中心なので、共通ライブラリには追加していません。
