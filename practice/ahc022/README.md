# AHC022 practice

公式問題: [A - Exploring Another Space](https://atcoder.jp/contests/ahc022/tasks/ahc022_a)

`main.cpp` だけで提出できる、ノイズ付き対話問題の練習例です。ローカルheaderや外部ライブラリは
使っていません。

## 問題の要点

既知の出口が `N` 個あり、入口と出口の対応は未知の順列です。最初にトーラス状の温度盤面を
出力し、その後は入口と移動量を指定して、ノイズを含む温度を最大10,000回測れます。

温度差が大きい盤面は設置費が高く、遠くへ何度も動くと測定費が高くなります。一方、対応を
1個間違えるごとに評価値が0.8倍になるため、この例ではまず誤答を避け、その範囲で温度差を
小さくします。

## 解法

### 1. 盤面を0/1の符号として使う

固定seedの乱数で各cellへ0/1を割り当てます。実際に出す温度は `500-A` と `500+A` の2種類
です。出口から同じだけ移動して温度を読むと、出口ごとに異なるbit列が得られます。

4枚の候補盤面を作り、識別しにくい出口pairのHamming距離を優先して、最初に測る短い変位を
貪欲に選びます。第三者の提出コードを移植したものではなく、「観測を符号設計として扱う」
考え方から書いた独自の単純実装です。

### 2. ノイズに応じて温度差と測定数を変える

ノイズ `S` が小さい時は少ない測定で済ませます。大きい時は入口ごとに使える上限近くまで測り
ます。温度差 `A` は、おおよその識別余裕が一定になるように次で決めます。

```text
A = clamp(ceil(3.5 * S / sqrt(入口ごとの測定数 / 3)), 8, 500)
```

これにより、小ノイズcaseで不要に大きな設置費を払わずに済みます。

### 3. 次の測定場所を候補に合わせる

最初のbit列を測った後、各出口候補との二乗誤差を更新します。可能性が高い上位12出口を
およそ半分ずつに分ける変位を選び、追加測定します。全出口×全変位を毎回見る方法よりかなり
速く、曖昧な候補を直接区別できます。

端の0/1000へ丸められる影響を減らすため、復号には設定温度そのものではなく、正規分布へ
clipを適用した後の期待測定値を使います。

### 4. 最後は順列として復号する

入口ごとに最良候補を独立に選ぶと、同じ出口を重複して答えることがあります。全入口×全出口
の誤差表へHungarian法を適用し、各出口をちょうど1回使う最小費用対応を出力します。
同じ処理を型の選べる `library/hungarian.hpp` にも切り出しています。提出用 `main.cpp` には
必要部分を直接含むため、ローカルheaderへの依存はありません。

## 計算量

- 符号準備: およそ `O(4 * K * C * N^2)`
- 対話中: およそ `O(Q * (N + 12C))`
- 最後の割当: `O(N^3)`

`K` は最初の測定数（最大22）、`C` は短い変位候補数（最大320）、`Q` は総測定数（最大
10,000）です。動的な測定場所選びを上位12候補へ限定するのが速度上の要点です。

## 使い方

AtCoderへは `main.cpp` をそのまま提出できます。

```bash
g++ -std=c++17 -O2 -pipe main.cpp -o solver
```

これは対話問題なので、ローカル入力をsolverへ直接redirectせず、公式testerを間に入れます。

```bash
./tester ./solver < in/0000.txt > out.txt
./vis in/0000.txt out.txt
```

- seed 0〜9: 評価値合計87,288,079、平均8,728,807.9、誤対応0件
- 安全寄りの温度係数5.0版: 同じ10件で合計68,459,549
- 係数3.5版は10勝0敗で、合計評価値が約27.5%向上

- strict compile: `-Wall -Wextra -Wshadow -Wconversion -pedantic` で警告なし

100件で誤りがなかったことは未知caseでの完全正解を保証しません。特に最大ノイズ付近では
温度差が上限500へ達するため、さらに得点を伸ばすには盤面の境界数を減らしつつ符号距離を
保つ設計が必要です。
