# 13. 逐次意思決定・協調計画

[詳細編の目次](README.md) · [用語](GLOSSARY.md) · [出典一覧](SOURCES.md)

逐次計画では、今の行動が資金・保管場所・将来の到達性を変えます。現在の1手だけでなく、実行順と待機、観測後のやり直し、最後まで完成できる手順を含めて考えます。

説明用の小例と、提出コードで確認した具体例を分けて記載しています。適用効果は未測定で、検算と練習はこれから確かめるための課題です。

## D240. 作業拠点の被覆

作業地点そのものを選び直すと、1回の移動で複数の仕事をこなせる場合があります。

壁を1枚だけ作れる地点より、左右2枚を作れる地点を先に選ぶと拠点数を減らせます。その後で人を割り当てるため、拠点選択と移動距離の両方を見ます。

<a id="example-29654603-03"></a>
### コードでの具体例：両側の壁を作れる位置を先に拾う

2壁を建設できる位置、1壁の位置の順に選び、残った拠点を最寄り順に人へ振り分ける。

**適用条件・落とし穴。** 一回の到達で複数作業を済ませる被覆と巡回の分離。

**検算と練習。** 予定する全壁が少なくとも一つの作業拠点から建てられるか確認する。

## D241. 観測後の再計画

未知の費用が実行中に分かる場合、最初の推定で最後まで決めず、観測のたびに計画を更新します。

安いはずの通路を1か所試して硬いと分かったら、別経路へ切り替えます。毎回の再計画費用と、誤った計画を進める損失を比べます。

<a id="example-39142737-03"></a>
### コードでの具体例：最安推定経路を求め、未確定点を1回掘って再探索する

既接続部分から多点始動Dijkstraを行い、経路上で累積投入の小さい未破壊点を観測し、更新後に経路を再計算する。

**適用条件・落とし穴。** 部分観測下の経路探索。最初に選んだ経路を最後まで固定しない。

**検算と練習。** 再計画なし版との費用差と、観測後に経路が切り替わる頻度を測る。

出典: [AHC018 / 提出 39142737](https://atcoder.jp/contests/ahc018/submissions/39142737) · `find_path / main` · L255–L303, L339–L360, L498–L501。 [収録情報](SOURCES.md#submission-39142737)

## D242. 将来接続先の評価

今の接続費用が同じでも、次の接続へ使える形が違う場合があります。

L字経路の曲がり点を2通り試し、残る住宅へ伸ばしやすい方を選ぶ例です。現在の目的地だけを見ると同点になる選択を、将来の用途で区別します。

<a id="example-39142737-04"></a>
### コードでの具体例：L字の曲がり方を残り住宅の接続費用で比較する

**適用条件・落とし穴。** 複数目標へ共有幹線を伸ばす場合。仮接続と実際の掘削完了状態を混同しない。

**検算と練習。** 残り住宅評価の有無で共有水路長と費用を比較する。

## D243. 当たり確率と費用

欲しい情報が得られる確率と、それを試す費用を一緒に評価します。

成功確率0.6・費用3なら比は0.2、確率0.4・費用1なら0.4です。比の高い観測が常に全体最適とは限りませんが、局所的な選択基準になります。

<a id="example-44783436-06"></a>
### コードでの具体例：高温点へ当てる確率を移動費用で割って観測を選ぶ

基準高温点を配置し、仮説の出口からそこへずらす照会を候補にする。確率0.99以上の入口を除き、確率/費用が最大の組を観測する。

**適用条件・落とし穴。** 当たりが強い識別情報になる高ノイズ環境。簡単な比率指標が将来の全費用最小を保証するわけではない。

**検算と練習。** 基準点位置と閾値別の測定数・誤認率を比較する。

出典: [AHC022 / 提出 44783436](https://atcoder.jp/contests/ahc022/submissions/44783436) · `OnePoint::DecideBase / Run` · L1736–L1758, L1898–L1938。 [収録情報](SOURCES.md#submission-44783436)

## D244. 時空間の衝突回避

複数の移動体では、同じ時刻に同じ場所へ入る衝突と、同じ辺を逆向きにすれ違う衝突を分けて検査します。

時刻tのAが左、Bが右で、次時刻に位置交換する場合、到着位置は重複しなくても辺上で衝突します。位置だけの予約表では検出できません。

<a id="example-53942556-02"></a>
### コードでの具体例：位置占有と逆向き交差を別マスクで禁止する

時刻ごとの空き位置だけでなく方向ごとの交差マスクを持つ。小クレーンの運搬時は荷物占有も重ね、大クレーンではその制約を外す。

**適用条件・落とし穴。** 同時移動で頂点衝突とすれ違い衝突の両方を避ける経路計画。

**検算と練習。** 全クレーンの軌跡を同時再生し、占有・交差・荷物制約を検査する。

出典: [AHC033 / 提出 53942556](https://atcoder.jp/contests/ahc033/submissions/53942556) · `Frame / armCrossMask` · L2806–L2828, L2977–L2988, L3015–L3026。 [収録情報](SOURCES.md#submission-53942556)

## D245. 作業時間を含む到達判定

到着した瞬間に仕事が完了するとは限りません。作業に必要な滞在時間を確保します。

荷物の取得に1手必要なら、地点へ着いた時刻と次の時刻の両方でそこにいられる必要があります。移動経路の到達性と作業の実行可能性を分けます。

<a id="example-53942556-03"></a>
### コードでの具体例：把持と解放には連続2時刻で目的位置に居られることを要求する

単に目的位置へ到達しただけでなく現在集合と次時刻集合の両方に含まれることを確認して、作業の1手を確保する。

**適用条件・落とし穴。** 移動後にその場で操作するロボット計画。到達時刻と作業完了時刻のずれに注意する。

**検算と練習。** 他のクレーンが直後に同セルへ来る例で作業が誤って許されないか確認する。

出典: [AHC033 / 提出 53942556](https://atcoder.jp/contests/ahc033/submissions/53942556) · `MakeFindBoxMap / MakeFindCarryMap` · L2990–L2993, L3030–L3033。 [収録情報](SOURCES.md#submission-53942556)

## D246. 観測ごとの再評価

入力が世代ごとに更新されるなら、評価の基準も更新します。以前の希少性や最大値を持ち越すと判断が古くなります。

前の世代で唯一だった特徴が、新しい世代で5個体へ広がったなら希少性は下がります。観測後に何を再集計するかを明確にします。

<a id="example-55852875-04"></a>
### コードでの具体例：各世代で最大値と希少度を計算し直す

新しい種の観測を読み、評価の基準となる最大値・出現数を毎世代更新して配置を出力する。

**適用条件・落とし穴。** 分布が逐次変わる選抜問題。前世代の絶対評価を使い回すと希少性がずれる。

**検算と練習。** 世代別の特徴分布と配置選択を記録し、固定評価版と比較する。

出典: [AHC035 / 提出 55852875](https://atcoder.jp/contests/ahc035/submissions/55852875) · `main` · L481–L521, L572–L577。 [収録情報](SOURCES.md#submission-55852875)

## D247. 資金と待機

資金が足りない場合、1ターンずつ待たず、必要額と定期収入から待機量を求められます。

不足50、毎ターン収入12なら待機は切上げで5ターンです。収入が0の場合や、待機中に収入が変わる場合は、この式の前提が成立しません。

<a id="example-63119772-01"></a>
### コードでの具体例：待機をまとめて進め、残り期間の収入まで評価する

建設に必要な不足額から待機ターンを切り上げ計算し、現在資金と残りターンの収入を評価にする。

**適用条件・落とし穴。** 収入一定の区間を一括処理できる。収入ゼロ時の除算は呼び出し条件と合わせて確認する。

**検算と練習。** 一手ずつの資金シミュレータと待機圧縮版を比較する。

出典: [AHC043 / 提出 63119772](https://atcoder.jp/contests/ahc043/submissions/63119772) · `GetDelay / Final / Wait` · L948–L972。 [収録情報](SOURCES.md#submission-63119772)

<a id="example-63121685-03"></a>
### コードでの具体例：一括建設できる資金条件を先に判定する

線路群を連続建設できれば式で更新し、不足する場合のみ一本ずつ必要待機を計算する。

**適用条件・落とし穴。** 高速経路と一般経路の併用。収入ゼロで建設不能なら負の資金を返す。

**検算と練習。** 資金が閾値直前・ちょうど・直後のケースで逐次版と比較する。

## D248. 終盤の資源使い切り

残りの仕事をまとめて考えると、端数の資源を別の仕事と共有できます。

赤を1.2と0.8使う2件なら、合計2で購入できるかもしれません。1件ずつ切り上げると2+1になります。終盤に余る資源も含めて組合せを調整します。

**適用条件・落とし穴。** 購入が整数単位で残量を持ち越す問題向け。残り件数や費用による切替条件も問題固有。

**検算と練習。** 逐次最適化と終盤一括計画で購入数・余剰量を比較する。

## D249. 製造順と納品順の分離

作りやすい順序と、届けるべき順序が違う場合、中間保管を使って両者を分離できます。

製造はA,C,Bの順が安くても、納品はA,B,Cが必要ならCを保管します。保管場所の容量と、保管・取出しの操作費用も計画へ入れます。

<a id="example-66623158-07"></a>
### コードでの具体例：混ぜやすい順に作って区画へ保管し、要求順に取り出す

**適用条件・落とし穴。** 物理バッファがある順序制約問題向け。区画の循環再利用で未納品品を壊さない条件の検証が必要。

**検算と練習。** 製造イベント・格納場所・納品番号を再生し衝突を検査する。

## D250. 締切と抜け道の防止

通路や視界を変えると、本来意図しなかった短絡も生じます。新しい道の合法性だけでなく、既存計画への影響を調べます。

壁を開けて早く到達できても、別の行動が予定より先に実行されるなら計画が変わります。締切と、意図しない抜け道の両方を検査します。

<a id="example-69728114-02"></a>
### コードでの具体例：視界を通す候補に時刻制約とショートカット検査を加える

4方向の候補を調べ、既存経路に接続でき、締切を越えず、意図しない近道を生まない最短候補を選ぶ。

**適用条件・落とし穴。** 局所的に穴を開けると全体の誘導が崩れる設計問題向け。近道検査の詳細は別途追う必要がある。

**検算と練習。** 候補を開けた後に観測・移動シミュレーションを再実行する。

## D252. 非交差同時操作のDP

同時実行できる操作を選ぶとき、順序が交差しない条件をDPの状態にできます。

最後に選んだ相手番号を持ち、次の候補の許される範囲を限定します。各操作の利益を足し合わせてよいか、同時実行による相互作用も確認します。

<a id="example-75295267-03"></a>

各線路対の最良候補を残し、出発線路を進めながら最後に選んだ相手線路番号をDP状態にする。

**適用条件・落とし穴。** 順序を保つ非交差マッチングに近い同時操作選択。各候補gainの加算が実評価に一致するかは別途確認する。

**検算と練習。** 少数線路で全組合せを列挙しDPと比較する。

## D253. 投入タイミングの制御

流れている経路へ物を投入する場合、正しい場所だけでなく正しい時刻も必要です。

次に番号7が来るべき位置へ、側線の7が一致した瞬間に投入します。時刻を1つずらすだけで後続の順番が変わるため、更新順序を統一します。

<a id="example-75827741-03"></a>
### コードでの具体例：側線の箱番号が到着予定番号に一致したとき交換する

各時刻に周回路を走査し、側線の箱がsbと一致すれば交換、最後に主コンベアを一つ回す。負時刻では先行配置を行う。

**適用条件・落とし穴。** 大量の順序付き排出を単純な規則で実現する例。終了時に全箱排出済みか確認する。

**検算と練習。** 箱番号の出力順と残存箱数を逐次検査する。

## D254. 途中解からの完了手順

探索が時間内に最後まで到達しない場合に備え、途中状態から簡単な方法で完成させます。

現在の接頭辞から失敗したら、少し前の保存状態へ戻って試します。最悪でも初期状態から作れる完成手順を用意すると、出力できない失敗を減らせます。

<a id="example-76520389-05"></a>
### コードでの具体例：ビーム途中・過去の途中・初期状態の順に貪欲完了を試す

ビームが完走しない場合、現在接頭辞から貪欲で埋め、失敗なら少し前の保存状態、最後は空接頭辞から作る。

**適用条件・落とし穴。** 締切付き探索で完成率を保つ構成。各完了手順の実行可能性は再生して確かめる。

**検算と練習。** 時間予算を削り段階別フォールバックの成功率を測る。
