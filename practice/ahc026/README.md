# AHC026 practice

公式問題: [A - Stack of Boxes](https://atcoder.jp/contests/ahc026/tasks/ahc026_a)

`main.cpp` だけで提出できる、複数の山から箱を番号順に取り出す練習例です。
ローカルのライブラリや外部ファイルには依存しません。

## 問題の要点

- 箱は10個の山に下から上の順で並んでいます。
- 次に運び出す箱は `1, 2, ..., 200` の順で固定です。
- 目的の箱の上にある連続部分は、順序を保ったまま別の山へ移せます。
- `k` 箱を一度に移すと消費エネルギーは `k + 1` です。

したがって「一度に多く運ぶ」と手数料の `+1` は減りますが、近いうちに必要な箱まで
大きな塊の中へ埋めると、同じ箱をもう一度動かすことになります。この二つの損を両方
小さくするのが中心です。

## 解法

### 1. 必要な箱の上をまとめて退避する

単純版は、目的の箱の上を一つの塊として移します。移動先には「山全体の最小番号が
最も大きい山」を選びます。近い将来に必要な箱を覆いにくい、安全な基準方策です。

### 2. 近いうちに必要な箱だけを分ける

現在の目的を `target`、先読み幅を `range` とします。上から目的の箱へ向かって調べ、
`target + range` 以下の箱を見つけたら次のように分けます。

1. その箱より上だけを、基準方策でまとめて退避する。
2. 見つけた箱を1個だけ別の山へ置く。

1個だけ置く先は、その山の最小番号が箱番号以上である山から選びます。これなら、その箱
より先に取り出すべき箱を覆いません。条件を満たす中では最小番号が近い山を選び、大きな
番号だけの山を後のために残します。

### 3. 先読み幅をrolloutで選ぶ

最適な `range` は盤面の途中で変わります。各 `target` で、全ての `range` 候補について
最後まで同じ貪欲を仮実行し、消費エネルギーが最小だった幅をこの1段だけ採用します。
次の箱では、変化後の山からもう一度比較します。

仮実行の結果はそのまま正確な消費エネルギーなので、採点ツールを呼ぶ必要はありません。
また `box -> 現在の山` の表を移動時に更新し、目的の箱を探すたびに10山全てを走査しない
ようにしています。

## コードを読む順番

- `move_suffix`: 公式操作1を盤面と出力へ同時に反映
- `choose_bulk_destination`: 大きな塊の安全な退避先
- `choose_small_box_destination`: 近い番号の箱を1個置く先
- `remove_one_target`: 1箱を運び出すまでの処理
- `make_plan`: 固定した先読み幅で最後まで仮実行
- `main`: rolloutで幅を選び、実盤面へ1段だけ反映

## コンパイルと比較用設定

通常版:

```bash
g++ -std=c++17 -O2 main.cpp -o solver
```

比較用の単純版と固定幅版も同じソースから作れます。

```bash
g++ -std=c++17 -O2 -DBASELINE_POLICY main.cpp -o baseline
g++ -std=c++17 -O2 -DFIXED_POLICY main.cpp -o fixed
```

## 公式ローカルツールでの確認

[公式ローカルツール](https://img.atcoder.jp/ahc026/lPQezTZx.zip)のseed 0〜99で採点しました。

- 全100ケース合法、未完了・5000操作超過ともに0件
- 平均得点: 9,336.94（平均消費エネルギー663.06）
- 最小得点: 9,232、最大得点: 9,418
- 平均操作数: 413.45、最大操作数: 446
- 実行時間中央値: 約0.31秒、95 percentile: 約0.39秒

seed 0〜9を同じ10ケースで比較した結果です。

| 方策 | 平均得点 | 平均消費エネルギー |
|---|---:|---:|
| 全て一塊で退避 | 9,049.3 | 950.7 |
| ケース全体で固定した最良幅 | 9,310.8 | 689.2 |
| 各段で幅を選び直す通常版 | 9,334.0 | 666.0 |

通常版は単純版に対して消費エネルギーを約30.0%減らしました。
`-Wall -Wextra -Wshadow -pedantic` で警告なしです。ASan・UBSan同時有効版も
seed 0、37、99で完走し、公式ビジュアライザで合法性を確認しました。

## 計算量と注意

各段で最大201種類の貪欲な完走を比較します。`N=200, M=10` 固定で、実測時間を優先した
構成です。入力上限が大きく変わる問題へ流用する場合は、試す幅を間引くか候補だけに絞って
ください。

知識コーパスのAHC026代表コードは未確認だったため、そこから特定実装は採用していません。
公式問題の構造と、スタック問題で有効な「合法性を候補生成で守る」「先の邪魔を評価する」
という一般原則から組み立てた独自実装です。
