# 08. 候補制限・枝刈り

[詳細編の目次](README.md) · [用語](GLOSSARY.md) · [出典一覧](SOURCES.md)

候補を全て精密評価する時間がないとき、どれを残すかを決めます。必ず勝てないと証明して落とす枝刈りと、有望そうな候補へ絞る近似は違います。省略した計算と、見逃す可能性の両方を確認します。

説明用の小例と、提出コードで確認した具体例を分けて記載しています。適用効果は未測定で、検算と練習はこれから確かめるための課題です。

## D187. 近傍上位K

全候補を完全に並べ替える必要がなく、近い数個だけ欲しい場合は、上位K個を分離する処理で済みます。

1000候補から近い5個だけ使うなら、残り995個の順序には意味がありません。分離後の5個もソート済みとは限らない点に注意します。

<a id="example-20926292-04"></a>
### コードでの具体例：全ソートせず近い5領域だけ複合近傍にする

改善不要な組を除き、nth_elementで距離上位5件を抜き出して順番を乱す。

**適用条件・落とし穴。** 二要素近傍の候補数を抑える。遠隔交換の価値は取りこぼす。

**検算と練習。** K別の試行数と最終品質を同一入力群で測る。

出典: [AHC001 / 提出 20926292](https://atcoder.jp/contests/ahc001/submissions/20926292) · `NE::n2` · L882–L910。 [収録情報](SOURCES.md#submission-20926292)

## D188. 軽い評価を先にする

安い計算だけで棄却できる候補には、高い合法性検査を行いません。

経路差分が許容悪化量を越えていれば、長い区間内の先行制約を調べても採用には変わりません。逆に、得点が良くても合法性の検査自体を省くことはできません。

<a id="example-27260278-05"></a>
### コードでの具体例：受理されない反転は合法性走査の前に捨てる

O(1)の経路差分と受理判定を先に行い、その後で区間の先行制約を調べる。

**適用条件・落とし穴。** 重い合法性判定を通す候補を減らす。判定前に状態を破壊しない。

**検算と練習。** 各判定の通過数と時間を分けて計測する。

出典: [AHC006 / 提出 27260278](https://atcoder.jp/contests/ahc006/submissions/27260278) · `step type 1` · L498–L503。 [収録情報](SOURCES.md#submission-27260278)

## D189. 閾値到達での探索終了

正確な個数ではなく「少なくともK個あるか」だけ知りたいなら、K個を見つけたところで探索を終えます。

領域が10セル以上かを調べる際、1000セル全部を数える必要はありません。戻り値が正確な面積なのか、閾値判定なのかを関数の契約で分けます。

<a id="example-29654603-05"></a>
### コードでの具体例：連結面積の正確な値が不要なら途中で止める

到達セル数がlimitへ達した時点でflood fillを打ち切る。lockでは狭い領域かどうかだけを判定する。

**適用条件・落とし穴。** 面積の下限判定に向く。返り値を完全な面積として再利用しない。

**検算と練習。** 完全flood fillによる閾値判定と一致するか確認する。

出典: [AHC008 / 提出 29654603](https://atcoder.jp/contests/ahc008/submissions/29654603) · `ff / fill` · L1139–L1169。 [収録情報](SOURCES.md#submission-29654603)

## D190. 粗い評価から精密評価へ

候補を安い情報で絞ってから、残ったものに高い評価を使います。

100候補を少数の始点だけで比較し、選ばれた候補を全始点で精算する形です。最終評価が正確でも、前段で落とした候補の最善性は保証されません。

<a id="example-36660262-02"></a>
### コードでの具体例：グラフ全体特徴で16候補に絞って頂点対応を解く

集約特徴の内積で候補ラベルを選び、残った候補について頂点特徴の内積行列を最小費用割当に渡す。

**適用条件・落とし穴。** 重い対応付けを全ラベルへ行いたくない場合。真のラベルを粗い段階で落とす可能性がある。

**検算と練習。** 候補16件の正解包含率と精密段階の計算時間を測る。

出典: [AHC016 / 提出 36660262](https://atcoder.jp/contests/ahc016/submissions/36660262) · `solve_large_N` · L764–L789。 [収録情報](SOURCES.md#submission-36660262)

<a id="example-38643777-02"></a>
### コードでの具体例：少数始点で最良日を選んでから残りを精算する

testVisだけで全候補日を評価し、選んだ日についてotherVisも更新したスコアで受理判定する。

**適用条件・落とし穴。** 候補数と完全評価費用の積が大きい場合。一次選抜が最良候補を落とす点は近似である。

**検算と練習。** 全始点で候補選択する版との差と、選抜の失敗率を測る。

出典: [AHC017 / 提出 38643777](https://atcoder.jp/contests/ahc017/submissions/38643777) · `Transition_Update1` · L2915–L2957。 [収録情報](SOURCES.md#submission-38643777)

## D191. 被覆による同一視

将来に重要そうな特徴だけをキーにして、似た候補を1つへまとめます。

同じ投影を覆う2つの立体でも、伸ばしやすさは違うかもしれません。体積の小さい方だけ残す規則は計算量を減らしますが、完全な同一状態判定ではありません。

<a id="example-40290839-07"></a>
### コードでの具体例：同じ投影被覆の候補を体積で絞る

被覆マスクをまとめたキーで候補や途中状態をまとめ、小さい体積を優先して残す。配置全体の同一性判定ではない。

**適用条件・落とし穴。** 主目的が被覆の進捗に強く依存する場合。将来拡張可能性は配置に依存するので厳密な支配則ではない。

**検算と練習。** 同一視なしの小規模探索と比較し、良い配置を落とす頻度を調べる。

出典: [AHC019 / 提出 40290839](https://atcoder.jp/contests/ahc019/submissions/40290839) · `hist3 / H` · L569–L580, L930–L988。 [収録情報](SOURCES.md#submission-40290839)

## D192. 確定済み要素を固定

すでに仕上げた部分を動かさないと決めると、後半の分岐が小さくなります。

番号1〜5を確定したら、次は6だけを動かします。完成領域を一時的に壊した方が得な解は探索できなくなるので、制限の強さを意識します。

<a id="example-42958359-01"></a>
### コードでの具体例：最小の未確定番号だけを動かして分岐を減らす

上側の条件を満たす番号を順に確定し、次の番号を隣接点へ動かす候補だけを列挙する。より小さい番号との交換を禁止する。

**適用条件・落とし穴。** 順序条件を段階的に満たす問題。早い確定が後段の自由度を狭める可能性がある。

**検算と練習。** 確定部分の不変条件と、全隣接交換探索との差を小盤面で調べる。

出典: [AHC021 / 提出 42958359](https://atcoder.jp/contests/ahc021/submissions/42958359) · `State::current_id / Tree::dfs` · L285–L315, L427–L437。 [収録情報](SOURCES.md#submission-42958359)

## D193. 上位候補の閾値

上位K個の最下位を常に知っていれば、それ以下の新候補を保存する費用を省けます。

現在の最低得点が100なら、99点の候補の長い履歴をコピーしなくて済みます。同点候補を残すかどうかは、比較規則に合わせます。

<a id="example-52156995-03"></a>
### コードでの具体例：ビーム下限を最小ヒープで維持し弱い候補の保存を避ける

上位幅ranの最低得点を保持し、それ以下の候補では操作列への追加や候補ベクタ保存を省く。最終的には保存候補をソートして切る。

**適用条件・落とし穴。** 候補生成数が多いビーム。盤面コピー自体は閾値判定より前なので、その費用まで省けるわけではない。

**検算と練習。** 保存件数とコピー回数を別々に計測する。

出典: [AHC032 / 提出 52156995](https://atcoder.jp/contests/ahc032/submissions/52156995) · `valque` · L303–L337。 [収録情報](SOURCES.md#submission-52156995)

## D194. 楽観上界による枝刈り

残りがすべて理想的に成功した場合の得点でも基準に届かないなら、その枝は捨てられます。

現在10点、残り2本の指が最大3点ずつなら上界16です。基準が18なら打ち切れます。競合を無視した過大評価は上界になりますが、過小評価は安全ではありません。

<a id="example-58801909-02"></a>
### コードでの具体例：未確定の各指の最大利得を足して回転列挙を打ち切る

途中まで関節を決め、残る指の到達集合と未処理仕事の積を取り、各指の最良利得を上界として足す。ビーム下限に届かない姿勢を捨てる。

**適用条件・落とし穴。** 関節列挙の指数分岐を削りたい場合。同じセルを複数指で数える上界は楽観的に扱う。

**検算と練習。** 小規模で枝刈りなしとの最良候補一致を確認する。

出典: [AHC038 / 提出 58801909](https://atcoder.jp/contests/ahc038/submissions/58801909) · `Next` · L917–L959。 [収録情報](SOURCES.md#submission-58801909)

## D195. 境界候補の管理

境界の形を変える操作なら、内外の境目だけを候補にすると無意味な抽選を減らせます。

広い塗り領域の内部セルを毎回引く代わりに、外側へ接するセルの集合を持ちます。変更後に新しく境界になったセルの追加も必要です。

<a id="example-59660035-04"></a>
### コードでの具体例：内外が接するセルだけを追加削除候補にする

初期候補を境界から作り、採用時だけ変更セルと4近傍の候補所属を更新する。内部や遠い外部を引く無駄を減らす。

**適用条件・落とし穴。** 境界だけ動かす領域探索。候補の再追加と除去を両方維持する。

**検算と練習。** 候補集合の全走査と更新結果を比較する。

出典: [AHC039 / 提出 59660035](https://atcoder.jp/contests/ahc039/submissions/59660035) · `on_candidates / off_candidates` · L289–L321, L536–L571。 [収録情報](SOURCES.md#submission-59660035)

## D196. 探索規模で切替

データ構造の準備費用には固定の負担があります。小さい集合では単純な全走査の方が扱いやすいことがあります。

駅が5個なら5距離を比べ、多くなったら行ごとのビット集合を使う、と切り替えます。境界の個数は実測して決めます。

<a id="example-63119772-03"></a>
### コードでの具体例：駅が少なければ全走査、多ければ行マスク検索

既設駅24未満では距離を全列挙し、それ以上では各行の近いビットを調べ、現在最短距離で行の走査を打ち切る。

**適用条件・落とし穴。** データ数により定数項が変わる処理の切替例。閾値24の最適性は未検証。

**検算と練習。** 駅数を横軸に両方式の時間と得た距離を比較する。

## D197. 親ごとの候補制限

1つの親が大量の似た子を生成すると、他の親の候補が見えにくくなります。親ごとに生成数を制限します。

各親から20件までにすると、候補数の偏りを抑えられます。ただし優秀な親の21件目を落とすので、全体上位だけを選ぶ方法とは異なります。

<a id="example-63121685-04"></a>
### コードでの具体例：新収入のある駅を優先し、親ごと20候補に絞る

即時収入増の候補を列挙し、なければ潜在収入増へ切り替える。各親からの子数に上限を置く。

**適用条件・落とし穴。** 枝の多い一親がビームを占有するのを抑える設計。候補評価の上界性は別途証明が必要。

**検算と練習。** 子数制限と潜在収入候補の有無を別々に比較する。

出典: [AHC043 / 提出 63121685](https://atcoder.jp/contests/ahc043/submissions/63121685) · `localCands / dincomes / dpincomes` · L6270–L6310。 [収録情報](SOURCES.md#submission-63121685)

## D198. 安価な指標で前段選別

未来まで精密に評価する前に、目先の危険が小さい候補だけ残します。

即時の失敗確率が低い上位10点だけを先読みする例です。今は危険でも将来に有利な行動を落とす可能性があるため、候補数との交換条件を測ります。

<a id="example-67393589-03"></a>
### コードでの具体例：即時死亡確率の小さい上位だけを先読みする

低確率位置を並べ、上位K候補だけ先読み評価。進行に伴い候補数と先読み反復数を減らす。

**適用条件・落とし穴。** 高価な評価前の候補削減。低い即時コストが長期最善を保証するわけではない。

**検算と練習。** Kを変え探索時間と最終期待値を比較する。

出典: [AHC050 / 提出 67393589](https://atcoder.jp/contests/ahc050/submissions/67393589) · `K / lookahead_turns / candidates` · L1313–L1358。 [収録情報](SOURCES.md#submission-67393589)

## D199. 近接ペアの前計算

候補の種類によって、近いと見なす尺度を変えます。

単独移動なら1つの端点距離、2組の交換なら両端の対応距離の和で候補を作ります。共通の近接表を無理に使うより、操作に合う候補を集められます。

<a id="example-72330966-05"></a>
### コードでの具体例：端点距離で移動候補と交換候補を別に作る

移動は近いペアのリスト、交換は二端点の対応距離和の小さい組に絞る。

**適用条件・落とし穴。** 二端点を持つ要素の候補削減向け。閾値3と8は別の尺度である。

**検算と練習。** 候補閾値と探索速度・改善幅を比較する。

出典: [AHC059 / 提出 72330966](https://atcoder.jp/contests/ahc059/submissions/72330966) · `NearPairs / SwapCandidates` · L653–L661, L725–L743。 [収録情報](SOURCES.md#submission-72330966)

## D200. 実行頻度による重点化

何度も実行される判断を優先して変えると、1つの改善が繰り返し効く可能性があります。

1回しか訪れない地点より20回訪れる地点の閾値を試す設計です。頻度の低い地点に決定的な改善がある可能性は残ります。

<a id="example-72942421-04"></a>
### コードでの具体例：10回以上訪れる地点だけを変更対象にする

現在の操作列の訪問回数で候補を作り、採用後に更新する。

**適用条件・落とし穴。** 影響の大きい方策パラメータに探索を集中できる。未訪問地点を開拓する変更は落ちる。

**検算と練習。** 全地点からの選択を少量混ぜた版と比較する。

出典: [AHC060 / 提出 72942421](https://atcoder.jp/contests/ahc060/submissions/72942421) · `frequent_nodes / rebuild_frequent` · L194–L202, L227–L235, L268–L275。 [収録情報](SOURCES.md#submission-72942421)

## D201. 合法な切断点の逆引き

接続可能な相手をランダムに探して棄却する代わりに、空間上の隣接から経路内の位置を引きます。

**検算と練習。** 全位置を調べた合法候補集合との対応を確かめる。

## D202. 下界で高価な距離計算を省く

制約を緩めた距離は、本当の距離以下になります。この下界で有望でない候補を精密計算の前に除きます。

障害物を無視しても距離20で、現在の上位Kの限界が15なら、障害物付きBFSをしても入れません。比較対象と下界の単位を揃えます。

<a id="example-77562268-02"></a>
### コードでの具体例：全域距離順に候補を調べ、現在のk番目を越えたら止める

制約を外した距離を前計算し、確定セルを除いた正確なBFSは有望な目標だけに行う。

**適用条件・落とし穴。** 削除により距離が短くならないことを利用する。ただし候補の最初のk個への制限自体はヒューリスティック。

**検算と練習。** 全目標でBFSする版との採用候補差と時間を測る。

## D203. 学習器による再配置候補選別

重い修復へ進める候補を、学習器の予測で選別する方法です。予測がそのまま実行可能性を保証するわけではありません。

100候補から予測上位10個だけ詳細探索します。予測の順位品質と推論費用を測り、少数候補では単純な順序に切り替える設計もあります。

<a id="example-78259988-05"></a>
### コードでの具体例：重い救済探索の候補が多いときだけネットで並べる

再配置候補群を特徴量化してまとめて推論し、上位shortlistに絞る。特徴を使わない場合は移動費用などの安い順序を使う。

**適用条件・落とし穴。** 高価な探索前のランキング向け。推論時間と上位候補を落とす損失を両方測る。

**検算と練習。** 全候補評価に対する上位再現率と所要時間を測る。

## D204. 同一中心のサイズ間選別

同じ中心で範囲だけ広げる候補を比較し、目的上の利益が増えないものを省きます。

サイズ3と5で回収数が同じで、5の方が高価なら小さい方を優先します。ただし将来の盤面への影響が違う場合、厳密な支配関係とは限りません。

<a id="example-79251146-03"></a>
### コードでの具体例：大きくしても回収数が増えず安くもならない候補を省く

中心位置ごとにサイズを伸ばし、処理対象が増えるか費用が下がる候補だけ残す。

**適用条件・落とし穴。** 同じ効果の入れ子候補が多い場合向け。後続の許可位置もサイズに依存するため全体最適性の証明とは区別する。

**検算と練習。** 候補削減なしとの解の差と分岐数を測る。
