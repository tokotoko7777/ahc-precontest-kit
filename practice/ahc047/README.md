# AHC047 - Lovely Language Model

12 状態の確率的な文字生成器を作る問題です。各状態には `a`〜`f` の1文字を置き、各行の遷移確率を整数で合計100にします。長さ `1,000,000` の生成文字列に好きな文字列 `S_i` が1回以上出る確率を `Q_i` とすると、公式得点は `round(sum(P_i * Q_i))` です。

このフォルダの `main.cpp` は、外部ヘッダーを使わない提出可能な1ファイルです。

## まず分かる単純解

状態0〜5を `a`〜`f` にして、次の文字をほぼ一様に選べば必ず合法です。

```cpp
// 各行で a,b,c,d は17%、e,f は16%
17 17 17 17 16 16
```

`main.cpp` を `-DSIMPLE_BASELINE` 付きでコンパイルすると、この単純解だけを出力します。

```bash
g++ -std=c++17 -O2 -DSIMPLE_BASELINE main.cpp -o baseline
./baseline < input.txt > baseline.txt
```

## この解法

### 1. 各文字を2状態ずつ持つ

最初は `abcdefabcdef` と割り当てます。どの文字も必ず状態にあるため、全ての `S_i` が出現可能です。また、同じ文字の2状態を「直前や直後の文脈が違う状態」として使えます。

### 2. 好ましい文字列から遷移を数える

`P_i` が大きい文字列ほど重くして、隣り合う文字の遷移を数えます。重視する上位語数、重みの掛け方、2状態への振り分け方を変えた小さな初期解を複数作ります。

全ての辺に最低1%を残します。これには次の利点があります。

- どの文字列も出現確率が0にならない
- Markov連鎖が混ざりやすく、探索用の近似が安定する
- 1行の合計は常に100のまま変更できる

### 3. 軽い近似で焼きなまし

探索中に公式確率を毎回計算すると重すぎます。そこで次の近似を使います。

1. 状態確率を28回伝播して定常分布を近似する
2. 各 `S_i` がランダムな1位置から始まる確率を前向きDPで求める
3. 期待出現回数を `lambda` として、出現確率を `1-exp(-lambda)` と近似する

近傍は次の2種類だけです。

- 同じ遷移行の1〜4%を別の遷移先へ移す
- 2状態の文字を交換する

どちらも各行の合計100と「各文字が2状態」を壊しません。

### 4. 最終候補だけ公式と同じ厳密評価

近似には誤差があります。最後に次の5候補を厳密評価して、一番良いものを出します。

- 一様な単純解
- 1本の12状態周期で文字列を確実に出す決定的解
- 軽い近似で上位だった初期解2個
- 焼きなまし後の解

厳密評価では、`(S_i の何文字まで一致したか, 現在のモデル状態)` を状態にしたKMPオートマトンを作ります。`S_i` が完成する遷移を吸収させ、残った確率行列を二乗法で `L-1` 乗します。最後まで吸収されなかった確率を1から引くと `Q_i` です。これは公式visualizerと同じ評価方法です。

一様解も最終候補に含めるため、厳密な内部評価では単純解より悪い候補を選びません。

## コンパイルと実行

```bash
g++ -std=c++17 -O2 -pipe main.cpp -o main
./main < input.txt > output.txt
```

公式ローカルvisualizerを展開したディレクトリでは、次で得点と合法性を確認できます。

```bash
cargo run -r --bin vis input.txt output.txt
```

## 読む順番

初心者なら、まず以下だけ追えば全体像が掴めます。

1. `make_uniform_model` - 必ず合法な出力
2. `make_learned_model` - 入力を遷移確率へ変える
3. `approximate_score` - 探索用の軽い評価
4. `improve_model` - 制約を壊さない焼きなまし
5. `exact_word_probability` - 最後だけ使う厳密評価

## 計算量

探索用評価は概ね `O(N * |S| * M^2)` ですが、文字が一致する遷移だけを見るため実際には小さいです。厳密評価は各文字列について小行列を `O(log L)` 回二乗します。重い厳密評価を最終5候補に限定して、2秒制限に収めます。

## 知識集との関係

- 公式確認: 制約、採点式、KMP進捗を使う公式visualizerの確率計算
- 知識集の確認済みレビュー: AHC047代表例は、状態文字・遷移先・確率を焼きなましし、文字列進捗を含むMarkov連鎖を評価していました
- この実装で独自に簡略化した点: 2状態/文字、文脈別の頻度初期化、Poisson近似、最低1%平滑化、最終候補だけの厳密評価

第三者提出コードは使用していません。代表レビューの「小行列で確率を評価し、局所変更する」という構造だけを参考に、初心者向けに独立実装しています。

## 調整しやすい値

- `improve_model(..., 0.62)` の `0.62`: 探索に使う秒数
- `28`: 定常分布を近似する反復数
- `top_counts`: 初期解で重視する上位語数
- `powers`: `P_i` の重みの強さ
- 焼きなましの `0.0025` と `0.02`: 開始・終了温度

時間制限が違う環境では、最初に探索時間だけを調整するのが安全です。

## ローカル検証結果

2026-08-31 に公式配布の seed 0〜99 と公式visualizerで確認しました。

| 指標 | 単純一様 baseline | この解法 |
|---|---:|---:|
| 100ケース合計 | 247,280 | 3,769,833 |
| 1ケース平均 | 2,472.80 | 37,698.33 |
| 勝/同点/負 | - | 100 / 0 / 0 |
| 各ケースの `sum(P_i)` 合計に対する割合 | 3.29% | 50.18% |

- 公式visualizer: seed 0〜99 の100件すべて合法
- 独自の行検査: 全出力が12行、各行13トークン、文字は `a`〜`f`、確率は0〜100、行和100
- 厳格コンパイル: `-Wall -Wextra -Wshadow -Wconversion -Wpedantic` で警告0
- ASan + UBSan: seed 0, 50, 99 で異常なし（実行環境の制約によりLeakSanitizerのみ無効化）
- Release版実行時間: 代表5ケースで0.63〜0.64秒、最大常駐メモリ約4.2 MB

得点は環境の速度により探索反復数が少し変わるため、再実行時に完全一致するとは限りません。合法性と「最後に厳密評価した候補を選ぶ」性質は変わりません。
