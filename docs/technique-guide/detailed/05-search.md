## D105. 展開回数で制限するDFS

小さな修復探索に時間をかけすぎないよう、展開した状態数で打ち切ります。処理量が比較的再現しやすい制限です。

予算300なら301個目を展開せず失敗として戻します。ただし1状態の処理費用が一定とは限らず、全体の実時間制限も別に必要です。

<a id="example-22075413-02"></a>
### コードでの具体例：時間ではなくノード数で修復を止める

DFSはremを展開ごとに減らし、区間修復では10×区間幅を予算にする。

**適用条件・落とし穴。** 1近傍の最悪計算時間を抑え、小修復へ均等に試行を割り当てる。

**検算と練習。** 早期returnで残った作業状態が次のbs・path初期化で確実に破棄されるか確認する。

出典: [AHC002 / 提出 22075413](https://atcoder.jp/contests/ahc002/submissions/22075413) · `dfs / dfs2` · L194–L228, L230–L268, L396–L423。 [収録情報](SOURCES.md#submission-22075413)

<a id="example-31233938-03"></a>
### コードでの具体例：修復DFSを300展開で止める

再帰のたびに回数を進め、上限を越えた候補は探索失敗として元の区間へ戻す。

**適用条件・落とし穴。** 修復近傍一回の予算を制御し、試行回数を確保する。

**検算と練習。** 上限到達のすべてのreturnで復元が成立するか試す。

## D110. ハッシュ重複排除と逆手禁止

すぐに1手前へ戻る操作や、より短い手順ですでに到達した状態を除くと、同じ場所を巡る探索を減らせます。

A→B→Aという往復は、多くの静的な最短手順問題では不要です。ただし履歴で条件が変わる問題では、盤面だけが同じでも同一状態ではありません。

<a id="example-32267675-06"></a>
### コードでの具体例：直前の逆移動を除き浅い同一状態を優先する

逆方向へ即戻る手を生成せず、状態ハッシュで既出深さを比較する。復元は親indexと最後の手で行う。

**適用条件・落とし穴。** 経路全体を子ごとにコピーせず探索できる。ハッシュ衝突には別対策が必要。

**検算と練習。** 復元した列の再実行と、ハッシュ一致時の盤面照合を確認する。

## D111. 差分履歴のビーム

ビームの候補ごとに状態全体を保存せず、親と変更内容だけ保存します。必要になったとき履歴を適用して状態を復元します。

盤面1000セルに対し変更が2セルなら、保存量を減らせます。一方、深い履歴の再生が遅い場合は途中の完全コピーを併用します。

<a id="example-40290839-06"></a>
### コードでの具体例：親IDと追加・削除セルだけを保存して状態を復元する

ビーム節点には親、追加ブロック、移管で消したセルを保持し、展開時に根から再生する。履歴データを連続バッファへ詰める。

**適用条件・落とし穴。** 状態コピーが大きいビーム探索。固定バッファの容量と復元コストは別途見積もる。

**検算と練習。** 再生した状態のハッシュ一致、最大バッファ使用量、展開時間を測る。

出典: [AHC019 / 提出 40290839](https://atcoder.jp/contests/ahc019/submissions/40290839) · `Recreate / BeamStep` · L896–L906, L985–L1015。 [収録情報](SOURCES.md#submission-40290839)

<a id="example-58801909-04"></a>
### コードでの具体例：目標節点への共通祖先まで戻って操作を再生する

現在の深さを戻し、親節点を再帰的に辿って必要な操作だけ適用する。各節点へ盤面全部を持たせない。

**適用条件・落とし穴。** 操作列の共通接頭辞が多いビーム。revertとapplyの完全な対称性が前提。

## D113. 周期長の拡張

同じ巡回を複製しただけでは平均的な訪問頻度は変わりません。複製後に各部分を別々に変更できることが利点です。

ABCをABCABCへ伸ばした後、片方だけABDCへ変えると、Dを2周に1回訪れる表現ができます。長い周期は選択肢と計算費用を増やします。

<a id="example-48359374-06"></a>
### コードでの具体例：最良巡回路を複製して訪問頻度の自由度を増やす

経路を複製して探索し、中間で最良経路へ戻した後さらに複製して低温の探索を続ける。単純複製そのものの平均費用改善ではなく、その後の不均等な訪問変更が狙いと読める。

**適用条件・落とし穴。** 短周期では訪問頻度比を表現しにくい巡回問題。経路長上限と探索速度の損失を考える。

**検算と練習。** 複製直後の平均費用不変と、再探索後の頻度・得点変化を確認する。

出典: [AHC027 / 提出 48359374](https://atcoder.jp/contests/ahc027/submissions/48359374) · `solve2` · L4420–L4447。 [収録情報](SOURCES.md#submission-48359374)

## D117. ビームの多様性

得点順だけのビームは似た候補で埋まりやすいため、候補の型ごとに残りやすさを変えます。

同じ粗い分類の1件目には大きい加点、2件目には小さい加点を与えます。異なる形を残す代わりに、元の評価が上位の候補を落とすこともあります。

<a id="example-60609745-04"></a>
### コードでの具体例：同じ粗い履歴キーの出現回数に応じてボーナスを減らす

候補を元の得点で並べ、同じキーの第k候補にbonus/kを与える。キーは一部の配置履歴だけで、完全状態の同一性ではない。

**適用条件・落とし穴。** 似た配置でビームが埋まりやすい場合。ハッシュ一致を厳密重複と取り違えない。

**検算と練習。** キー別候補数、実形状の多様性、最終得点を比較する。

出典: [AHC040 / 提出 60609745](https://atcoder.jp/contests/ahc040/submissions/60609745) · `bonus_map / hash` · L243–L272, L440–L449。 [収録情報](SOURCES.md#submission-60609745)

## D118. 粗い状態キーでの多様性制限

状態全体ではなく特徴の一部をキーにすると、似た候補をまとめて多様性を調整できます。

最新の層が同じでも過去の層が違えば、未来の選択肢も違う可能性があります。この統合は厳密な重複除去ではなく、探索幅を節約する近似です。

<a id="example-61871243-05"></a>
### コードでの具体例：最新層の集合だけで途中状態をまとめる

最新層の頂点XORをキーに評価の良い状態を残す。過去の層全体が一致するわけではないため、厳密重複除去ではない。

**適用条件・落とし穴。** 前線に将来の情報が多く集まる探索。過去に確定した頂点が異なる影響を捨てる近似である。
