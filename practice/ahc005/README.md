# AHC005 practice

公式問題: [A - Patrolling](https://atcoder.jp/contests/ahc005/tasks/ahc005_a)

`main.cpp` だけで提出できる、過去AHCを使ったライブラリ実戦例です。外部の
`.hpp` は参照せず、必要なパーツをすべて1ファイルへ貼っています。

## 問題の要点

数字 `5`〜`9` の道路だけを上下左右へ移動します。数字は「そのマスへ入る時間」です。
開始点から出発して開始点へ戻り、すべての道路を一度以上カメラから見えるようにします。

ある道路から、壁 `#` にぶつかるまで同じ横道・縦道にある道路が見えます。道路数を
`r`、見えた道路数を `v`、移動時間を `t` とすると、全道路が見えた場合の得点は
`round(10000 + 10000000 * N / t)` です。したがって、まず合法な閉路を作り、その後で
移動時間を短くするのが安全です。制限時間は3秒です。

## まず作れる安全解

道路グラフを開始点からDFSし、木の辺を「行き・帰り」の2回ずつ通れば開始点へ戻れます。
連結な全道路を実際に踏むので、可視性も必ず満たします。ただし道路の奥まで毎回入り、
同じ辺を多く往復するため、移動時間は長くなります。

`main.cpp` にはこのDFSを最終保険として残しています。後述する解を自前検査し、何か1つ
でも条件を満たさなければDFS解へ戻します。

## このコードの改善

### 1. 少数の監視点を選ぶ

各道路マスについて、そこから見える「最大の横道 + 最大の縦道」をbitsetで持ちます。
最初は開始点から見える道路を済みにし、まだ見えていない道路を最も多く見られるマスを
1つずつ追加します。これは単純な貪欲集合被覆です。

どの道路も自分自身からは必ず見えるため、候補が尽きることはありません。最後に、他の
監視点だけでも同じ道路をすべて見られる点を削除します。

### 2. 監視点の間を重み付き最短路で結ぶ

選ばれた各監視点からDijkstra法を1回ずつ行います。辺の重みではなく「移動先マスの
数字」を足す点に注意してください。最短距離だけでなく親も保存し、最後に `U/D/L/R`
の文字列を復元します。

### 3. 巡回順を短くする

開始点から近い未訪問点へ進むnearest neighborで初期順を作り、次を改善がなくなるまで
繰り返します。

- 2-opt: 巡回順の一区間を反転する
- relocate: 監視点を1個抜き、別の辺の間へ入れる

移動コストは一見有向ですが、監視点 `a, b` について
`dist(a,b) - cost(b) = dist(b,a) - cost(a)` です。そのため、この左右対称な値を使えば
通常の2-optの境界4辺だけで差分を計算できます。

### 4. 最短路が偶然見た道路も使う

監視点間の最短路は、途中にある横道・縦道も見ています。監視点を1個抜いて前後を
最短路で直結し、なお全道路が見える場合だけ削除します。削除後に巡回順を変えると、使う
最短路が変わって可視性を失う可能性があるため、この削除は巡回順改善の後に行います。

## 合法性が保たれる理由

1. 貪欲選択の終了時には、各道路が少なくとも1つの監視点から見えます。
2. Dijkstraで復元した経路は道路の上下左右移動だけです。
3. 監視点列の最後から開始点への最短路も連結するので、必ず開始点へ戻ります。
4. 監視点削除のたびに、実際に使う全最短路から全道路が見えるか再計算します。
5. 出力直前に移動、帰還、可視性をもう一度独立に検査します。

## 使用したパーツ

- 最大直線区間への分解
- 動的bitsetによる貪欲集合被覆
- 移動先コスト付きDijkstra法と最短路復元
- nearest neighbor
- 2-opt
- relocate
- 全道路DFS往復の安全解

いずれも `main.cpp` 内にあり、名前空間や設定ファイルは不要です。

## 使い方

```sh
g++ -std=c++17 -O2 -Wall -Wextra -Wshadow -pedantic main.cpp
./a.out < in.txt > out.txt
```

提出時は `main.cpp` の内容をそのまま提出します。公式Rust toolsで確認する場合は、toolsの
ディレクトリで次を実行します。

```sh
cargo run --release --bin vis in.txt out.txt
```

## 注意と次の発展

- 決定的な短時間解で、制限時間いっぱいの焼きなましは行いません。
- 監視点を先に選んでから順序を決めるため、選択と巡回を同時最適化する余地があります。
- 監視点数を `K`、道路数を `R` とすると、主な前計算は `K` 回のDijkstraです。
- 汎用化するなら、`weighted-grid-dijkstra.hpp`、`greedy-bitset-cover.hpp`、
  `tour-local-search.hpp` の3部品に分ける候補です。この練習では共有ライブラリを変更せず、
  初心者が1ファイルで追える形を優先しました。
