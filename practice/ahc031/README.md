# AHC031 practice

公式問題: [A - Event Hall](https://atcoder.jp/contests/ahc031/tasks/ahc031_a)

複数日ぶんの長方形を配置し、面積不足と、日をまたいで作り直す壁の長さを小さくする問題
です。`main.cpp` はローカルheaderを参照せず、そのまま提出できます。

## 問題の要点

- 会場は `1000 × 1000`
- 日数は `5 <= D <= 50`
- 1日あたりの予約数は `5 <= N <= 50`
- 同じ日の長方形は正の面積で重なってはいけない
- 要求面積より1不足するごとに100の費用
- 2日目以降は、前日と異なる内壁の単位長さだけ費用
- 絶対得点は `総費用 + 1` で、低いほど良い

面積不足は係数100なので、まず全予約へ十分な面積を渡し、その中で同じ壁を再利用する方針
が有効です。

## 解法

この実装は、表現力と壁の再利用しやすさが異なる複数の合法解を作り、公式費用を正確に
再計算して一番良いものを出します。

### 1. 安全な横一列baseline

各予約へ、幅1000の横長長方形を1本ずつ割り当てます。必要高さは
`ceil(要求面積 / 1000)` です。丸めの合計で高さが1000を超えた時は、失う面積が小さい
高さから削ります。

これは必ず合法ですが、日ごとに横壁が動き、空き面積が少ないcaseでは丸めによる面積不足
も生じます。最終版にも、他の構築が悪かった時のfallbackとして残しています。

### 2. 日をまたいで共通な帯をDPで選ぶ

予約をいくつかの横帯へ分け、同じ帯の中では長方形を左から右へ並べます。帯の高さを `H`
とすると、予約 `k` が必要とする幅は `ceil(a[d][k] / H)` です。

連続した予約集合ごとに、次の2種類の最小高さを二分探索します。

- 動的幅: どの日も、その日の必要幅の合計が1000以下になる高さ
- 固定幅: 各予約の全日最大幅を足しても1000以下になる高さ

固定幅を選べた帯は、長方形そのものを全日同じにでき、その帯の変更費用は0です。動的幅の
帯でも横壁は共通になり、縦壁だけが動きます。`位置 × 使用高さ` のDPで、合計高さ1000以下
かつ変更費用が最小の帯分割を選びます。

帯内順序は入力順、逆順、面積変動の小さい順を比較します。高さも最小値だけでなく少し大きい
候補を試します。高さを増やすと壁自体は長くなりますが、必要幅が安定して前日の壁を再利用
できる場合があるためです。

### 3. 日別の棚配置と、共通グループ・可変高さ

共通高さでは収まらないcase向けに、各日だけを見る棚DPも作ります。さらに、その日別DPで
現れた予約グループを全日に固定し、帯の高さだけを日ごとに変える候補も試します。

固定グループ候補には、等しい個数ごとの分割も加えます。良かった分割から壁を1本追加または
削除する局所探索を4回行います。候補は毎回最初から再構築するため、失敗した変更が状態へ
残りません。

### 4. 空きが少ない時の再帰guillotine分割

空き面積が数千しかない入力では、棚の整数丸めだけで全予約が入らないことがあります。
そこで会場を縦または横に二分し、予約集合も要求面積の比に合わせて二分する処理を再帰します。

各切断では、両側の要求面積を満たせる整数座標の範囲を先に求めます。縦・横と全ての分割位置
を試し、細長すぎず面積比に近い候補から再帰します。失敗状態は
`予約区間・高さ・幅` で記録して、同じ部分問題を解き直しません。

これにより、横一列では10,937,801点だった公式seed 34を553,405点まで下げられました。

### 5. 壁の費用を区間のまま正確に数える

長方形の辺を100万個のcellへ展開せず、同じ `x` または `y` 上の半開区間として保存します。
重なる区間をmergeし、前日と当日の区間の対称差長をtwo-pointerで数えます。

これは探索用の近似ではなく、公式の単位辺定義と同じ費用です。候補構築は近似的でも、最後の
候補選択は必ず本来の目的関数で行います。

## 使い方

```bash
g++ -std=c++17 -O2 main.cpp -o solver
./solver < input.txt > output.txt
./vis input.txt output.txt
```

比較用の横一列版は次で作れます。

```bash
g++ -std=c++17 -O2 -DAHC031_STRIP_BASELINE main.cpp -o baseline
```

| 共通帯DP | 534,352.6 |

| 可変高さの共通グループ | 188,833.3 |

最終版はこの10ケース全てでbaseline以下でした。

公式seed 0〜99の最終確認は次のとおりです。

## 計算量

予約数を `N`、日数を `D`、会場幅を `W=1000` とします。

- 帯の必要高さ前計算: おおよそ `O(D N^3 log W)`
- 高さ付き帯DP: `O(N^2 W × 1区間あたりの高さ候補数)`
- 日別棚・可変帯候補: おおよそ `O(D N^3 log W)`
- guillotine分割: 失敗状態をmemoし、実測では上記DPより軽い
- 1候補の正確な壁評価: `O(D(W + N log N))`

最大規模でも3種類の予約順を比較し、実測約1.3秒に収めています。

## 読む時の目印

- `make_strip_baseline`: 必ず出せる横一列解
- `minimum_band_height`: 全日共通帯の高さ二分探索
- `make_common_band_answer`: 高さ付き帯DP
- `make_day_shelf_answer`: 1日ずつの棚DP
- `make_variable_band_answer`: グループ固定・高さ可変の構築
- `make_guillotine_answer`: 面積比による再帰分割
- `calculate_cost`: merge済み壁区間の対称差

## 弱点と根拠

- 帯は棚型、guillotineは再帰切断型に限るため、一般の非slicing配置は表現できません。
- 帯の並びは3種類だけで、予約の大きな並べ替え探索は行っていません。
- 局所探索は壁1本の追加・削除だけです。帯間の予約移動や複数壁の同時変更には改善余地が
  あります。
- 公式問題文とvisualizerの面積不足・壁対称差を一次情報として確認しました。ローカル研究
  資料からは「日をまたぐ共通帯」「変更した日・帯だけを見る」「下界達成条件」の構造を
  参照し、実装と候補設計は新しく組み立てています。第三者提出コードは転載していません。
