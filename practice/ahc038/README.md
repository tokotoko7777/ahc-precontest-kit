# AHC038 - 長さの違う複数の指で運ぶ

## まず問題を小さく考える

最初の盤面と目標盤面が同じマスは、触る必要がありません。

- `S=1, T=0` のマス: たこ焼きを拾う場所
- `S=0, T=1` のマス: たこ焼きを置く場所

拾う場所と置く場所の個数は同じです。この solver は、前者から拾い、後者へ置くことだけを繰り返します。

## 腕の形

根を中心とする星型の腕を作ります。全頂点を根の子にし、辺の長さを
`1, 2, 3, ...` と全て変えます。

使う最大の長さは `floor(N/2)` です。この長さ以下なら、盤面上のどのマスにも、上下左右の少なくとも一方向から指を届かせられます。特に長さ1の指が必ずあるため、他の指の使い方が悪くても最後まで運び切れます。

長さが全て違う指は、同じ根から見た距離も違います。そのため、複数の指が同じターンに同じマスで `P` を実行して衝突することがありません。

## 次に行う仕事を選ぶ

各指について、次の候補を全て調べます。

- 空の指なら、まだ余っているたこ焼きのマス
- 保持中の指なら、まだ空いている目標マス
- そのマスへ届く4方向の腕の向き

ある候補へ移るのに必要な根の移動回数を `move`、90度回転の回数を `rotate` とします。移動と回転は同時にできるため、必要ターン数は

```text
max(move, rotate)
```

です。この値が最小の候補を次の仕事にします。

選んだ指を目的地へ運んでいる間も、他の指は休ませません。各ターンで左右どちらへ回せば拾う場所・置く場所に近づくかを調べ、通り道で操作できるマスがあれば同時に `P` を実行します。これが単腕版との差の大部分です。

## 1ターンの文字列の作り方

頂点数を `V'` とすると、各命令は長さ `2V'` です。

1. 先頭1文字に根の移動を書く。
2. 続く `V'-1` 文字に各指の回転を書く。
3. 後半 `V'` 文字に、各頂点の `P` または `.` を書く。

公式判定と同じく、先に移動と回転を適用し、その後の指先座標で拾う・置くを判定しています。

## 合法になる理由

- 根の移動先は常に盤面内です。腕や指先が一時的に盤外へ出ること自体は公式仕様で許されています。
- `P` は指先が盤面内で、空の指なら `S=1,T=0`、保持中なら `S=0,T=1` のときだけ出します。
- 予約した次の目的マスは、移動中に別の指が触らないようにしています。
- 各辺長は `1..N-1`、頂点数は入力の上限以下です。
- 操作数上限10万回に対し、公式100ケースの最大は2651回でした。

## 使い方

```bash
g++ -std=c++20 -O2 -pipe -Wall -Wextra -Wshadow main.cpp -o main
./main < input.txt > output.txt
```

提出には `main.cpp` だけを使います。ローカルライブラリや外部ファイルには依存しません。

比較用の「長さ1の指を1本だけ使う」単純版も、同じソースから作れます。

```bash
g++ -std=c++20 -O2 -DAHC038_BASELINE main.cpp -o main-baseline
```

## 計算量

指の本数を `A`、盤面のマス数を `N^2`、出力ターン数を `K` とします。次の仕事探しは1回あたり `O(A N^2)`、移動中の補助指の向き選びも素直な全マス走査です。全体はおおよそ `O(K A N^2)` です。

`N<=30`, `A<=14` と小さいため、複雑なデータ構造を使わなくても十分高速です。

## 公式ツールでの検証

公式配布の seed 0--99 全てを、完成版と単腕基準版の同じ入力で比較しました。全ケースで全てのたこ焼きを目標へ移したため、表の絶対スコアはそのまま操作ターン数です（小さいほど良い）。

| 方法 | 平均 | 最小 | 最大 |
|---|---:|---:|---:|
| 長さ1の単腕基準 | 2373.37 | 187 | 11032 |
| 長さ違いの星型腕 | **313.95** | **51** | **2651** |

完成版は100勝0分0敗で、平均ターン数を約86.77%削減しました。

seed 0--9 の完成版は
`51, 112, 593, 299, 71, 82, 537, 265, 1300, 159`
（平均346.90）、単腕版は
`187, 809, 3044, 834, 410, 301, 5314, 1633, 8770, 2105`
（平均2340.70）でした。

- 公式 visualizer: seed 0--99 が全て合法かつ完成
- strict compile: `-Wall -Wextra -Wshadow -Wconversion -pedantic` で警告なし
- ASan + UBSan: seed 0, 8, 42, 99 で指摘なし（実行環境の制約により leak detection のみ無効化）

実行時間はこの環境での参考値です。
