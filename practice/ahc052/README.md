# AHC052 練習用ソルバー

10 台のロボットを、共通のボタン列で動かして全マスを掃除する問題の提出用 `main.cpp` です。
このファイル単体でコンパイルでき、リポジトリ内のヘッダには依存しません。

## 問題の要点

- 盤面は `30 x 30`、ロボット・ボタンはそれぞれ 10 個です。
- 1 個のボタンに対して、ロボットごとに別々の `U/D/L/R/S` を設定できます。
- 設定表は開始前に固定し、実行中は同じボタンを全ロボットへ同時に送ります。
- 壁へ進もうとしたロボットはその場に残ります。
- 操作は最大 1,800 回です。
- 全 900 マスを掃除した場合の得点は `2700 - 操作回数` です。

## baseline

ボタン 0〜3 を、全ロボット共通の `U/D/L/R` にします。ロボット 0 だけに注目して盤面グラフを DFS し、木の辺を往復します。

連結な 900 頂点の木には 899 辺あるので、操作回数は必ず

```text
2 x 899 = 1798
```

です。上限 1,800 以下で、ロボット 0 が全マスを訪れることも保証できます。

baseline は次のように試せます。

```bash
g++ -std=c++17 -O2 -DBASELINE main.cpp -o baseline
./baseline < in.txt > out.txt
```

## 完成版の考え方

### 1. いろいろなボタン設定を作る

各ロボットについて、10 個のボタンに上下左右を最低 2 回ずつ入れてから、決定的な疑似乱数で並べ替えます。

これにより、同じボタンでも、例えばロボット 0 は右、ロボット 1 は上、ロボット 2 は左、という別々の動きができます。この設定表を 128 通り試します。

### 2. 未訪問マスへ近づくボタン列を選ぶ

現在の全ロボット位置と訪問済みマスをシミュレーションします。未訪問マスをすべて始点にした多始点 BFS で、各マスから最寄りの未訪問マスまでの距離を求めます。

次の 3 種類の作り方を試します。

- 1 手を評価して、その 1 手を使う
- 2 手先まで評価して、最初の 1 手だけ使う
- 3 手をまとめて評価し、その 3 手を使う

候補は次の順に比較します。

1. 数手の間に新しく掃除できるマス数
2. 早い時刻に掃除できるマス数
3. 最後の各ロボットと未訪問マスとの距離
4. ロボット同士が同じ位置に重ならず、散らばっている数

1 台ずつ目的地を決める必要はなく、「この共通ボタンを押したら全体でどれだけ得か」を直接比較しているのがポイントです。

### 3. 最後に短くする

最も短く全マスを掃除できた設定と列を残し、次を試します。

- 操作を 1 個削除
- 隣り合う 2 操作を別の 1 操作へ置換

変更後は必ず最初から全ロボットを動かし直し、900 マスすべてを掃除できた場合だけ採用します。

候補がうまく全掃除できなかった場合も、最初の DFS baseline を残してあるので不完全解を出力しません。

## コンパイルと実行

```bash
g++ -std=c++17 -O2 -Wall -Wextra -Wshadow -Wconversion -pedantic \
  main.cpp -o main
./main < in.txt > out.txt
```

公式ツールでの確認例です。

```bash
cargo run --release --bin vis in.txt out.txt
```

乱数の初期値はソース内で固定しているため、同じ入力には毎回同じ出力になります。

## 検証結果

公式配布の seed 0〜99 を、baseline と完成版の両方で採点しました。

| 版 | 合法 | 平均スコア | 中央値 | 最小 | 最大 | 平均操作数 |
|---|---:|---:|---:|---:|---:|---:|
| DFS baseline | 100 / 100 | 902.00 | 902 | 902 | 902 | 1,798.00 |
| 完成版 | 100 / 100 | 2,439.70 | 2,440 | 2,379 | 2,464 | 260.30 |

- 同一 seed の勝 / 分 / 敗: `100 / 0 / 0`
- 完成版の合計スコア: `243,970`
- 完成版の操作数範囲: `236〜321`
- 100 ケース wall time: `139.61` 秒
- 1 ケース平均: `1.396` 秒
- 最大実行時間: `1.636` 秒（seed 56）
- strict compile: 警告なし
- ASan + UBSan: seed 0, 42, 99 で異常なし
- sanitizer 時の公式スコア: `2,436`, `2,448`, `2,426`

## 合法性の確認ポイント

- 設定表は必ず `K x M = 10 x 10` 個出力します。
- 操作番号は常に `0 <= button < K` です。
- DFS baseline が 1,798 手なので、必ず操作上限以下の完全解を保持できます。
- 完成版を採用するときも、全操作を再生して900マス訪問済みであることを確認します。
- 後処理は操作数を減らす変更だけなので、1,800 手を超えません。
- 壁移動は事前計算した `next_cell` だけを使い、公式仕様どおり壁なら現在地のままにします。
