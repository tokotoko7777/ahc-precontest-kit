# AHC046 練習解答: Skating with Blocks

提出するのは [`main.cpp`](./main.cpp) だけです。ローカルのヘッダやライブラリには依存していません。

## 問題を短く整理

20 × 20 の盤面で、40 個の地点を入力順に訪れます。使える操作は次の3種類です。

- `M`: 隣の1マスへ移動
- `S`: 壁か岩の直前まで滑る
- `A`: 隣のマスの岩を置く、または取り除く

最大操作数は1600です。全地点を訪問した場合のスコアは `1640 - 操作数` なので、操作数を減らすほど良くなります。

注意点は、滑っている途中で目的地を通っても訪問にはならないことです。目的地で停止する必要があります。

公式問題文: <https://atcoder.jp/contests/ahc046/tasks/ahc046_a>

## 解法

まず、岩を一切使わず、各目的地へ縦横に1マスずつ移動する答えを作ります。1区間は最大38手、区間は39個なので、最大でも `38 × 39 = 1482` 手です。これは必ず1600手以内に収まる安全な答えです。

そのうえで、次の探索を行います。

1. 現在の岩配置で、次の目的地までの最短路をBFSで求める。
2. 次の目的地の上下左右それぞれについて、そこへ岩を1個置いてから目的地へ向かう経路も調べる。
3. 岩配置、ここまでの操作数、操作列を1つの状態として持つ。
4. 同じ岩配置なら、操作数が最小の状態だけを残す。
5. 現在までの操作数と、残り全区間の推定操作数の和で並べ、上位128状態を残す。

目的地そのものには岩を置きません。また、岩を置くための寄り道中は、次の目的地へ先に停止しないようBFSで禁止しています。これにより、探索が想定する訪問順と実際の判定がずれません。

置いた岩は、その目的地へ到達するときだけでなく、後の区間でも滑走の停止点として再利用できます。目先の最短路だけではなく残り全区間を見るのは、この再利用価値を評価するためです。

最後に、探索解が移動だけの安全解より短い場合にだけ探索解を出力します。

## コードの読みどころ

- `make_stop_table`: 各マスから4方向へ滑った停止先を先に計算
- `run_bfs`: 実際の操作列を復元できるBFS
- `shortest_distance`: 将来評価専用の軽量BFS
- `beam_search_answer`: 岩を置くかどうかを比較するビーム探索
- `move_only_answer`: 必ず合法な基準解兼フォールバック

岩配置は400ビットで保持しています。難しいクラス分割や独自namespaceは使わず、1ファイル内の小さな関数に処理を分けています。

## コンパイルと実行

```bash
g++ -std=c++20 -O2 -Wall -Wextra -Wshadow -Wconversion -Wpedantic main.cpp -o main
./main < in.txt > out.txt
```

移動だけの基準解は、同じファイルを次のようにコンパイルすると出せます。

```bash
g++ -std=c++20 -O2 -DMOVE_ONLY_BASELINE main.cpp -o baseline
./baseline < in.txt > baseline.txt
```

公式ツールでは次のように確認できます。

```bash
cargo run --release --bin vis in.txt out.txt
```

## 検証結果

公式配布ツールに同梱された seed 0〜99 を使用しました。両方式を同じ100入力で比較しています。

| 方式 | 平均操作数 | 平均Score | Score合計 | 不正出力 |
|---|---:|---:|---:|---:|
| 移動のみ | 511.23 | 1128.77 | 112877 | 0 / 100 |
| この解法 | 207.44 | 1432.56 | 143256 | 0 / 100 |

- 勝 / 分 / 敗: 100 / 0 / 0
- 操作数削減: 平均59.42%
- Score改善: 平均26.91%
- 探索解の最小 / 最大操作数: 184 / 229
- 通常版の実測時間（seed 0〜9）: 平均1.156秒、最小1.03秒、最大1.31秒
- strict warning付きコンパイル: 警告なし
- AddressSanitizer + UndefinedBehaviorSanitizer: seed 0〜9で異常なし

サニタイザ実行環境ではLeakSanitizerとptraceが競合したため、`ASAN_OPTIONS=detect_leaks=0` とし、アドレス違反・未定義動作の検査を行いました。
