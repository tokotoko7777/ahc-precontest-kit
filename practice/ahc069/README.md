# AHC069 練習解答: コンパクト配置 + 少数グループの再配置

`main.cpp` だけで提出できる、自己完結した C++17 の練習解答です。独自の
`namespace` やローカルライブラリは使っていません。状態は `Solver` クラスにまとめて
ありますが、提出時に別ファイルを参照する必要はありません。

この解答はかなり発展的です。最初から全行を理解しようとせず、まず「普通に置く部分」
まで読み、最後に「既存グループを動かす部分」へ進むのがおすすめです。

## 問題を短く言うと

- 50×50 の公園へ、1000 組のグループが時刻順に来るオンライン問題です。
- グループ番号 `i` は `0, 1, ..., 999` の順に届くため、コード中の `turn` と一致します。
- 到着したグループには、空いている芝生をちょうど `P` マス、4 近傍連結で渡します。
- 形の周長を `L` とすると、コンパクトさは `C = 4√P / L` です。
- 料金は `round(V * C)` です。ただし途中で移動した場合も、過去を含む最大周長で
  最終料金が決まります。一度悪い形にすると、後で良い形へ戻しても帳消しにはなりません。
- 既存グループの移動には `max(round(VR), 1)` の費用がかかります。
- 各到着を見てから置くか断るかを決めます。未来の入力を先読みできません。

つまり、目先の料金だけでなく、未来のグループが使えるまとまった空間を残す必要が
あります。

## まず動かす

GCC 系コンパイラを想定しています。`__int128`、GCC の属性と pragma を使うため、
`-pedantic` は付けていません。

```bash
g++ -std=c++17 -O2 -Wall -Wextra -Wshadow -Wconversion -Werror \
    main.cpp -o main
```

公式ツール一式のディレクトリでは、次のようにローカルテストできます。

```bash
target/release/tester ./main < in/0000.txt > out.txt
target/release/vis in/0000.txt out.txt
```

Rust 版ツールをまだビルドしていない場合は、公式 README と同じく次でも構いません。

```bash
cargo run -r --bin tester ./main < in/0000.txt > out.txt
cargo run -r --bin vis in/0000.txt out.txt
```

AHC069 は対話型です。ソルバを単独で `./main < in/0000.txt` と実行するのではなく、
必ず tester を間に入れてください。

## 最小の合法ベースライン

次のどちらかを定義すると、すべての到着を断るだけのベースラインになります。

```bash
g++ -std=c++17 -O2 -DSIMPLE_BASELINE main.cpp -o baseline
target/release/tester ./baseline < in/0000.txt > baseline-out.txt
```

`-DBASELINE` も同じ意味です。各ターンで移動数 `0` と `No` を返して必ず flush するため、
スコアは 0 ですが合法です。オンライン出力の書き方だけを確認したいときに使えます。

## 初心者向けの作り方

自分で一から作るなら、次の順に機能を足すと理解しやすいです。

1. 全拒否ベースラインを通し、入出力を確認する。
2. `P` マスの準長方形を探し、空いていれば置く。移動はまだしない。
3. `V / (P(T-S))` が低いグループを断り、未来の空間を買う。
4. 配置後の空き連結成分も評価し、細い通路や小さな端切れを作りにくくする。
5. 最後に、高価値の到着だけ既存グループの再配置を試す。

この `main.cpp` は、その 5 段階目を高速化・安全化したものです。

## 1 ターンの流れ

中心は `Solver::run()` です。到着ごとに次を行います。

1. `release_before(S)` で、到着時刻より前に帰ったグループを盤面から消す。
2. `prepare_free_state()` で空きマスの連結成分と各種 prefix sum を作り直す。
3. `find_small_component_placement(P)` で、使い道の少ない小島をぴったり消費できるか調べる。
4. 小島でなければ `is_low_value()` で明らかに低価値な到着を早く断る。
5. `find_placement(P)` で通常配置を探す。
6. `acceptance_threshold()` と比較して、今この空間を使う価値があるか決める。
7. さらに得なら `find_move_plan()` で少数の既存グループを動かす案を探す。
8. `validate_move_plan()` で盤面を最初から再現して合法性と費用を確認し、
   `commit_move_plan()` で確定する。
9. 回答を出力して flush する。

探索が時間切れに近づいたら、候補評価を段階的に安くします。最後は新しい到着を断るだけに
切り替え、対話の返答を欠かさないようにしています。

## 盤面の持ち方

`owner[cell]` の意味は単純です。

| 値 | 意味 |
|---:|---|
| `-2` | 池、または最初に使用不可と決めたマス |
| `-1` | 空いている芝生 |
| `0` 以上 | その番号のグループが使用中 |

`Group` は `P, V, S, T`、現在のマス、過去最大周長、移動費を持ちます。
退去予定は終了時刻をキーにした priority queue で管理します。

初期化時の `close_three_sided_pond_pockets()` は、3 方向を池に囲まれた芝生を再帰的に
使用不可にします。そこへ形を伸ばすと細い袋小路になりやすいため、最初から容量として
数えない割り切りです。また、初期連結成分が 4 マス未満なら、どのグループにも使えません。

## 普通の配置候補

`find_placement()` は主に 2 種類の形を集めます。

### 準長方形

`rectangle_candidates(P)` は高さ `h` を全て試し、幅を `ceil(P/h)` とします。
余ったマスは四隅の細い帯から削るので、ちょうど `P` マスで連結な形になります。
池が長方形の内側にあっても、池と外周の削りを合わせて `P` マスにでき、連結性を確認できる
場合は候補に含めます。

長方形に近いほど周長が小さくなり、料金が高くなります。矩形内の障害物数などは 2 次元
prefix sum で調べるため、全配置をかなり速く走査できます。

### 連結 growth

`choose_growth_seeds()` で盤面の端、連結成分内の特徴点、中心付近などから開始点を選び、
`grow_from_seed()` で隣接マスを 1 マスずつ足します。準長方形が障害物に阻まれた場合にも、
入り組んだ空き領域を使えます。

### 候補の評価

まず安い評価で絞り、異なる形を最大 8 個だけ詳しく調べます。主な項目は次です。

- `compactness`: 周長が小さいほど高い。
- `weighted_contact`: 外壁や、終了時刻が近い既存グループへ接するほど高い。
  近い時刻にまとめて空く領域を作り、盤面の穴あきを減らす狙いです。
- `future_usability`: 仮置き後の空き連結成分が、将来の `P` 分布に対して使いやすいほど高い。
- `packing_pressure`: 小さい到着では、多くの将来長方形を置ける貴重なマスを使うほど減点する。

どれか 1 項目だけで決めず、コンパクトさを主成分にした小さな重み付き和で選びます。

## 受け入れるか断るか

置けることと、置くべきことは別です。

`is_low_value()` は

```text
V / (P * (T - S))
```

を見ます。1 マスを 1 時間占有するあたりの基礎価値が低すぎる到着は、重い形状探索の前に
断ります。ただし、初期から孤立した 4〜20 マスの小島をちょうど有効利用できる場合と、
未来を残す必要がない最後の到着は例外です。

`acceptance_threshold()` は、観測済みの平均滞在時間と `P`、現在の利用量、残り到着数を
使って空間の機会費用を見積もります。未来時間を複数 bucket に分け、既存グループがいつ
帰るかも加味します。予想料金密度がこの閾値以上なら通常配置を受け入れます。

## 既存グループを動かす探索

移動は高価なので、普通に置くより利益が増える可能性があるときだけ試します。

1. `enumerate_move_targets()` が、到着グループ向けのコンパクトな目標領域を列挙する。
2. 目標領域と重なる既存グループを blocker として集める。
3. 安い上界評価で 512 件まで残し、通常上位に加えて空間的に離れた候補も残す。
4. `move_target_has_component_capacity()` が、blocker を外した後の空き連結成分へ
   各 blocker の面積を詰め直せそうか、容量だけの高速 proxy で調べる。
5. blocker が原則 3 組以下の候補について、`relocation_candidates()` が実際の移動先を作る。
6. 移動費と、過去最大周長が悪化することで失う料金を両方引く。
7. 通常配置より十分良い案だけ採用する。

blocker が 1 組で、その移動先がさらに別グループに塞がれる場合は、安いグループを順に
逃がす短い連鎖も限定的に探索します。非常に価値の高い大グループには、事前に作った大型
slot を使う別経路もあります。

容量 proxy は「面積的に入りそう」と言うだけで、形や重なりまでは保証しません。そのため
採用直前に `validate_move_plan()` が、現在の盤面から移動対象だけを外した scratch 盤面へ
全移動を置き直します。ここで
マス数、連結性、重複、対象 group、移動費、料金損失が一致しなければ案を捨てます。

## 高速化で効いているもの

- 50×50 を 1 次元の `cell = x*N+y` として持つ。
- 矩形内の障害物数、接触量、移動優先度を 2 次元 prefix sum で得る。
- BFS の `visited` を毎回消さず、整数 stamp を進めて再利用する。
- 2500 マス以下と分かる配列は固定長 scratch にして再確保を減らす。
- 同じ候補形を 64-bit hash で除く。
- `round(V * 4√P/L)` は最後に `__int128` の不等式で補正し、浮動小数点の境界誤差を防ぐ。
- process CPU time に 1.52〜1.92 秒の段階 deadline を置き、重い移動、通常候補、
  詳細評価の順に止める。

速度のための定数は冒頭へ集めています。まずアルゴリズムを読むときは deadline 定数を
飛ばして構いません。

## 検証結果

2026-08-31 に公式配布の seed 0〜99 を tester で確認しました。比較用ビルドは元プロジェクトの
`build_fast.sh` と同等の設定を使い、seed ごとに kit と元の現行 `main.cpp` の実行順を
交互にしています。100 ケースすべて `status=ok`、emergency なしでした。

主指標の分母は、保存済みの全 `scores.tsv` から次だけを採用して再構成した、共通の最新
100-seed 履歴best vectorです。

- `status=ok`
- emergency なし
- 実時間 2 秒以下
- diagnostic / extended / 30 秒系列ではない

この再構成方法で、元 `BENCHMARK.md` の最新 5 版の値を小数 6 桁まで再現してから、同じ
分母で今回の 2 版を計算しました。元プロジェクトを読み取り専用に保つため、`runs.tsv`、
`best.tsv`、`BENCHMARK.md` 自体は更新していません。

| version | historical relative / 10000 | 平均best比 | raw sum | wall median | wall max |
|---|---:|---:|---:|---:|---:|
| 全拒否 baseline | 0.000000 | 0.000000% | 0 | 0.030s | 0.030s |
| 元の現行 `main.cpp` | 9731.649505 | 97.316495% | 7,249,580,897 | 1.240s | 1.650s |
| この `main.cpp` | **9816.738085** | **98.167381%** | **7,317,697,797** | **1.210s** | 1.650s |

主指標では `+85.088580 / 10000`、平均best比で `+0.850886` percentage point です。
raw sum は `+68,116,900`、約 `+0.940%` でした。

2 版だけの per-seed max を分母にした補助診断では、この版 `9977.939811`、現行版
`9892.212163 / 10000`、勝/分/敗は `75/0/25` です。これは比較相手によって分母が変わる
ため、採否の主指標にはしていません。

実行を同居プロセスに一時停止されたと見られる 2 秒超の wall 異常値が初回に 6 件ありました。
該当ケースを単独で再実行すると全て 2 秒未満となり、スコアも完全一致したため、表はその
正常時間へ置き換えた値です。この版の平均 wall は 1.204 秒、最大 RSS は 27,496 KiB でした。

採用元の保存済み repairable-lane 100 ケース記録を、今回と同じ最新履歴bestで再集計すると
`9821.980754 / 10000`、raw sum `7,321,518,861` です。今回の fresh run はそれより
`-5.242669 / 10000`、raw `-3,821,064` でした。100 件中 78 件は完全同点で、勝/分/敗は
`6/78/16` です。アルゴリズムは同じですが、この解答では独自 namespace を外したことで
linkage が変わり、さらに探索が CPU deadline に依存するため、過去の binary と全 seed で
同じ探索量になるとは限りません。差を隠さず fresh 値を正式な教材版の結果としています。

### 追加の安全確認

- C++17、`-Wall -Wextra -Wshadow -Wconversion -Werror` で通常版と baseline をコンパイル。
- 通常版 seed 0000 は tester と visualizer の両方で合法、visualizer score `62,806,633`。
- baseline は seed 0〜99 の全てで合法、全て score 0。
- ASan + UBSan で seed 0000, 0042, 0099 を実行し、メモリエラー・未定義動作・tester error なし。

sanitizer 版は計測負荷で CPU deadline に早く達するため、そのスコアは性能比較には使って
いません。

## 出典と作り方

採用元は、このプロジェクト内に保存されていた
`benchmark/repairable_move_lane_slim_20260809.cpp` です。無効な実験分岐を削除した版で、
保存時点では元の frozen strongest と前処理後コード・主要 binary section が一致すると
検証されていました。この教材版では、単一 `main.cpp` のまま次だけを整理しています。

- 独自の匿名 namespace を除去
- `SIMPLE_BASELINE` / `BASELINE` を追加
- C++17 strict warning で指摘された暗黙変換を明示
- 冒頭へ提出用ファイルであることを追記

設計を読み解く際は、ローカル知識集から「コンパクトな非重複配置」「不可逆な受理判断の
機会費用」「空間×時間の容量管理」「再配置コスト」の関連 review だけを参照しました。
レビュー内の外部評価値は根拠が不明なものとして採否に使っていません。第三者コードの転記も
していません。
