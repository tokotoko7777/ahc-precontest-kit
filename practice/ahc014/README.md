# AHC014 A - RectJoin

公式問題: <https://atcoder.jp/contests/ahc014/tasks/ahc014_a>

`main.cpp` だけで提出できる、合法性を優先した初心者向けの解答例です。外部の `.hpp` や自作 namespace は使っていません。

## 使い方

```bash
g++ -std=c++17 -O2 -Wall -Wextra main.cpp -o main
./main < input.txt > output.txt
```

AtCoder へは `main.cpp` をそのまま提出できます。

## 問題を簡単に言うと

- 最初からいくつかの格子点に点がある。
- 既存点3個と空いている点1個で、軸平行または45度傾いた長方形を作る。
- 長方形の4辺の途中に別の点があってはいけない。
- 以前に描いた辺と、長さが正の部分を重ねてはいけない。一点で交差するだけならよい。
- 新しく置いた点も、次の長方形からは既存点として使える。
- 中心から遠い点ほど重みが大きいので、追加点の重みの合計を大きくしたい。

何も操作しない `K = 0` も必ず合法です。このコードも、万一最後の再検査に失敗した場合は `K = 0` に戻ります。

## 解法

### 1. 盤面

`Board` は次を持ちます。

- `has_point`: その座標に点があるか
- `used_edge`: その座標から8方向へ出る単位線分を既に使ったか
- `moves`: 今までに採用した長方形
- `added_weight`: 新しく置いた点の重みの合計

線分を格子点間の「単位線分」に分けて記録するため、公式 checker と同じ条件で辺の重なりを判定できます。

### 2. 合法候補を列挙する

新しい点を `p0`、その対角の既存点を `p2` とします。`p2` から直角な2方向を見て、最初に見つかる既存点を `p1`, `p3` とすると、

```text
p0 = p1 + p3 - p2
```

で残りの頂点が決まります。

合法な長方形では各辺の途中に点がないので、`p1`, `p3` は必ず各方向の最初の点です。したがって、全既存点について8方向を調べれば合法候補を漏らしません。最後に `can_apply` で、点・直角・45度・途中点・使用済み辺をすべて再確認します。

空き座標から3点組を全探索するより候補が小さく、1回に作る候補は高々「現在の点数 × 8」個です。

### 3. 複数の貪欲を試す

候補の評価には、次の考え方を異なる割合で混ぜた6式を使います。

- 新しい点の重みが大きい候補を優先する。
- 周長が短く、将来の辺を塞ぎにくい候補を優先する。
- `重み / 周長` や `重み / 周長²` を使う。

最初に6種類の決定的貪欲を作り、最良を保存します。その後は上位2〜8候補から少しランダムに選び、最初から何度も作り直します。乱数 seed は入力から作るので、同じ入力なら基本的に同じ探索になります。

同じ入力では公式得点の初期点・分母が固定なので、`added_weight` が大きい解を選ぶことは、公式得点が大きい解を選ぶことと同じです。

### 4. 最後に全手を再検査する

保存した最良解を初期盤からもう一度適用します。一手でも不合法なら空解を返します。通常探索でも各手を検査していますが、提出事故を避けるための二重チェックです。

## 高速化している箇所

- 全3点組ではなく「対角点 × 8方向」から候補を作る。
- 点と辺を1次元の連続した配列に置く。
- 辺の8方向を `unsigned char` で保持する。
- 全候補を完全 sort せず、必要な上位だけ `partial_sort` する。
- 公式得点を毎回計算せず、追加点の重みだけ差分加算する。
- 再検査は保存した最良解に対してだけ行う。

## 改良するとしたら

この例は分かりやすい multi-start 貪欲であり、追加済み長方形を取り消す局所探索は入れていません。そのため、序盤の短い辺が後の高得点長方形を塞ぐ局所最適から抜けられない場合があります。

次の発展が考えられます。

- 後ろから数手を取り消して、別の貪欲で作り直す destroy / repair
- 点や辺が変わった近傍だけ候補を更新する差分候補 cache
- 即時得点だけでなく、その点から次に作れそうな長方形数も評価する
- 入力サイズや残り時間に応じて評価式の選択率を変える

合法性に関わる `can_apply` と `apply` は触らず、まず `priority` と候補の選び方だけを変更するのが安全です。

## 参照した研究メモと独自性

一次情報として公式問題文と公式 tools の checker を確認しました。ローカル knowledge corpus は、構造検索の後に AHC014 Review と関連する次の3項目だけを参照しました。

- candidate restriction
- incremental evaluation
- destroy / repair

AHC014 Review には「合法候補 cache、重み付き貪欲、削除と再構築、方向別辺占有」が有効だったという確認済みの要約があります。本実装はそこから問題構造だけを参考にし、第三者コードは転載せず、より単純な全候補再列挙 + multi-start を独自に実装しています。destroy / repair と差分 cache は未実装です。
