# AHC003: 山登りフォーマットによるオンライン推定、5回比較

2026-09-19。局所探索の基本フォーマットを、経路そのものではなく**未知辺コストの推定**に使用。
同じTimeBasedAnnealingRunnerを山登りモードで呼び、観測誤差を差分更新する。
推定後の経路はDijkstraで選ぶ。方式別テンプレートや専用Runnerは増やしていない。

## 条件・主指標

[公式問題](https://atcoder.jp/contests/ahc003/tasks/ahc003_a)は30×30グリッドで1000回の経路要求に答え、
ノイズ付きの経路総和から未知辺長を学ぶ対話問題。制限時間は2秒。
内部目的は負の正則化付き二乗誤差だが、**採否は公式の経路スコア**で決めた。
真の辺長・未来クエリ・乱数ノイズはsolverへ渡していない。

公式生成器seed 0〜9で開発し、事前に選んだ20〜39で設定固定後の確認をした。
各ケース各版1回、実行順を交互にして逐次測定。C++17 O3 NDEBUG。
測定中に別のbuild/solverを実行しない。
公式tester・visualizer・独立した全経路検査と採点の3つを照合した。
時間はtester＋solverの壁時計時間で、2秒超過・失敗は0点とする保守的な計測。

主指標は入力SHAごとの合法・時間内の過去最高を共通分母とする
`sum(100 * score / best)`。今回の全候補を含み、leave-one-outにはしない。
開発10件で1000点、確認20件で2000点。平均公式scoreは補助指標。

## 5回の開発比較

| 回 | 候補 | 対照 → 候補 /1000 | 平均比率 | 判定 |
|---|---|---:|---:|---|
| 1 | 履歴を使う正則化モデルの座標山登り（64試行/観測） | 971.861 → 996.193 | 97.1861% → 99.6193% | 採用 |
| 2 | 64→256試行/観測 | 996.193 → 998.003 | 99.6193% → 99.8003% | 採用 |
| 3 | 行・列の補正を固定2区間→4区間 | 998.003 → 996.752 | 99.8003% → 99.6752% | 不採用 |
| 4 | 256→1024試行/観測 | 998.003 → 997.088 | 99.8003% → 99.7088% | 不採用 |
| 5 | 探索ボーナス係数1.65→0.80 | 998.003 → 996.528 | 99.8003% → 99.6528% | 不採用 |

第4回はモデル内の最適化を多く回しても経路スコアが下がった。
探索数や近似目的の改善だけでは採用しない、という判定例。
行動が変わると後続の観測も変わるので、単なる過学習だけが原因とは断定しない。
固定試行数・固定乱数により、今回繰り返した同一版の開発得点は一致した。
ただし1クエリの安全時間上限もあるため、全環境での完全再現は保証しない。

| 第1・2回を採用 | 2000.000000 | 100.000000% | 978,810,163.75 | 20 / 0 / 0 |

平均scoreは+3.0679%。開発100出力＋確認40出力、計140,000クエリは全件合法。
公式tester・visualizer・独立採点は全件一致。確認のtester込み最長実時間は0.160秒未満。
共通分母比100%は**今回比較した版のケース別最高**で、公式満点や1位ではない。
統計的有意差・公式順位相当は主張しない。同一ケース集合の1位データは取得していない。
確認後の追加チューニングはしていない。

## Problemへ書く内容

| 型・関数 | 役割 |
|---|---|
| State | 行/列・区間・辺固有の補正係数、観測ごとの予測cache |
| Move | 変更する係数1個、変更量、計算済みの改善量 |
| observe | 返却された経路総和だけを履歴へ追加し、新観測の目的値変化を返す |
| propose_move | 1係数について二次目的の最小点を計算する |
| evaluate_move | 絶対得点ではなく、負の正則化誤差の改善量を返す |
| apply_move | 係数と、その係数が含まれる観測の予測値だけ差分更新 |
| planning_costs | 推定平均から探索ボーナスを引き、正の辺コストを作る |
| 共通Runner | 山登り採否・時間・現在/最良State。問題固有モデルは知らない |

特徴量から観測を逆引きして、毎近傍で全1000観測を走査しない。
事前分散、特徴量の分け方、ノイズ重みはProblem側の判断で、汎用ヘッダには固定しない。
固定2区間は真の変化点を直接推定するものではない。
複数Kalman/MCMCの第三者提出コードの移植ではなく、フォーマット上の独自実装。

## 検証・再現

- 100観測×64近傍で差分を全再計算、予測cacheを特徴量内積と照合。ASan/UBSanも成功。
- 5候補のpatch復元SHAとmanifestを照合。保存時の共通分母集計も再計算。
