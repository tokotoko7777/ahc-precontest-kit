## D001. 実現可能性を保つ外側表現

探索が動かす「予約枠」と、実際に出力する形を分けます。予約枠どうしが重ならなければ、その内側に収めた形も重なりません。

例えば幅10の枠の中に幅7の長方形を置きます。枠の境界だけ調整すれば、内部の長方形の位置や面積は別の小問題として決められます。

<a id="example-20926292-02"></a>
### コードでの具体例：担当領域と出力長方形を分ける

外側の非重複領域の幅高さから、点を内包する実長方形を別に求める。

**適用条件・落とし穴。** 制約を外側の分割に担わせ、内側の品質改善を独立化する。

**検算と練習。** 復元矩形が担当点を含み、領域外へ出ず、目的値と一致するか確認する。

出典: [AHC001 / 提出 20926292](https://atcoder.jp/contests/ahc001/submissions/20926292) · `RR::size / makeCs` · L147–L168, L775–L789。 [収録情報](SOURCES.md#submission-20926292)

## D002. 番兵境界

端に達したかを毎回分岐で調べる代わりに、端の外側に「必ず止まる相手」を置きます。これが番兵です。

例えば列の最後に通過不能な要素を1つ足せば、右へ進む処理は通常の停止条件で終われます。番兵も配列の有効範囲内に確保する必要があります。

<a id="example-20926292-07"></a>
### コードでの具体例：盤面外の4領域を隣接走査の番兵にする

盤面の左・右・下・上へ仮想領域を置き、境界方向の走査を必ず停止させる。

**適用条件・落とし穴。** 境界分岐を減らせるが番兵を通常の候補更新へ混ぜない。

**検算と練習。** 四隅・端の領域で走査停止と配列外参照を検査する。

出典: [AHC001 / 提出 20926292](https://atcoder.jp/contests/ahc001/submissions/20926292) · `init` · L943–L950。 [収録情報](SOURCES.md#submission-20926292)

## D003. 資源IDによる訪問管理

制約がかかる単位と、画面上の場所が一致するとは限りません。禁止状態は制約の単位で管理します。

例えばセルAとBが同じタイル7に属するなら、Aを使った時点でビット7を立てます。Bを未訪問でも、同じ資源を再使用することは防げます。

<a id="example-22075413-03"></a>
### コードでの具体例：セルではなくタイルIDをbitsetで禁止する

経路セルのA値をbit位置に使い、同じタイルの別セルも同時に使用禁止とする。

**適用条件・落とし穴。** 複数の位置が同じ資源を共有する経路制約へ使える。

**検算と練習。** 同じIDの隣接・非隣接セルを含む小例で二重使用を検査する。

出典: [AHC002 / 提出 22075413](https://atcoder.jp/contests/ahc002/submissions/22075413) · `bs / bbs` · L188–L199, L323–L327, L363–L366。 [収録情報](SOURCES.md#submission-22075413)

## D004. 通路群への縮約

途中に選択肢がない通路は、端点間のつながりとしてまとめられます。探索を「1歩ずつ進む」処理から「どの通路を巡るか」へ移します。

例えば長さ20の直線通路を毎回20セル処理せず、交差点どうしの1辺として扱います。最後に元の歩行列へ展開できる情報は残します。

<a id="example-24829216-01"></a>
### コードでの具体例：セル経路を通路群の代表点巡回へ置き換える

縦横両方向へ進める交点を頂点にし、連続した縦・横通路ごとに選べる交点リストを持つ。

**適用条件・落とし穴。** 同じ通路内なら同じ被覆効果を持つ問題で、訪問順と代表点を分ける。

**検算と練習。** 元盤面の必要な通路がすべて代表群へ含まれることを確かめる。

## D005. ペアIDと逆位置

対応する2要素に連続した偶数・奇数のIDを付けると、相方は最下位ビットの反転で求められます。

注文3の集荷を6、配送を7とすれば、6 xor 1は7です。さらに位置の逆引き表を持つと、順番を交換した後でも相方の現在位置を直接調べられます。

<a id="example-27260278-01"></a>
### コードでの具体例：偶奇で集荷・配送を表しxorで相方を引く

注文tの集荷を2t、配送を2t+1にし、xs[i]^1の現在位置を逆表から取る。

**適用条件・落とし穴。** 先行制約付きペアを頻繁に変更する列状態へ使う。

**検算と練習。** 移設・反転・入替後に全要素の逆位置が一致するか確認する。

## D006. 番兵付き一次元盤面

二次元座標を一次元に詰め、周囲を壁で囲むと、上下左右への移動を定数の加減算にできます。

幅32なら、右は+1、下は+32です。ただし行の右端から次行へ回り込まないよう、外周の番兵を正しく配置します。行幅は実盤面幅とは別に決めます。

<a id="example-29654603-01"></a>
### コードでの具体例：32幅へ埋め込み隣接を定数加算で引く

座標をx<<5とyで符号化し、外周を壁にして±32・±1で隣接を求める。

**適用条件・落とし穴。** 小盤面の探索で境界分岐を減らす。番兵の外へ連続移動しない設計が必要。

**検算と練習。** 四辺・四隅の隣接アクセスと座標復元を確認する。

出典: [AHC008 / 提出 29654603](https://atcoder.jp/contests/ahc008/submissions/29654603) · `pos / x / y / bfs` · L1120–L1134, L1183–L1219。 [収録情報](SOURCES.md#submission-29654603)

## D007. 状態に方向と多重使用を持つ

同じ場所にいても、向きや使用回数が違えば、その後にできることが変わります。将来に影響する情報を状態へ残します。

例えば同じ交差セルへ北から入った場合と西から入った場合を同一視すると、可能な出口を取り違えます。位置だけの訪問済み判定では不十分です。

<a id="example-31233938-01"></a>
### コードでの具体例：セルだけでなく出方向と使用回数を記録する

閉路を座標・方向の列にし、二重カーブは使用数1と2で異なる接続制約を課す。

**適用条件・落とし穴。** 交差を許す経路で通常のvisited boolでは足りない場合に使う。

**検算と練習。** 交差セルの二回目使用が既存経路を壊さないか確認する。

出典: [AHC010 / 提出 31233938](https://atcoder.jp/contests/ahc010/submissions/31233938) · `path_info / tile_use_count` · L300–L313, L355–L369, L433–L449。 [収録情報](SOURCES.md#submission-31233938)

## D008. 探索空間の構造制限

自由度を減らすと、探索が簡単になる一方、表現できない良い解も生まれます。この交換条件を意識して状態を設計します。

例えば任意角度の切断を縦横だけに限定すれば、座標列だけで区画を作れます。ただし斜めの切断が必要な配置には届かなくなります。

<a id="example-32961594-01"></a>
### コードでの具体例：自由な直線を水平・垂直の座標列へ限定する

二方向のソート済み切断座標と盤面両端を持ち、すべての領域を矩形として扱う。

**適用条件・落とし穴。** 表現の制限で評価を軽くする設計。斜線が必要な最良解は探索外になる。

**検算と練習。** 切断本数と領域数の関係、端点を含む出力合法性を確認する。

出典: [AHC012 / 提出 32961594](https://atcoder.jp/contests/ahc012/submissions/32961594) · `xs_ / Helper::get` · L397–L427, L431–L438。 [収録情報](SOURCES.md#submission-32961594)

## D009. 個数で重み付けしたヒストグラム

ヒストグラムに「対象の個数」を入れるか「対象が持つ量」を入れるかで意味が変わります。

3点入りの区画が2個なら、区画数は2、点の質量は6です。質量を持つ表から区画数を求めるときは3で割ります。この単位を混ぜると評価の重みが変わります。

<a id="example-32961594-03"></a>
### コードでの具体例：領域数ではなく領域に入る点数を加算する

点がcnt個ある領域はhisto[cnt]へcntを加える。評価時にcntで割り戻す成分と質量距離の成分を使う。

**適用条件・落とし穴。** 分布の総質量をそろえて比較するときの表現。通常の頻度表と混同しない。

**検算と練習。** ヒストグラム総和が全点数と一致するか確認する。

## D010. 可逆な操作履歴

取り消し可能かどうかは、動かした本人の履歴だけでは決まりません。他の操作が同じ場所を後から使っていないかも必要です。

Aが場所xを空け、Bがxへ入ったなら、Aだけを戻せません。個体ごとの履歴と場所ごとの履歴を照合し、依存が残っていない操作から戻します。

<a id="example-34085279-01"></a>
### コードでの具体例：個体別とセル別の二重スタックで移動の依存を表す

各PCの経路と各セルを通ったPCの順を持ち、直前セルのスタック頂上が自分のときだけ逆移動する。逆移動を新しい移動として数えない。

**適用条件・落とし穴。** 操作列に依存がある配置探索向け。座標だけ戻しても合法な履歴にはならない。

**検算と練習。** 移動と逆移動後に盤面、履歴、移動回数が全一致するか確認する。

出典: [AHC013 / 提出 34085279](https://atcoder.jp/contests/ahc013/submissions/34085279) · `State::Move / Revert` · L1830–L1873, L1970–L2043。 [収録情報](SOURCES.md#submission-34085279)

## D011. 置換不変性

頂点番号を付け替えただけで答えが変わると、構造を学ぶはずの処理が番号に依存します。番号に依存しない集約を使います。

例えば各頂点の特徴を足し合わせる操作は、足す順番を入れ替えても同じです。ただし頂点ごとの中間表現は番号に合わせて並び替わるため、最終出力の不変性と区別します。

<a id="example-36660262-01"></a>
### コードでの具体例：隣接と非隣接を別マスクにする注意機構

次数・ノイズ率・頂点数の埋込みから特徴を作り、隣接辺と非隣接辺を分けたattentionと残差更新を繰り返す。頂点和のheadも持つ。

**適用条件・落とし穴。** 頂点番号がランダムに置換されるグラフ識別。番号そのものに依存する特徴を入れない。

**検算と練習。** 頂点順をシャッフルし、頂点特徴の並び替えと集約特徴の不変性を検査する。

出典: [AHC016 / 提出 36660262](https://atcoder.jp/contests/ahc016/submissions/36660262) · `op_attention / NpModel.forward` · L492–L577。 [収録情報](SOURCES.md#submission-36660262)

## D012. 制約を満たす状態空間

絶対に使えない候補を最初に消せば、以後の探索は有効な候補だけを扱えます。

例えば立体の上面投影で禁止された列にあるセルは、別の投影が許していても使えません。候補集合は各制約の共通部分ですが、残った候補を選ぶだけで全要求を満たすわけではありません。

<a id="example-40290839-01"></a>
### コードでの具体例：2投影が許す立方体だけを連番へ圧縮する

両方の投影が1である座標だけをcell_idへ登録し、6方向の隣接IDを前計算する。存在不可能なセルは最初から候補にしない。

**適用条件・落とし穴。** 複数の外部制約の交差で候補を絞れる復元問題。投影を満たすことと全投影を覆うことは別に管理する。

**検算と練習。** 全登録セルの投影適合と隣接の逆向き対称性を確認する。

出典: [AHC019 / 提出 40290839](https://atcoder.jp/contests/ahc019/submissions/40290839) · `Prepare` · L213–L250。 [収録情報](SOURCES.md#submission-40290839)

## D013. 構築器の入力を探索

完成した答えそのものではなく、答えを作る手順への入力を探索します。複雑な整合性は構築器へ任せます。

例えば利用する施設の集合だけを決め、半径と接続路は毎回作り直します。変更変数は少なくなりますが、構築器が作れない形の答えには到達できません。

<a id="example-42196314-01"></a>
### コードでの具体例：基地局の有効集合だけを反転し半径と辺を再構築する

局を1つ反転し、被覆半径を決め直し、半径0の局を落としてから接続辺を構築する。生成された実費用から受理を決める。

**適用条件・落とし穴。** 結合した設計変数を全部同時に近傍化しにくい問題。内側構築器の偏りが探索空間を制限する。

**検算と練習。** 集合固定で内側構築のばらつきと、直接半径探索との差を確認する。

出典: [AHC020 / 提出 42196314](https://atcoder.jp/contests/ahc020/submissions/42196314) · `main` · L1364–L1435。 [収録情報](SOURCES.md#submission-42196314)

<a id="example-47308761-01"></a>
### コードでの具体例：山の前処理順を探索変数にする

最小番号を含む山から処理する初期順を作り、順序の区間反転ごとに初期状態から全操作列を再生成する。

**適用条件・落とし穴。** 操作列の直接探索が難しい並べ替え問題。構築器の決定性・乱択性も評価のばらつきに影響する。

**検算と練習。** 同じ処理順の複数試行と、順序変更による差を分けて測る。

出典: [AHC026 / 提出 47308761](https://atcoder.jp/contests/ahc026/submissions/47308761) · `main / best_seq` · L655–L704。 [収録情報](SOURCES.md#submission-47308761)
