## D256. 区間最適値の表引き

何度も同じ形の区間最適化を行うなら、事前に値を計算し、問い合わせだけを軽くできます。

高さ3〜8の中で最良の寸法を毎回6通り調べる代わりに、区間最小を引く表を使います。要求値が変われば前計算の作り直しが必要か確認します。

<a id="example-20926292-01"></a>
### コードでの具体例：高さ区間の最良寸法を定数時間で引く

要求面積ごとに高さ別の最適幅と損失を作り、左右累積最小と最上位相違bitで区間最小を取得する。

**適用条件・落とし穴。** 小さい整数の内側最適化を表へ移せる。単なる面積一致表より、制約付き区間問い合わせまで前計算する。

**検算と練習。** 小さい全幅・高さで総当たりと最適損失・復元寸法を比較する。

出典: [AHC001 / 提出 20926292](https://atcoder.jp/contests/ahc001/submissions/20926292) · `RR::init/get/size` · L107–L163。 [収録情報](SOURCES.md#submission-20926292)

## D257. 不可能な遷移の削除

入力だけで不可能と分かる遷移は、探索のたびに弾かず、隣接表へ最初から入れません。

同じタイルの別セルへの移動が禁止なら、その辺を初期化で除きます。探索中に状態によって変わる禁止条件まで固定して消さないようにします。

<a id="example-22075413-07"></a>
### コードでの具体例：同じタイルへの隣接辺を初期化で除く

境界内の4近傍のうち、同じタイルIDへ移る辺は隣接表へ登録しない。

**適用条件・落とし穴。** 毎回同じ無効条件を探索ループ外へ出す。

**検算と練習。** 全隣接表を元の盤面条件で再判定し、必要辺の欠落がないか確認する。

出典: [AHC002 / 提出 22075413](https://atcoder.jp/contests/ahc002/submissions/22075413) · `Solver::init` · L472–L489。 [収録情報](SOURCES.md#submission-22075413)

## D258. 接尾辞接頭辞の重なり

文字列Aの末尾とBの先頭が重なる長さを求めれば、連結時に増える長さをすぐ計算できます。

ABCとBCDはBCが重なるので、ABCDへまとめられます。全ペアの相性を保存すると、隣接交換や挿入の差分評価にも使えます。

<a id="example-23751222-02"></a>
### コードでの具体例：文字列の連結増分と相性リストを作る

全ペアで最大の接尾辞・接頭辞一致長を求め、前後に置く候補を重なり順に保持する。

**適用条件・落とし穴。** 文字列列挙を順列探索へ変換し、連結長を辺コストにできる。

**検算と練習。** 空の重なり・全文字一致・片方向だけ一致する組を比較する。

出典: [AHC004 / 提出 23751222](https://atcoder.jp/contests/ahc004/submissions/23751222) · `addr / d / bnext / bprev` · L111–L113, L299–L314。 [収録情報](SOURCES.md#submission-23751222)

## D259. 最短路と復元の同時保存

最短距離だけでは、最後に具体的な移動列を出せません。経路復元の情報も一緒に用意します。

AからBまで距離5と分かっていても、上下左右のどの列かは別情報です。経路を全部保存するか、親だけ保存して後で戻すかで容量と復元費用が変わります。

<a id="example-24829216-02"></a>
### コードでの具体例：交点間距離と移動文字列を一緒に作る

各交点からDijkstraし、到着セルの費用で距離更新すると同時に移動文字列も保存する。

**適用条件・落とし穴。** 探索は距離表だけ、最終出力は保存経路の連結で行う。文字列コピーのコストには注意する。

**検算と練習。** 復元経路の費用がCと一致し、隣接・壁制約を満たすか確認する。

出典: [AHC005 / 提出 24829216](https://atcoder.jp/contests/ahc005/submissions/24829216) · `dij / C / walk` · L224–L255, L184–L193。 [収録情報](SOURCES.md#submission-24829216)

## D260. 同型類の表引き

番号だけ違う同じ構造を代表形へ写すと、多くの入力を共通の表で扱えます。

頂点名A,B,Cを1,2,3へ付け替えても同じ三角形なら、同じ代表IDを使います。番号の付け替えで変わらない性質かどうかを確認します。

<a id="example-36660262-03"></a>
### コードでの具体例：観測ビット列を同型代表に写してラベルを引く

観測辺を整数化し、分割保存された同型類配列から代表IDを取得、そのIDで識別bookを参照する。

**適用条件・落とし穴。** 全状態または同値類を事前列挙できる小規模問題。2の辺数乗の規模増大に注意する。

**検算と練習。** 全順列で同型代表が一致することと、テーブルのサイズ・索引境界を確認する。

出典: [AHC016 / 提出 36660262](https://atcoder.jp/contests/ahc016/submissions/36660262) · `solve_small_N` · L706–L726。 [収録情報](SOURCES.md#submission-36660262)

## D261. 保守的な集合縮約

複数の要求をまとめるとき、平均ではなく最悪側の必要量を残すと、全要求を満たす条件を保てます。

施設から距離3と7の顧客を1群にするなら、必要半径は7です。ただし全員を同じ施設で扱う制限により、別々に割り当てる良い解を失う場合があります。

<a id="example-42196314-04"></a>
### コードでの具体例：近い顧客群を局ごとの最大必要半径へまとめる

近い顧客をまとめ、各局までの距離の最大値を代表群の必要半径とする。代表点の平均距離ではなく全員を覆う半径を保持する。

**適用条件・落とし穴。** 似た制約が多数ある被覆。群全体を同じ局へ割り当てる制限による損失がある。

**検算と練習。** 縮約後の半径で元顧客が全員覆われるかと費用増を確認する。

出典: [AHC020 / 提出 42196314](https://atcoder.jp/contests/ahc020/submissions/42196314) · `r_dist / r_home2node` · L1290–L1318。 [収録情報](SOURCES.md#submission-42196314)

## D262. 尤度の表引き

観測値と候補値が小さな整数範囲なら、尤度を全組合せで計算して表へ保存できます。

0〜1000の2変数なら約100万要素です。反復で指数関数などを呼ばずに済む一方、要素型とキャッシュに収まるかが実時間へ影響します。

<a id="example-44783436-05"></a>
### コードでの具体例：温度の全ペアについて確率密度を前計算する

1001×1001の尤度を平坦配列に格納し、観測位置選択の二重候補ループでは表引きする。

**適用条件・落とし穴。** 離散観測値の種類が小さい場合。約100万要素の初期化時間とメモリも予算に入れる。

**検算と練習。** 直接密度計算との誤差、起動費用、照会回数の損益分岐を測る。

出典: [AHC022 / 提出 44783436](https://atcoder.jp/contests/ahc022/submissions/44783436) · `memo_prob_dens` · L2960–L2971, L3034–L3040。 [収録情報](SOURCES.md#submission-44783436)

## D263. 局所位相の表引き

周囲8セルの内外だけで判定できる条件なら、状態数は2^8=256通りです。全てを調べて表にできます。

実行中は周囲を8ビットへ詰めて参照するだけです。局所の表が全体の連結性をどこまで保証するかは、表の作成条件とは別に確認します。

<a id="example-45441612-02"></a>
### コードでの具体例：各セルの周囲8ビットから反転の可否を引く

壁を含む3×3局所グラフごとに256通りを列挙し、中心を加えても局所連結成分数が変わらないパターンを保存する。

**適用条件・落とし穴。** 全域の連結性検査を局所的な十分条件で置き換えたい場合。許す近傍を狭める可能性がある。

**検算と練習。** 許可された反転後に全域flood fillを行って不変条件を確認する。

## D264. 重なりと内部DP

連続する単語の重複部分を打ち直さず、残った文字列の移動だけをDPで解きます。

ABCの後へBCDを続けるなら、重複BCを再利用してDだけ追加できる状況を考えます。文字の同一性と盤面上の位置の選択を合わせて評価します。

<a id="example-49255792-02"></a>
### コードでの具体例：接尾辞と接頭辞の重なりを飛ばして残り文字の最短費用を前計算する

最大重複長から必要文字数を求め、各文字の全出現位置間でDPする。すべての末尾状態間の費用を平坦配列へ格納する。

**適用条件・落とし穴。** 短い文字ブロックを多数連結する問題。完全同一語など必要文字数0の扱いは確認が必要。

**検算と練習。** 小例で位置の全列挙とDP結果を比較する。

出典: [AHC028 / 提出 49255792](https://atcoder.jp/contests/ahc028/submissions/49255792) · `need / min_scores` · L769–L796, L881–L904, L1051–L1066。 [収録情報](SOURCES.md#submission-49255792)

## D265. 遅延生成する確率表

使う可能性のある表を全部作ると大きすぎる場合、初めて必要になった組合せだけ計算して保存します。

観測セル数kと真の合計sごとに分布を作る例です。確率へ下限を設ける処理は数値を安定させますが、元の分布を少し変えることになります。

<a id="example-50447114-04"></a>
### コードでの具体例：観測セル数と真の合計に応じた分布を必要時だけ作る

単点は確定値として扱い、集合観測は正規分布の区間積分で離散化し、確率の下限を設ける。

**適用条件・落とし穴。** 同じ観測条件が反復される推定。近似分布と真の生成モデルの差を把握する。

**検算と練習。** 確率和、端点の裾、モンテカルロ頻度との誤差を確認する。

出典: [AHC030 / 提出 50447114](https://atcoder.jp/contests/ahc030/submissions/50447114) · `ProbTable::lazy_init` · L1828–L1858。 [収録情報](SOURCES.md#submission-50447114)

## D266. 可換操作の組合せ

操作の順序を入れ替えても同じ結果なら、並び順の違いを重複列挙する必要はありません。

A,B,Bを使う候補はABBだけ列挙し、BABやBBAを省きます。順序が意味を持たない範囲にだけ適用し、同じ操作の複数回使用は残します。

<a id="example-52156995-01"></a>
### コードでの具体例：同じ位置のスタンプを非減少ID列で列挙する

加算順に意味がないので次IDを前ID以上に限定し、同じ多重集合の順列を重複列挙しない。9セルの合計と元の操作IDを保存する。

**適用条件・落とし穴。** 局所操作が可換な組合せ探索。重複使用を許すので同じIDも選べる。

**検算と練習。** 小mで全操作列を集合化した結果と比較する。

出典: [AHC032 / 提出 52156995](https://atcoder.jp/contests/ahc032/submissions/52156995) · `dfs13` · L250–L274。 [収録情報](SOURCES.md#submission-52156995)

## D267. 経路のメモ化

入力が同じ副問題を何度も解くなら、結果を保存して再利用します。失敗した結果も再計算を防ぐ情報になります。

同じ訪問列に対する最適な運搬量と費用を保存します。経路以外に評価を変える入力があるなら、それもキーへ含めます。

<a id="example-54643130-03"></a>
### コードでの具体例：同じ訪問列の最小費用流を再計算しない

訪問列全体をキーに最適費用と操作列を保存し、不可能判定もキャッシュする。

**適用条件・落とし穴。** 経路削除で同じ候補へ戻りやすい探索。キー比較・メモリ費用があるため命中率が低いと損する。

**検算と練習。** 命中率、キャッシュ容量、流計算の削減時間を測る。

出典: [AHC034 / 提出 54643130](https://atcoder.jp/contests/ahc034/submissions/54643130) · `static map dp` · L2652–L2653, L2676–L2694。 [収録情報](SOURCES.md#submission-54643130)

## D268. 変更時だけ再計算

キャッシュは毎回更新する必要も、永遠に有効なわけでもありません。依存する状態が変わった時点で無効化します。

グループの頂点集合を変えたら連結性の表を捨て、次に必要になった時だけ計算します。変更を取り消す場合は旧表を戻す選択肢もあります。

<a id="example-57377353-02"></a>
### コードでの具体例：非関節点の集合を区間ごとにキャッシュする

区間変更後だけ非関節点キャッシュを無効化し、次にその区間を触るときLowLinkを再実行する。棄却なら旧キャッシュも戻す。

**適用条件・落とし穴。** 同じ局所グラフに何度も問い合わせる探索。空集合を未計算の印にも使う設計には注意。

**検算と練習。** キャッシュ版と毎回LowLinkを実行する版の判定を比較する。

出典: [AHC036 / 提出 57377353](https://atcoder.jp/contests/ahc036/submissions/57377353) · `nart_A / LowLink` · L1006–L1009, L1061–L1062, L1082–L1084。 [収録情報](SOURCES.md#submission-57377353)

## D269. 部分木の到達可能性

複雑な部品の到達範囲は、葉から親へ情報を合成して前計算できます。

先端の指が届くセル集合を回転候補ごとに親へ渡せば、途中関節を決めた段階で残りの最大到達範囲を引けます。障害物や仕事状態への依存を区別します。

<a id="example-58801909-01"></a>
### コードでの具体例：関節位置ごとに各指が届く仕事セルをビット集合にする

葉から親へ4方向の回転候補を伝播し、指ごと・関節位置ごとに届く搬出元/搬入先を前計算する。

**適用条件・落とし穴。** 固定長の木型ロボットで姿勢候補を多数列挙する場合。関節構造を変えたら表を作り直す。

**検算と練習。** 小さい腕の全姿勢列挙と到達集合を比較する。

出典: [AHC038 / 提出 58801909](https://atcoder.jp/contests/ahc038/submissions/58801909) · `CalcReach` · L1148–L1187。 [収録情報](SOURCES.md#submission-58801909)

## D270. 部分集合の形だけ先計算

選択する「位置の組合せ」は、そこへ入る数値が変わっても同じです。その形だけを先に列挙します。

10個から3個選ぶマスクは120通りです。反復中は各マスクの立った位置の値を足すだけになり、組合せ生成の費用を再利用できます。

<a id="example-69285442-03"></a>
### コードでの具体例：要素数とpopcount別のマスクを再利用する

値とは独立な固定個数マスクを用意し、反復中は立っているビットの値だけ加算する。

**適用条件・落とし穴。** 同じサイズの部分集合探索を何度も解く場合向け。サイズ12未満・枚数5未満の表範囲を守る。

**検算と練習。** 毎回マスク生成する版と時間・メモリを比較する。

## D271. 数値関数のテーブル化

入力範囲が小さく決まる高価な関数は、表引きへ置き換えられます。

距離の平方根や人数の逆数を保存する例です。距離を整数へ丸めて表を引く場合は量子化誤差が入り、乱数表の再利用では周期性も生じます。

### コードでの具体例：平方根・逆数・正規乱数を探索前に用意する

整数化した距離の平方根と人数逆数を参照し、時刻変更には保存した正規乱数を使う。

**適用条件・落とし穴。** 頻繁な数値演算の代替。距離を100で割る量子化やテーブル範囲を含め精度を確認する。

**検算と練習。** 直接計算版との差と反復速度を測る。
