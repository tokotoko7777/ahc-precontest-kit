# 17. 時間予算・フェーズ制御

[詳細編の目次](README.md) · [用語](GLOSSARY.md) · [出典一覧](SOURCES.md)

説明用の小例と、提出コードで確認した具体例を分けて記載しています。適用効果は未測定で、検算と練習はこれから確かめるための課題です。

## D301. 多段階探索とbest復帰

初期解を広く試す段階と、良い初期解を大きく揺らして磨く段階を分けます。

揺らした後の改善が失敗したら保存した最良へ戻れば、完成度を保ちながら再挑戦できます。探索中の現在解と全期間の最良解を別々に管理します。

### コードでの具体例：初期解再生成とkick探索を時間で分ける

前半1.2秒は構築し直し、後半4.9秒まではkick後にbest改善しなければ保存解へ戻す。

**適用条件・落とし穴。** 初期解の多様化と局所盆地からの脱出を別予算にする。

**検算と練習。** best復帰で境界順・逆位置・個別損失を含む全状態が一致するか確認する。

## D302. モデル選別と計算予算

複数モデルを維持すると推定は柔軟になりますが、残りの各ターンにも更新費用がかかります。

今1回の更新が軽くても、残り1000回なら総費用は大きくなります。将来分を見積もり、信頼度の低いモデルから減らす判断を行います。

**適用条件・落とし穴。** 履歴増加で1更新が重くなるオンライン推定を最後まで走らせる。

**検算と練習。** 最悪のモデル数・観測数で終了時刻を測り、早すぎる枝刈りの精度低下も測る。

**適用条件・落とし穴。** 温度なしの停滞脱出。単要素操作の非悪化性に依存する箇所を切り分ける。

**検算と練習。** 現状態のscoreとcur、保存bestのscoreが各採否後に一致するか確かめる。

## D304. 時刻と温度更新の間引き

終了確認と温度更新は同じ頻度である必要がありません。必要な精度に応じて別々に間引きます。

時計は256回ごと、温度はそのさらに数回に1回だけ更新する形です。終了の遅れと、温度の段差が探索へ与える影響を別々に確認します。

<a id="example-27260278-07"></a>
### コードでの具体例：終了確認256回、温度更新32768回ごと

時計を読む頻度と温度を更新する頻度を別々に抑え、温度は開始終了値の指数補間にする。

**適用条件・落とし穴。** 高速な近傍で管理コストが相対的に大きいときに使う。

**検算と練習。** 最も重い近傍を連続実行した場合も締切超過しないか測る。

**検算と練習。** 切替直後に評価キャッシュの整合性を確認し、時間配分を比較する。

## D307. 入力別の専用化

入力規模や観測ノイズで、適した表現サイズや推定方法が変わる場合があります。

小さな状態は表引き、大きな状態は特徴量による推定へ分ける例です。切替表の範囲外や境界で、未定義の組合せにならないか確認します。

**適用条件・落とし穴。** 得点式に問題サイズの費用がある設計問題。表の出所や最適性はコードだけでは保証できない。

**検算と練習。** 境界条件を網羅し、未学習のノイズ条件でも選択が妥当か比較する。

## D311. 形状候補の選抜

腕の長さが違う3形状を軽く探索し、結果と前処理費用を見て残時間を配ります。試走得点だけでなく、その後に拡張できる探索量も判断材料です。

<a id="example-58801909-05"></a>

盤面サイズに対応する腕と隣接サイズの腕を試し、前処理時間・探索時間を測る。最良形の追加探索幅を残時間から決める。

**適用条件・落とし穴。** 構造設計と操作計画の両方が必要な問題。既存表の形が最適と保証するものではない。

**検算と練習。** 各形の可達範囲、探索速度、最終手数を比較する。

## D314. 入力別の戦略選択

入力の密度や種類数により、1本の探索と分割探索を選びます。

空きが少ない盤面では部分解を先に退避する方が進みやすい、といった仮説を分岐へ落とします。少数の入力だけで決めた閾値に依存しすぎないよう確認します。

<a id="example-74935244-01"></a>
### コードでの具体例：密度・盤面サイズ・色数から探索構成を選ぶ

密度の閾値と表で単方向探索か二段探索を選び、二段の分割比率も0.75・0.625・0.5から切り替える。

**適用条件・落とし穴。** 入力分布で得意戦略が異なる場合向け。表が別分布にも最適とは限らない。

**検算と練習。** 入力条件別に全戦略を比較し選択表の頑健性を測る。

## D317. 処理進捗による予算調整

処理済み件数から予定上の時刻を求め、実際に先行しているか遅れているかで追加探索量を変えます。

半数の案件を予定より早く処理できたなら、後続の高価値案件へ救済探索を多めに使います。案件ごとに費用が違う場合、件数だけの進捗は近似です。

### コードでの具体例：処理件数から予定時刻を引き、救済探索の試行数を変える

**適用条件・落とし穴。** 大量のオンライン問い合わせを総時間内に捌く用途。線形な予定配分と案件難易度のずれに注意する。

**検算と練習。** 案件別時間と高価値案件への配分を記録する。
