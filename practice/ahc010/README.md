# AHC010 practice

公式問題: [A - Loop Lines](https://atcoder.jp/contests/ahc010/tasks/ahc010_a)

`main.cpp` だけで提出できる、過去AHCを使ったライブラリ実戦例です。外部の `.hpp` は
参照せず、必要な部品を1ファイルへ直接置いています。

## 問題の要点

30×30枚の線路タイルを0〜3回、反時計回りへ90度ずつ回します。出力は各マスの回転回数を
行優先に並べた、長さ900の文字列です。最長の環状線の長さを `L1`、2番目を `L2` とすると
得点は `L1 * L2` です。環状線が1本以下なら0点になります。

タイルは次の3種類として考えると分かりやすくなります。

- `0`〜`3`: 1本の曲線。入った向きから必ず左右どちらかへ曲がる
- `4`, `5`: 2本の曲線。同じタイルを別々の2本の線路が通れる
- `6`, `7`: 1本の直線。入った向きの反対側へ出る

枝分かれはないため、1本の線路を入口の向きごとに追えば、盤外へ出る経路か環状線の
どちらかになります。公式の制限時間は2秒です。

## まず作れる安全解

`0` を900文字出せば、全タイルを回転しない合法解になります。得点は低くても、文字数や
回転範囲を間違えない基準として便利です。

もう一段だけ進めるなら、2×2の4マスがすべて曲線タイルである場所を探します。4枚を
正方形の辺に沿うように回すと、長さ4の環状線を必ず1本作れます。このコードは最初に
その候補を全部集めます。正式な入力条件はこの正方形が2個あることまでは保証しないため、
最後まで候補が足りなければ全回転0へ安全に戻せる形にしています。

## このコードの改善

### 1. 盤面を半分に分ける

2本とも盤面全体で探すと、長い候補同士が同じマスを奪い合います。そこで、次の4領域で
独立に環状線候補を作ります。

- 上半分
- 下半分
- 左半分
- 右半分

上と下、または左と右から1本ずつ選べば、マスが重ならない長い2本を自然に作れます。

### 2. 入口から出口を決めながらランダムDFSする

開始マスで入口と最初の出口を決め、隣のマスへ進みます。各マスでは、直線なら次の向きは
1通り、曲線なら2通りです。同じマスを2度使わないようにしてDFSし、開始状態へ戻れた
経路を環状線候補として保存します。

1回のDFSは展開数を600〜2999回に制限します。失敗した探索が長時間止まらず、別の開始点を
数多く試せます。入力文字列から乱数seedを作るため、同じ入力では探索傾向も再現できます。

### 3. 2本を安全に組み合わせる

各領域の長い候補を180本まで残し、使用マスを `bitset<900>` で比較します。共通マスが
なければ、その2本はそのまま共存できます。

タイル `4`, `5` だけは2本の曲線を持つため、同じマスを2本が通ることも許します。ただし、
次の3条件をすべて満たす場合だけです。

1. 2本が要求するタイル回転が同じ
2. 入口・出口の2方向が重ならない
3. 共通マスが二重曲線タイルである

この確認により、2本が同じ線路へ合流することを防ぎます。

### 4. 必要な回転回数を表から逆算する

候補上の各マスでは、前のマスの方向が入口、次のマスの方向が出口です。元のタイルを
0, 1, 2, 3回と順番に回し、公式の `to[tile][entry] == exit` を満たす最初の回数を出力へ
書き込みます。使わないマスは0回のままです。

### 5. 出力前に公式得点を再計算する

公式visualizerと同じ入口状態の走査を `score_output` に実装しています。作った解と全回転0を
最後に比較し、低い方は出しません。探索中の重い処理には使わず、最後の2案だけを完全評価
するため高速です。

## 選んだ環状線が壊れない理由

1. 候補中の連続2マスは必ず上下左右に隣接します。
2. DFSは曲線で曲がり、直線で直進するため、各マスには必要な回転が存在します。
3. 最後のマスから開始マスの入口へ戻ることを確認してから候補にします。
4. 同じマスを使う2本は、二重曲線の別々の線路だけに限定します。
5. タイルには分岐がないため、閉じた線路は周囲の未使用線路によって途中から壊れません。

なお、この問題では得点0でも、長さ900かつ各文字が `0`〜`3` なら出力自体は合法です。

## 使用したパーツ

- `Timer`: `steady_clock` の経過時間
- `Random`: 軽量なSplitMix64乱数
- 展開数上限付きランダムDFS
- `bitset<900>` による候補の衝突判定
- タイル回転・入口・出口の遷移表
- 公式得点の自己計算
- 入力hashによる乱数seed固定

独自の名前空間や設定ファイルはありません。

## 高速化した箇所

- 盤面、経路使用中フラグ、タイル状態を固定長配列にする
- DFSの時刻確認を256展開ごとに間引く
- 候補を領域ごとに上位180本へ制限する
- 2候補の共通マス有無を `bitset` のANDで先に判定する
- 回転遷移を8×4の小さな表にする
- 完全な閉路列挙は出力直前の2回だけにする

## 使い方

```sh
g++ -std=c++17 -O2 -Wall -Wextra -Wshadow -pedantic main.cpp
./a.out < in.txt > out.txt
```

提出時は `main.cpp` の内容をそのまま提出します。公式Rust toolsで確認する場合は、toolsの
ディレクトリで次を実行します。

```sh
cargo run --release --bin vis in.txt out.txt
```

## 公式入力での確認

公式配布のseed 0〜99を `-O2` で各1回実行し、公式visualizerで採点しました。

- 不正出力または0点: 0 / 100ケース
- 平均スコア: 76,325.96
- 最小スコア: 71,788
- 最大スコア: 84,036
- 探索上限: 1,850ms
- 通常観測された最大wall time: 1,857ms

共有検証環境のCPU競合でプロセスが停止した2回だけ、外から測ったwall timeが4,790msに
なりました。solverは `steady_clock` で1,850msに停止し、それ以外の98回は約1,853〜1,857ms
でした。専有環境での計算時間とは分けて記録しています。

`-fsanitize=address,undefined` でもseed 0、48、91を実行し、エラーはありませんでした。
100出力すべてについて、1行、900文字、文字種 `0`〜`3` も独立に確認しました。

### 段階比較

## 注意と次の発展

- 1本の候補内では同じタイルを2回使わないため、二重曲線タイルを1本が2回通る公式仕様を
  活用し切れていません。
- 上位解を目指すなら、作った閉路の一部分だけを外し、未使用マスを通る長い経路でつなぎ直す
  destroy/repairが次の候補です。
- 汎用化するなら `bounded-random-dfs.hpp`、`tile-transition.hpp`、
  `compatible-cycle-pair.hpp` の3部品へ分けられます。この練習では共有ライブラリを変更せず、
  `main.cpp` だけで読める形を優先しました。
