# AHC017 practice

公式問題: [A - Road Repair](https://atcoder.jp/contests/ahc017/tasks/ahc017_a)

`main.cpp` だけで提出できる、辺を日ごとのグループへ分けて局所探索する例です。外部の
`.hpp` は参照せず、必要な部分を1ファイルへ直接置いています。

## 問題の要点

重み付き無向グラフの全辺を `D` 日へ割り当てます。1日に工事できる辺は `K` 本以下です。
ある日の工事辺を全部消した時、全頂点対の最短距離がどれだけ伸びるかの平均を小さくします。
グラフは平面ですが、近くの道路を同じ日にまとめて閉じると、その一帯で大きな迂回や切断が
起きやすい点が重要です。公式制限時間は6秒です。

この問題は小さい値ほど良い最小化問題です。

## 解法

### 1. 16頂点だけを最短路の代表にする

全頂点からDijkstraすると、1回の交換評価が重すぎます。座標の中心付近から始め、今まで
選んだ代表から最も遠い頂点を順に追加して、地図全体へ散らばる16頂点を選びます。

各頂点を一番近い代表へ割り当て、その人数を代表の重みにします。代表から全頂点への
距離増加をこの重み付きで足すと、全点対評価の軽い近似になります。

### 2. 性質の違う初期解を4個比べる

- 最短路木へ頻繁に現れる辺、次数の小さい端点を持つ辺を日ごとに分散するgreedy
- 辺の中点を蛇行順に並べ、隣り合う辺を別の日へ送る空間分散
- 入力hashで再現できるランダム均等割当を2個

すべての日の本数を `floor(M/D)` または `ceil(M/D)` に固定します。公式条件ではこれは必ず
`K` 以下です。4案を同じ16代表で評価し、最良案から探索を始めます。

### 3. 2日間の辺を交換する

異なる2日から1辺ずつ選び、工事日を交換します。変わるのはその2日だけなので、残り
`D-2` 日の評価はcacheしたままです。悪い日を候補にしやすくした焼きなましを5.7秒まで
続け、途中の最良割当を保存します。

交換では各日の本数が変わりません。したがって探索中も出力時も、容量違反は構造上
発生しません。

## 読む時の目印

- `samples`: farthest-point samplingで選んだ代表頂点
- `sample_weight`: 各代表が受け持つ頂点数
- `evaluate_day`: その日の工事辺を飛ばす16回のDijkstra
- `initial_schedules`: 性質の違う4初期解
- `day_cost`: 日別評価cache
- `day_edges`: 日をまたぐ2辺交換をO(1)で反映する配列

## 高速化

- 全点対評価を、地理的に散らした16始点へ近似する
- 1交換につき変更された2日だけ再計算する
- Dijkstra用の距離配列を毎回再利用する
- 日別辺集合は、2本を同じ添字位置で置き換えてallocationしない
- 入力hashを乱数seedにし、同じ入力なら同じ候補列にする
- 5.7秒で探索を止め、6秒制限に出力余白を残す

## 公式ツールでの確認

公式配布ツール、`g++ -O2`、既定の5.7秒探索を使いました。seed 0〜9のfrustrationは
次のとおりです。時間打切りのため、共有CPUの負荷で探索回数と値は少し変動します。

| seed | frustration |
|---:|---:|
| 0 | 8,561,347 |
| 1 | 11,366,497 |
| 2 | 38,579,595 |
| 3 | 18,633,915 |
| 4 | 12,030,451 |
| 5 | 4,974,611 |
| 6 | 6,777,524 |
| 7 | 9,098,151 |
| 8 | 5,984,271 |
| 9 | 12,467,790 |

平均は **12,847,415.2** です。同じ10入力で段階比較すると次のようになりました。

| 段階 | 平均frustration | 単純均等割当からの削減 |
|---|---:|---:|
| 入力順を1日ずつ巡回 | 463,665,971.9 | - |
| 4初期解のsample評価 | 16,785,900.5 | 96.4% |
| 2日交換の焼きなまし | 12,847,415.2 | 97.2% |

単純割当はseed 2などで局所的な切断を起こすため平均が大きくなります。探索版は全10入力で
公式visualizerがエラーなしでした。探索を初期解作成だけで止めた短時間設定でも、公式
seed 0〜99は100/100ケース合法でした（平均151,446,688.68、最小3,036,936、
最大6,362,794,855）。この平均は合法性確認用で、通常5.7秒版の品質値ではありません。

`-Wall -Wextra -Wshadow -pedantic` でこのsolver固有の警告はありません。ASan・UBSanを
同時に有効にしたseed 2も公式visualizerまで完走しました。提出時は `main.cpp` の内容を
そのまま提出できます。

## 再利用できる部分

- `library/farthest-point-sampling.hpp`: 離れた代表をgreedyに選ぶ汎用部品
- 大きな評価を固定sampleで近似する方法
- グループ変更時に、影響するグループだけ再計算するcache
- 容量を常に守る2グループ間swap

この構成は、要素を複数の箱へ分け、1手で少数の箱だけが変わる問題へそのまま応用できます。

## 参照した研究資料と弱点

一次情報として公式問題文、公式入力、公式Rust visualizerの採点実装を確認しました。
ローカルknowledgeは構造検索後、AHC017 Reviewと、候補制限・局所Dijkstra・
transaction型apply/undoの節だけを参照しています。第三者コードは転載せず、16代表の
重み付き評価と4初期解から独自に組み立てました。

- 16始点は近似なので、sampleに見えない頂点対へ過適合することがあります。
- 上位を狙う場合は、工事辺の周辺頂点を評価始点へ追加する方法や、短い代替路を差分更新する
  方法が候補です。
- 1辺移動は使わず、日別本数を完全に固定しています。容量に余裕が大きい入力では探索空間を
  狭めています。
